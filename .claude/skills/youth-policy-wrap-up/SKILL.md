# 작업 마무리

메모: $ARGUMENTS

## 현재 상태

!`git status --short`

!`git log --oneline -8`

!`npm run verify -- status`

## 1. 커밋할 변경 고르기

- 위 작업 트리에서 이번 작업으로 바꾼 파일만 고른다. 대화 시작 전부터 있던 변경, 다른 에이전트·사용자의 작업, `.playwright-cli/`·임시 로그는 포함하지 않는다. 판단이 어려운 파일은 커밋하지 않고 보고한다.
- `git add -A`·`git add .`를 쓰지 않고 경로를 지정해 스테이징한다. 한 파일에 내 변경과 남의 변경이 섞여 있으면 커밋하지 않고 사용자에게 알린다.
- 생성 파일(`api/*.json`, `frontend/src/generated/**`)은 서버 DTO 변경과 같은 커밋에 넣는다.

## 2. 검증이 최종 파일을 덮는지 확인

- 위 검증 기록에서 필요한 검사가 통과했고 그 뒤 바뀐 파일이 문서뿐인지 확인한다. 코드가 더 바뀌었으면 `youth-policy-verify` 스킬로 그 범위만 다시 검증한다.
- 실행하지 못한 검증(외부 연동·Docker 없음 등)은 커밋을 막지 않되 HANDOFF와 보고에 미검증으로 적는다.

## 3. 비밀값·개인정보 점검

스테이징 후 실행한다.

```bash
git diff --cached -U0 | grep -nE 'sk-[A-Za-z0-9_-]{16,}|re_[A-Za-z0-9]{16,}|whsec_[A-Za-z0-9+/=]{16,}|BEGIN [A-Z ]*PRIVATE KEY|(API_KEY|SECRET|PASSWORD|TOKEN)=[^ <]{8,}'
```

결과가 있으면 실제 값인지 확인하고, 실제 값이면 스테이징에서 빼고 사용자에게 알린다. 테스트 고정값(`test-*`)과 `.env.example`의 공개 예시값(`local-only-password`)은 해당하지 않는다. `.env`·`.local/`·실제 응답 캡처·실제 이메일 주소는 커밋하지 않는다. 출력에 값 전체를 다시 옮겨 적지 않는다.

## 4. HANDOFF 갱신

[HANDOFF](../../../HANDOFF.md)는 다음 작업자가 바로 이어갈 현재 상태만 담는다.

- 첫 줄의 기준일을 오늘 날짜로 바꾼다.
- "현재 작업"은 이전 내용을 이어 붙이지 않고 교체한다: 브랜치와 원격 반영 여부, 이번 변경의 결과, 실행한 검증 명령·범위·결과, 정리한 프로세스·남긴 제약.
- "구현·검증 범위"·"남은 작업"은 이번 작업으로 상태가 바뀐 항목만 고친다. 상세 재현·검증 기록은 기능별 `docs/development/` 문서에 두고 링크한다.
- 테스트 총개수·과거 작업 이력·로그 전문을 적지 않는다.
- 스킬·문서만 바꾼 작업이라도 작업 방식이 바뀌었으면 "이어서 작업할 때"에 한 줄로 반영한다. 바뀐 것이 없으면 HANDOFF를 고치지 않는다.

## 5. 커밋

- 성격이 다른 변경은 나눈다. 이 저장소의 흐름은 기능 커밋(코드와 그 테스트) 뒤에 검증 결과·문서·HANDOFF 커밋이다. 문서만 바뀐 작업은 커밋 하나로 충분하다.
- 제목은 접두어 없이 바뀐 결과를 한글 명사형으로 한 줄에 쓴다. 최근 예: `정책 변경 재조회 후 사용자의 입력 초점 유지`, `OpenAI 비용 조회 설정과 검증 범위 문서화`. 이유가 제목으로 드러나지 않으면 본문에 짧은 목록을 붙인다.
- 세션 지침에 공동 작성자 표기가 있으면 메시지 끝에 붙인다. 여러 줄 메시지는 heredoc으로 전달한다.
- 커밋 후 `git status --short`로 남은 파일을 확인한다. 사용자가 요청하지 않으면 push·병합·브랜치 전환을 하지 않는다.

## 6. 보고

커밋 해시와 제목, 포함한 파일 분류, 실행한 검증과 결과, 커밋하지 않고 남긴 파일과 이유를 짧게 보고한다.
