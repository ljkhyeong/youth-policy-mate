# ADR-0001 기술 스택과 책임 분리

- 상태: 채택
- 결정일: 2026-08-30
- 제품 기준: [PRD-0001](../PRD/0001_product-baseline/spec.md)

## 배경

공개 정책 페이지의 검색 노출, 정책 수집과 변경 이력, 근거가 있는 자격 판정, 일정과 알림이 필요하다. 초기 운영비는 월 3만 원 이내이며 운영 장비·클라우드 선택은 뒤로 미뤘다. 소규모 서비스 단계에서 여러 데이터베이스와 독립 서비스를 운영하는 비용을 먼저 만들지 않는다.

## 채택한 스택

| 영역 | 선택 | 역할 |
|---|---|---|
| 웹앱 프런트엔드 | Next.js 16 App Router, React 19, TypeScript | 공개 정책 탐색과 개인 조건·저장·일정·알림 화면 |
| UI | Tailwind CSS 4, shadcn/ui, Radix UI | 화면 구성과 접근 가능한 상호작용 |
| 서버 | Java 25 LTS, Spring Boot 4.1, Spring MVC | 인증·업무 규칙·트랜잭션·외부 연동 |
| 백엔드 구조 | 모듈러 모놀리스, Spring Modulith | 기능별 책임 분리와 모듈 의존 검증 |
| API | REST, OpenAPI 3.1, 생성 TypeScript 계약 | 프론트엔드와 서버의 전송 계약 동기화 |
| 데이터 | PostgreSQL 18, Spring Data JPA, 필요한 SQL/JdbcClient | 정책·회원·일정·알림 상태 저장 |
| 스키마 | Flyway | 배포 가능한 스키마 변경 이력 |
| 수집 | Spring Batch | 원본 수집·실행 이력·재처리 |
| 검색 | PostgreSQL 인덱스와 pg_trgm | 초기 필터·문자열 검색 |
| 인증 | Spring Security OAuth2 | 카카오·네이버 로그인과 서버 측 접근 제어 |
| 알림 | DB Outbox와 발송 공급자 어댑터 | 저장 상태와 발송 요청의 일관성, 실패 처리 |
| 원본 보관 | S3 호환 객체 저장소를 사용할 수 있는 보관 경계 | 원본과 수집 근거 보존. 실제 운영 저장소는 배포 단계에서 선정 |
| 관측 | Actuator, Micrometer, 필요 범위의 OpenTelemetry | 수집 실패·판정 불가·발송 실패·비용 관련 상태 확인 |
| 검증 | JUnit/Jupiter, AssertJ, Testcontainers, Vitest, Playwright | 규칙과 실제 DB·사용자 흐름의 필요한 경계 검증 |
| 빌드·전달 | Gradle, Docker, GitHub Actions | 재현 가능한 빌드와 검증·배포 준비 |

주요 버전 계열을 채택한 것이며 이 문서가 의존성 잠금 파일은 아니다. 스캐폴딩 시 안정 패치와 Spring Boot BOM 호환성을 확인하고 실제 빌드 설정에 고정한다. 위 표는 현재 설치 상태가 아니다.

2026-09-05에는 Boot BOM의 Spring Batch 6.0.5와 JDBC 실행 저장소를 [한 페이지 수집](../development/limited-policy-collection.md)에 연결했다. Batch는 작업 실행 이력을, 수집 모듈의 업무 테이블은 원본과 항목별 재처리 위치를 맡는다. 외부 호출은 트랜잭션 밖에서 실행하고 정책 반영과 항목 완료는 함께 커밋한다. 이후 [범위 수집과 정기 실행](../development/policy-range-collection.md)에 같은 Batch 작업을 연결했다. DB에 페이지 진행 위치·호출 간격·발송 시작을 기록하며 외부 대기 중 잠금을 유지하지 않는다. 정기 실행은 명시적인 한도·간격·범위·주기 설정 뒤 활성화한다.

2026-09-05에는 [회원·정책 연결](../development/member-policy-flow.md)에 Spring Security OAuth2와 Spring Session JDBC를 사용했다. Next.js는 같은 출처의 제한된 API 중계를 제공하고, Spring이 회원 소유권과 CSRF를 확인한다. 별도 Redis 없이 기존 PostgreSQL에 세션·저장·서비스 내 알림을 보관한다. 이후 [이메일 주소 확인·Outbox](../development/member-email-reminders.md)를 추가했다. 회원·정책 저장에는 기존 PostgreSQL 트랜잭션을 사용하고, SMTP 호출은 발송 배정을 커밋한 후 실행한다. 주소는 AES-GCM으로 암호화하며 확인 코드 비교 값은 HMAC으로 저장한다. SMTP 어댑터는 STARTTLS를 필수로 요구하고 기본 비활성화한다. 실제 공급자와 운영 발신 도메인은 아직 미정이다.

## 책임 분리

Next.js는 상태 중심 웹앱의 화면 렌더링, 공개 페이지 메타데이터와 사용자 상호작용을 담당한다. Server Action이나 Route Handler에 자격 판정·정책 수집·알림 예약 같은 업무 규칙을 중복 구현하지 않는다. 필요하면 서버 API를 연결하는 얇은 중계만 둔다. 설치형 PWA·오프라인 사용·네이티브 앱 패키징·웹 푸시는 현재 채택 범위가 아니며 필요성이 확인되면 별도 기술 결정으로 다룬다.

Spring Boot는 다음 기능 모듈의 책임을 소유한다. 아래 이름은 설계상의 경계이며 생성된 디렉터리를 뜻하지 않는다.

| 모듈 | 소유하는 내용 |
|---|---|
| 회원 | 인증, 사용자 조건, 이메일 수신 설정 |
| 정책 | 정책 식별자, 현재 적용 내용, 개정과 원문 근거 |
| 수집 | 외부 자료 취득·정규화·재실행·예외 기록 |
| 자격 판정 | 조건 비교, 미확인 처리, 판정 근거 |
| 추천 | 자격 상태를 보존한 검색·노출·정렬 |
| 일정 | 관심 정책 저장, 마감일 표시, 변경·해제 반영 |
| 알림 | 동의와 예약 확인, 전달·취소·재시도 결과 |

처음부터 모듈마다 독립 서버·DB·Gradle 프로젝트를 만들지 않는다. 실제 책임이 있는 경계만 분리하고 단순 전달 계층·범용 규칙 엔진을 미리 만들지 않는다.

## 중요한 구현 원칙

- 원본 스냅샷, 정규화한 정책, 적용한 개정, AI 파생 결과를 구분한다. 외부 API가 신뢰할 수 있는 개정 번호를 준다고 미리 가정하지 않는다.
- 일반 CRUD는 JPA를 사용하고 DB 원자성이나 검색 조건이 필요한 부분은 소유 저장소의 명시적 SQL로 처리한다.
- DB 스키마는 Flyway가 변경한다. Hibernate 자동 생성·수정으로 운영 스키마를 대신하지 않는다.
- 정책과 규칙·기준일·사용자 입력을 식별할 수 있게 해 판정 결과를 설명한다. AI는 이 경계를 대체하지 않는다.
- 알림 요청은 업무 상태와 같은 트랜잭션에 보존하고 외부 발송은 커밋 이후 수행한다. 재시도 가능성과 발송 결과 미확인을 구분한다.
- 원본 수집과 AI 호출은 DB 트랜잭션을 오래 잡은 상태에서 실행하지 않는다. 실패한 항목만 재처리할 수 있게 한다.
- 공개 정책의 서버 캐시와 개인화 응답의 캐시를 분리한다. 회원 정보가 공용 캐시·메타데이터·사이트맵으로 노출되지 않게 한다.
- 시간은 원문 날짜와 정확한 시각을 구분하고 업무 계산에는 주입한 Clock과 명시적인 시간대를 쓴다.

## 운영비와 도입을 미룬 기술

AWS 서울 리전은 초기 검토 후보였지만 확정된 배포 조건은 아니다. 서버·DB를 한 장비에 올릴지, 관리형 서비스를 쓸지도 아직 결정하지 않았다. 어떤 배포안이든 월 예산과 백업·복구 가능성을 먼저 확인한다.

초기에는 Kubernetes, 마이크로서비스, Kafka/RabbitMQ, Redis 캐시, 별도 검색 서버, 별도 Python 서비스, 벡터 DB를 추가하지 않는다. 문제와 측정 결과가 생겼을 때 필요성을 검토한다. pgvector 역시 의미 검색이 실제로 필요한 시점의 후보이며 MVP 필수 의존성이 아니다.

AI 공급자·모델과 이메일 공급자는 미정이다. 공급자를 바꾸기 위해 제품 정책을 수정할 필요 없도록 외부 호출 경계를 둔다. AI 신규 요청은 비용 한도에 따라 중단할 수 있어야 한다.

## 선택의 이점과 비용

- 공개 정책 페이지에 서버 렌더링을 쓰면서 개인화 화면도 React로 구성할 수 있다.
- Spring에서 수집·판정·알림 규칙을 한곳에 관리한다.
- PostgreSQL 중심으로 운영 구성요소를 줄일 수 있다.
- Next.js와 JVM 두 런타임을 운영하므로 작은 장비의 메모리 사용량은 실제로 검증해야 한다.
- PostgreSQL 문자열 검색만으로 충분한 한글 검색 품질이 나오지 않을 수 있다. 사용자 검색 사례로 평가한 뒤 전용 검색 도입을 판단한다.
- 모듈러 모놀리스는 독립 배포를 제공하지 않는다. 초기 규모에서는 배포 단순성을 우선한다.
