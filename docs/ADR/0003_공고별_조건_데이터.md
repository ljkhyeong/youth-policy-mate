# 공고별 조건 데이터

- 상태: 채택
- 날짜: 2026-09-12

## 결정

정책별 Java 클래스를 늘리는 대신 공고의 질문·선택지·판정표·근거·적용 기간을 JSON으로 저장한다. 판정표는 선택지 조합을 위에서부터 비교하고 첫 일치 결과를 사용한다. 어느 행에도 맞지 않으면 추가 확인으로 남긴다. 임의 수식이나 실행 코드는 받지 않는다.

PostgreSQL에 변경 불가 버전과 현재 적용 버전을 분리한다. 관리자 화면에서 기존 규칙을 편집하거나 파일·운영 명령으로 초안을 등록하고, 원문 해시와 직전 적용 버전을 확인한 뒤 적용한다. 정책 수집과 같은 정책 행을 잠가 원문 변경과 적용이 엇갈리지 않게 한다. 관리자 화면의 쓰기는 조회한 개정도 확인하고, 요청 ID·작업자·사유를 규칙 변경과 같은 트랜잭션으로 기록한다. 같은 요청은 기존 결과를 반환해 응답 유실 후 중복 적용을 막는다. 원문 변경·기간 만료는 조회와 제출 시 즉시 차단한다. 적용 기간은 규칙을 사용할 기간이며 실제 접수 기간과 구분한다.

출생일 범위·만 나이 기준은 같은 데이터에서 기본 연령 비교와 질문 답변을 만든다. 만 나이는 기존 연령 모듈을 사용하고 미확인 병역 예외는 확인 대기로 남긴다. 월별 실적은 기준 월을 질문 범위와 답변 버전에 붙인다. 확인한 생년월일만 화면 메모리에서 재사용하고 다른 개인 조건은 임의 변환하지 않는다. 답변에는 정책 개정과 규칙 버전을 붙여 오래된 제출을 거부한다.

편집 화면은 서버의 규칙 정의에서 생성한 타입을 사용한다. 질문·선택지 식별자와 별도 예외 설정을 보존하며, 판정 계산과 유효성 검사는 기존 서버 모듈에 둔다. 원문이 바뀌면 검토 확인 후 현재 원문에 연결한다. 수정은 새 버전으로 저장하고 적용은 별도 처리한다.

AI 추출 요청은 기존 공고 개정·원본을 참조하고 DB 순번으로 최신 요청을 구분한다. 결과 본문은 요청당 한 번 보관하며 유효한 최신 결과와 규칙 초안을 함께 저장한다. 이전 공고·이전 요청·잘못된 결과는 사유를 남기고 초안을 만들지 않는다.

명시적인 운영 명령으로 OpenAI Responses API를 호출한다. Spring RestClient를 사용하고 자동 재시도는 추가하지 않는다. 입력 토큰 수와 출력 상한에 운영자가 설정한 원화 단가를 적용해 기존 예산 저장소에 먼저 예약한다. 발송 직전 정책 행을 잠가 원문·요청을 확인하며 외부 호출은 트랜잭션 밖에서 수행한다. 원 응답을 먼저 보관해 초안 저장 실패 후에는 응답만 다시 처리한다. 토큰 사용량을 실제 청구 확인으로 취급하지 않고 기존 예약 정산·무과금 확인 경로를 운영 명령에 연결한다.

질문 ID를 키로 쓰는 판정표의 동적 맵을 유지하기 위해 JSON mode를 사용한다. 서버 정의에서 생성한 스키마와 원문을 전달하며 실제 형식·참조 검사는 기존 `PolicyRuleDefinition`이 담당한다. 모델과 최신 요금은 설정해야 하며 공급자에 사용자 조건·작업자 정보를 보내지 않는다.

## 범위

현재 제공하는 11개 정책의 질문·판정을 데이터로 이전했다. 정책별 운영 클래스와 질문 분기는 제거하고 기존 구현을 고정된 비교 테스트 자료로 유지한다. 원문 충돌 안내와 검색용 모집 기간 보정은 별도 책임으로 남긴다. AI 호출·초안 저장·수동 청구 확인 명령을 제공하며 수집 후 자동 실행과 자동 승인은 포함하지 않는다. 실제 모델 품질·청구 대사는 설정 후 검증한다. 공고 값의 변경에는 데이터 적용만 필요하고, 새로운 비교 방식에는 공통 비교 코드 변경이 필요하다.
