# PRD-0001 청년정책메이트 MVP

- 상태: 제품 범위 승인
- 합의일: 2026-08-30
- 적용 범위: 첫 공개 버전
- 승인 기록: [최초 제품 합의](../../alignments/seoul-mvp.html)
- 기술 선택: [ADR-0001](../../ADR/0001_기술스택과_책임_분리.md)

이 문서는 사용자가 확인할 동작과 제품 정책의 기준이다. API 경로, DB 구조, 실행 명령은 실제 구현에서 관리한다. 이 문서의 요구사항을 이미 구현된 기능으로 해석하지 않는다.

## 1. 제품 목표

서울 거주 청년이 자신의 조건에 맞는 정책과 추천 근거를 확인하고, 관심 정책을 저장해 신청 마감과 변경 내용을 놓치지 않게 하는 웹앱을 제공한다.

핵심 경험은 **조건 입력 → 근거가 있는 자격 안내 → 관심 정책 저장 → 일정·알림 확인 → 공식 신청처 이동**이다. 청년정책메이트가 지원 자격을 공식 인증하거나 신청을 대신하지는 않는다.

## 2. 대상과 정책 범위

- 첫 대상은 서울에 거주하는 만 19~34세 청년이다.
- 정책 데이터는 온통청년 API에서 제공하는 정보로 한정한다.
- 서울 거주자가 신청할 수 있는 전국 공통·서울시·서울 자치구 정책을 포함한다. 전국 공통 정책을 서울시 정책이 아니라는 이유로 제외하지 않는다.
- 거주 자치구 조건은 사용자 입력과 정책의 실제 조건으로 확인한다. 서울 대상 정책이라는 분류만으로 모든 서울 거주자에게 적합하다고 판단하지 않는다.
- 서비스의 첫 대상 연령과 개별 정책의 연령 조건은 구분한다. 정책에 명시된 연령과 기준일을 서비스 대상 연령으로 덮어쓰지 않는다.
- 목표 대상은 신규 유입과 추천 범위를 정하는 기준이며, 별도로 합의하지 않은 회원가입 연령 제한을 뜻하지 않는다.

## 3. 사용자와 핵심 흐름

| 사용자 | 이용 범위 |
|---|---|
| 비회원 | 공개 정책 검색·상세 확인, 기본 조건 입력과 추천 결과 확인 |
| 회원 | 비회원 기능, 조건·관심 정책 저장, 내 일정과 알림 설정 |
| 관리자 | 수집·판정 예외 확인, 근거를 확인한 보정, 오류 상태 확인 |

### 3.1 탐색과 저장

1. 공개 정책 목록 또는 상세 페이지로 방문한다.
2. 기본 조건을 입력하여 정책별 자격 안내와 추천 근거를 확인한다.
3. 정책에 필요한 선택 조건을 추가 입력할 수 있다.
4. 저장을 요청한 비회원은 로그인 후 저장한다. 로그인 화면에서 입력 정보의 자동 저장을 기정사실화하지 않고 저장할 내용을 확인할 수 있게 한다.
5. 저장된 정책의 마감일과 변경 내용을 내 일정·알림에서 확인한다.
6. 실제 신청과 최종 자격 확인은 공식 신청 사이트에서 진행한다.

### 3.2 최소 화면 범위

- 공개 정책 목록·검색: 검색어와 지역 등 명확한 정책 조건으로 탐색한다.
- 현재 원문과 적용 시점에 맞는 공통요건 질문이 있는 정책을 목록에서 표시하고 따로 모아볼 수 있다. 검색어·페이지 이동에도 선택한 필터를 유지하며, 전체 건수는 필터를 적용한 정책 수다. 질문 제공 여부는 자격 충족이나 접수 중이라는 뜻이 아니다. 기본 조건 확인 결과에서도 해당 정책의 질문으로 이동할 수 있다.
- 정책 상세: 지원 내용, 자격 조건, 신청 기간, 제출 서류·절차 안내, 공식 링크, 출처와 수집 시각을 표시한다.
- 정책 목록·상세·내 조건 결과에 서버가 계산한 접수 상태와 근거를 표시한다. 날짜형은 서울 날짜 기준 ‘접수 기간’, 시각형은 확인한 시작·마감 시각으로 계산한다. 상시·소진형은 실제 접수 여부를 확정하지 않으며, 코드·날짜 충돌이나 복수 회차는 기간 미확인으로 남긴다. 원문 해석은 마감 알림과 공유하고 모집 상태 때문에 자격 결과·정렬을 바꾸지 않는다.
- 공개 목록과 내 조건 결과에서 접수 상태를 선택해 검색할 수 있다. 기본값은 전체이며 상시·기간 미확인도 각각 선택할 수 있다. 검색어·질문 제공 여부·정렬과 함께 전체 결과에 필터를 적용한 뒤 페이지를 나누고, 검색과 페이지 이동에도 선택을 유지한다. 접수 상태 필터는 자격 판정에 영향을 주지 않는다.
- 내 조건: 기본·선택 조건 입력, 제공 동의한 소셜 정보 확인, 저장한 조건 수정.
- 관심 정책·내 일정: 저장한 정책과 신청 마감일 확인, 저장 해제.
- 알림·설정: 서비스 내 알림 확인, 이메일 수신 활성화·비활성화.
- 관리자 예외 목록: 원문, 이전 내용과 변경점, 확인이 필요한 항목, 보정 근거 확인.

독립적인 서류 준비 체크리스트나 임의 일정 작성 기능은 이 MVP의 필수 완료 조건이 아니다. 제출 서류와 신청 절차는 정책 정보로 안내한다.

### 3.3 웹앱 사용 원칙

- 이 제품은 정보를 일방적으로 읽는 웹사이트가 아니라 사용자가 조건·관심 정책·일정·알림 상태를 계속 확인하고 관리하는 웹앱이다.
- 화면은 모바일과 데스크톱에서 같은 계정 상태와 업무 흐름을 제공한다. 공개 정책 탐색에서 개인 조건 확인·저장·일정 관리로 자연스럽게 이어져야 한다.
- 로그인 전 입력과 로그인 후 저장 상태의 경계를 명확히 보여주고, 새로고침·재방문·계정 변경에도 사용자에게 보이는 상태의 출처를 설명할 수 있어야 한다.
- 설치형 PWA, 오프라인 사용, 네이티브 앱 패키징과 웹 푸시 알림은 이번 결정에 포함하지 않는다. 필요성과 운영 조건을 확인한 뒤 별도로 합의한다.

### 3.4 화면 문구

- 버튼에는 누르면 실행되는 동작을 적는다. 상세 이동은 ‘지원 내용 보기’, 질문 시작은 ‘질문에 답하기’로 표시한다.
- 짧고 익숙한 표현을 사용한다. 질문 필터는 ‘질문 있는 정책’, 인증은 ‘이메일 인증’으로 표시한다. 알림 취소 안내는 이메일 등 취소 대상을 명시한다. 공개 화면에 지역 코드나 내부 검토 과정을 설명하지 않는다.
- 일부 요건의 결과는 ‘확인한 조건 충족’, ‘충족하지 못한 조건 있음’, ‘추가 확인 필요’로 구분한다. 최종 신청 자격과 남은 확인 사항은 별도로 표시한다.
- 결과 상단에는 비교 범위와 한계를 한 번 설명하고, 항목별로는 사유와 다음 행동을 안내한다. 기본 조건에서 연령만 비교할 때는 버튼과 결과 제목에 ‘연령 조건 비교’를 명시한다. 공식 용어, 적용 연도·기준일·예외와 출처는 유지한다.
- 마감 알림을 제공하지 못하면 상시 접수·접수 종료·마감일 미확인 등 실제 사유를 안내한다. 이메일 인증과 수신 동의를 구분하고, 재요청에 따른 코드 무효와 동의 해제를 구체적으로 알린다.

## 4. 조건 입력과 로그인

### 4.1 입력 항목

| 구분 | 항목 | 처리 원칙 |
|---|---|---|
| 기본 조건 | 생년월일, 주민등록상 거주 자치구, 취업 상태 | 개인화 결과를 요청할 때 입력한다. 공개 목록·상세 열람을 막지 않는다. |
| 선택 조건 | 소득 구간, 가구원 수, 학력·재학 상태 등 | 해당 정책 확인에 필요한 경우 추가 입력한다. 미입력은 알 수 없는 상태다. |

- 사용자 정보가 없다는 이유만으로 조건 불충족으로 처리하지 않는다.
- 확인한 생년월일은 같은 화면 이용 중 정책의 출생일 질문에 재사용할 수 있다. 적용한 답변을 표시하고 수정·삭제할 수 있게 한다. 새로고침·조건 수정·로그아웃·계정 변경 시 재사용 값을 지우며, 브라우저 저장소나 URL에 보관하지 않는다. 거주·취업·소득은 의미와 기준일을 맞추기 전에는 재사용하지 않는다.
- 주된 취업상태 하나를 선택해도 다른 취업 형태·겸업·재학 여부가 모두 없다는 뜻은 아니다. 선택하지 않은 상태나 ‘기타’를 일괄 비해당으로 바꾸지 않는다.
- 정책이 요구하는 취업 상태의 정의·기준일과 사용자 입력의 의미가 맞아야 비교한다. 추가 정보가 필요하면 해당 조건과 기준일을 설명하고 필요한 항목만 확인한다. 미응답·모름은 추가 확인 필요로 남긴다.
- 소득은 개인·가구 기준과 가구원 범위, 금액의 정의·단위, 대상 기간·적용 연도를 구분해야 한다. 의미를 맞출 수 없는 값은 억지로 비교하지 않는다. 월 소득에 단순히 12를 곱하거나 세후 금액을 추정 세전 금액으로 바꿔 정책 기준을 대신하지 않는다.
- 소득액·건강보험료·중위소득 비율은 서로 다른 값으로 다룬다. 정책이 요구하는 계산 방식과 기준표·적용 연도를 확인하기 전에는 서로 환산하지 않는다. 추가 입력은 해당 정책에서 필요한 범위로 제한한다.
- 선택 항목의 코드와 입력 방식은 실제 API 샘플 및 정책 원문을 확인한 뒤 정한다. 불필요한 상세 개인정보를 먼저 수집하지 않는다.

### 4.2 카카오·네이버 로그인

- 로그인 전에도 직접 조건 입력으로 검색할 수 있다.
- 동의받아 제공된 생일과 출생연도로 생년월일을 자동 입력하고, 사용자에게 확인받는다.
- 미동의·미제공·불완전한 생년월일·음력 생일은 직접 입력으로 보완한다.
- 일반 소셜 프로필 값을 별도 본인확인 완료 정보로 표시하지 않는다.
- 제공자 권한 심사에 실패하거나 정보가 제공되지 않아도 직접 입력 경로를 유지한다.
- 주민등록번호와 증빙서류는 수집하지 않는다. 거주지·취업·소득 정보가 소셜 로그인만으로 검증되었다고 주장하지 않는다.
- 회원별 조건·저장·일정은 다른 계정에 노출되지 않아야 한다. 로그아웃이나 계정 변경 후 이전 계정의 화면 데이터와 늦게 도착한 응답을 재사용하지 않는다.

## 5. 자격 안내와 추천 근거

### 5.1 표시 상태

| 상태 | 의미 |
|---|---|
| 입력 조건 기준 신청 가능 | 해석 가능한 모든 필수 조건과 예외를 확인했고 입력 조건이 충족한다. 공식 자격 인증이나 선정 보장은 아니다. |
| 추가 확인 필요 | 필요한 사용자 정보가 없거나 정책 조건·예외·기준일을 확정할 수 없다. 확인할 항목과 원문 근거를 표시한다. |
| 조건 불충족 | 명확한 조건을 적용한 결과 자격 요건을 충족하지 못한다. 해당 조건과 비교 근거를 표시한다. |

- 판정 상태만 보여주지 않고 적용 조건, 사용자 입력, 충족 여부, 원문 근거를 함께 제공한다.
- 수집 안내끼리 또는 모집 공고와 조건이 충돌하면 상세 화면에 차이와 확인할 공식 공고를 표시한다. 검토한 정책번호·내용 해시에만 안내를 적용하며 수집 원문은 유지한다. 안내가 없다고 검토 완료를 뜻하지 않으며, 원문이 바뀌면 다시 검토한다. 충돌 안내만으로 자격 판정이나 질문 제공 범위를 넓히지 않는다.
- 검토가 끝난 공통요건만 비교할 때는 해당 범위를 명시한다. 공통요건 충족을 최종 신청 가능으로 표시하지 않으며, 대학·기관별로 남은 조건과 예외를 함께 안내한다.
- 정책별 추가 질문은 적용 학기·연도와 현재 개정·규칙 버전에 묶는다. 원문이나 질문이 바뀌면 이전 답변을 지우고 새 기준을 확인한다. 공식 산정값이 필요한 항목은 월급 등 다른 값에서 임의로 환산하지 않는다.
- 공고의 적용 기간·질문·조건·예외·근거는 버전이 있는 데이터로 관리한다. 운영자가 초안을 검토한 뒤 적용하며, 적용한 버전은 수정하지 않는다. 원문이 달라지거나 적용 기간이 끝나면 질문과 비교를 중단하고 재검토 대상으로 표시한다. 새 공고에 이전 규칙을 자동 이월하지 않는다. 현재 제공하는 11개 정책의 질문과 판정을 데이터로 관리한다. 만 나이는 공고의 기준일 또는 서울의 현재 날짜로 계산하고, 월별 실적을 묻는 질문은 기준 월이 바뀌면 이전 답변을 받지 않는다.
- 금융상품의 가입 조건과 우대금리·세제 혜택·대출 조건을 구분한다. 소득의 기준 연도·증빙 금액, 병역기간 차감이나 군복무자 소득 예외를 확인하지 못하면 추가 확인으로 남긴다. 확인된 예외는 해당 항목에만 적용한다.
- 선택 조건 누락, AI 처리 실패, 알 수 없는 코드나 서술형 예외를 `false` 또는 제한 없음으로 바꾸지 않는다.
- 취업상태 선택지와 원천 코드의 이름이 같다는 이유만으로 충족을 확정하지 않는다. 취업 제한이 없다고 확인했더라도 학력·재학 등 다른 필수 조건과 예외는 별도로 확인한다.
- 소득 구간은 임의의 대표 금액으로 바꾸지 않는다. 의미가 맞는 구간 전체가 허용 범위 안이면 해당 항목을 충족하고, 허용 범위와 겹치지 않으면 불충족으로 처리한다. 일부만 겹치면 추가 확인이 필요하다. 미입력·모름은 0원이나 제한 없음이 아니다.
- 소득 무관 코드만으로 본문의 소득 제한·예외를 무시하지 않는다. 기준표·가구원 범위·계산 방식이 확인되지 않으면 추가 확인 필요로 남긴다.
- 기본 연령·지역이 맞더라도 추가사항·참여제한·중복 수혜 제한을 해석하지 못했다면 신청 가능으로 확정하지 않는다.
- 일부 조건이 명확하게 불충족이어도 정책 자체의 예외가 그 판단을 바꿀 수 있으면 추가 확인 필요로 남긴다.
- 연간 한도와 적용 출생일이 고정된 연도별 질문은 검토한 연도가 지난 뒤 다음 해 규칙으로 재사용하지 않는다. 남은 지원 횟수는 공식 서비스에서 확인한 값으로 질문하고, 취소 후 복구 중인 횟수를 임의로 더하지 않는다.
- 월별 이용·지급 요건을 비교할 때는 대상 연월을 표시하고 달이 바뀌면 이전 질문 답변을 다시 받는다. 첫 가입 월의 횟수 예외와 이용내역 반영 대기를 구분하며, 월 중간의 횟수 미달을 그 달의 최종 미지급으로 확정하지 않는다. 기본 이용요건 충족만으로 지역·대상별 환급률이나 실제 환급금을 계산하지 않는다.
- 나이는 정책이 정한 기준일로 계산한다. 오늘 기준 만 나이, 출생연도, 공고일 기준 나이를 혼용하지 않는다.
- 서울 거주 외에 서울 소재 대학·직장 등 생활권을 인정하는 공고는 각 경로를 구분한다. 비거주만으로 불충족 처리하지 않으며, 증빙 인정 여부가 불분명하면 추가 확인으로 남긴다.
- 모집 전·접수 중·마감·상시·기간 미확인 등 모집 상태는 개인의 자격 상태와 구분한다. 자격이 맞더라도 이미 마감한 정책을 현재 신청 가능한 것처럼 표시하지 않는다.
- 마감한 모집의 질문을 제공할 때는 해당 모집의 연도·회차와 접수 마감을 질문 및 결과 안내에 표시한다. 지난 모집의 기준을 다음 모집에 자동 적용하지 않는다.
- 정책이나 사용자 조건이 바뀌면 최신 내용으로 재판정한다. 이전 결과와 새 결과가 어느 정책 내용을 기준으로 했는지 구분할 수 있어야 한다.
- 적합한 정책이 없으면 그 사실과 조건 수정·추가 확인 경로를 안내한다. 결과를 채우기 위해 자격 조건을 완화하지 않는다.

### 5.2 추천의 책임

확정적인 자격 안내는 명시적인 규칙이 담당한다. AI는 정책 요약과 조건 후보 추출을 보조하며, 점수나 자연어 응답만으로 자격을 확정하지 않는다. 해석이 불가능한 조건은 원문과 함께 남긴다.

기본 조건 결과는 정책명·설명으로 검색하고, ‘연령 조건 충족 우선’ 또는 ‘최근 수집순’으로 정렬한다. 기본 정렬은 검토된 연령 조건 충족 → 미확인 → 불충족 순이며, 같은 그룹은 최근 수집순·정책번호순으로 표시한다. 검색과 정렬은 전체 결과에 적용한 뒤 페이지를 나눈다. 거주 자치구·취업상태만으로 비교할 수 없는 조건은 미확인으로 남기며, 해당 정책을 제외하지 않는다.

연령 비교는 응시료 지원·K-패스·서울청년정책네트워크·2026년 상반기 이사비 지원·청년주택드림청약통장·청년내일저축계좌·햇살론유스·청년 미래이음 대출·2026년 5월 미래 청년 일자리 모집의 검토된 원문과 적용 시점에 한정한다. 비교한 기준·규칙 버전·정책 개정·평가 시각을 결과에 남긴다. 원문 변경이나 검토 연도 만료 시 비교를 중단한다. 확인한 생년월일은 출생일·연령 질문에 재사용한다. 병역 예외를 확인할 수 없으면 확인 대기 답변으로 남긴다. 다른 기본 조건은 추가 질문에 자동 적용하지 않는다. 순서는 자격 확정이나 접수 중을 의미하지 않으며, 별도의 점수·가중치는 사용하지 않는다.

미래 청년 일자리(서울영커리언스 점프업)는 서울시 공고 제2026-1444호의 5월 모집에 한해 출생일·서울 주민등록·근로 상태·재학 상태·사업자등록·다른 일자리 사업 참여를 확인한다. 출생일은 1986.1.1.~2007.12.31.이며 의무복무 제대군인의 연령 연장이 미확인이면 상한 초과를 불충족으로 확정하지 않는다. 신청서 제출일 기준 주 30시간 이하 또는 계약기간 3개월 미만 근로 예외, 수료·졸업예정·졸업유예·방송통신·사이버·야간대학(원) 재학 예외와 실제 미영업·부동산임대업의 증빙 예외를 구분한다. 원문에 있는 예외의 증빙 인정 여부가 불명확하면 추가 확인으로 남긴다. 직무별 제한·서류·가점·근로 가능 여부·선발 심사는 기관 확인 사항이며 민감한 이력이나 증빙을 이 서비스에서 수집하지 않는다. 기본 조건에서는 같은 출생일 기준만 비교한다. 수집 안내의 공고기간을 신청기간으로 대신하지 않고 5월 18~31일 23:59 접수와 마감을 별도 안내하며, 이후 2차 모집에 이 질문을 재사용하지 않는다.

청년주택드림청약통장은 오늘(서울 날짜) 가입한다고 가정한 만 나이를 표시한다. 만 19~34세는 연령 충족, 만 19세 미만은 불충족이며 만 35세 이상은 병역기간 차감 기준을 확인할 때까지 추가 확인으로 남긴다. 실제 가입일이 다르면 다시 확인하도록 안내하고, 무주택·소득·기존 통장 전환·우대금리·세제·대출 조건을 연령으로 대신 판단하지 않는다.

햇살론유스는 검토한 2026년 기준의 만 19~34세, 연소득 3,500만 원 이하, 이용 대상과 남은 생애 보증한도를 질문한다. 취업준비생·중소기업 1년 이하 재직자·창업 1년 이하 청년 개인사업자를 구분하되, 학적·근로·사업을 함께 하는 경우나 적용 유형이 불명확하면 미확인으로 남긴다. 소득은 서금원 기준의 증빙·산정 기간을 확인한 값만 비교하고 월급·매출·가구소득으로 대체하지 않는다. 생애 보증한도 1,200만 원은 상환으로 복원되지 않으며, 남은 한도는 공식 확인값을 사용한다. 기본 검색은 오늘(서울 날짜) 보증신청을 가정한 만 나이만 비교하고 실제 신청일 재확인을 안내한다. 소득·재산·학적·재직·사업 증빙, 자금 용도·기간별 한도·재신청 제한·금융교육·보증 및 은행 심사는 추가 확인으로 남긴다. 거치기간의 군입대 예외를 연령 상한 연장으로 적용하지 않으며 실제 대출 승인·금리·지급액을 확정하지 않는다.

청년 미래이음 대출은 검토한 2026년 3월 31일 이후 기준의 만 19~34세, 미취업 또는 취·창업 1년 이내 여부를 질문한다. 개인신용평점 하위 20%, 기초생활수급자·차상위계층 이하, 근로장려금 신청 자격의 세 요건은 하나만 충족하면 된다. 하나라도 확인된 충족이면 해당 묶음을 충족으로 표시하고, 세 요건이 모두 확인된 비해당일 때만 불충족으로 표시한다. 점수 구간을 임의로 정하거나 근로장려금 수령 이력·소득만으로 신청 자격을 추정하지 않는다. 다른 미소금융 상품의 신용 하위 50%·연소득 요건을 적용하지 않는다. 기본 검색에서는 오늘(서울 날짜) 신청을 가정한 연령만 비교한다. 자금 용도·상환 심사·재무상담·서류와 신용정보·재산·거주 등 지원 제한 및 예외는 추가 확인으로 남기며 대출 승인·금액·금리를 확정하지 않는다.

청년내일저축계좌는 검토한 원문과 2026년 5월 신규 모집에 한해 연령·본인 근로소득·가구 소득인정액·중복참여를 질문한다. 복지로 모집 공고와 2026년 사업 지침을 근거로 수집 안내의 소득·연령 차이를 별도 표시한다. 출생일 범위는 1986.5.1.~2011.5.31.이며 본인의 인정되는 세전 근로·사업소득 월 10만 원 이상과 가구 소득인정액 기준 중위소득 50% 이하를 구분한다. 가입 후 유지 기준을 신규 가입 기준으로 사용하지 않는다.

청년내일저축계좌의 기본 생년월일 비교도 상세 질문과 같은 출생일 기준을 사용한다. 결과와 연령 충족 우선 정렬에 함께 반영하고, 모집 마감·수집 안내와의 기준 차이·다른 조건의 미확인을 유지한다.

전세보증금반환보증 보증료 지원은 검토한 원문과 2026년 기준에 한해 보증 가입·납부, 임차보증금, 본인·배우자 무주택과 소득을 질문한다. 서울 신청자의 청년 유형은 신청일 만 19~39세, 신혼부부는 혼인신고 7년 이내이며 나이만으로 지원 대상에서 제외하지 않는다. 신혼부부 해당 여부를 먼저 구분하고 유형별 연소득 한도 5천만·6천만·7천5백만 원을 적용한다. 소득 합산 범위·대상 연도·증빙 기준이 미확인이면 금액만으로 비교하지 않는다. 분양권·입주권도 소유 여부에 포함한다. 주소·임차인 및 보증서 명의·국적·등록임대주택·중복지원·서류 심사·예산과 실제 지급액은 추가 확인으로 남기고 전체 자격을 확정하지 않는다. 원문 변경·검토 연도 만료 후 질문과 이전 답변을 재사용하지 않는다.

자활근로의 인정 예외, 인건비 일부 지원·별도 채용 등 공공 일자리의 기관 확인, 소득 증빙 확인 중 상태를 구분한다. 가구원의 가입이나 과거 환수 이력만으로 중복참여를 확정하지 않는다. 가구 범위와 소득인정액은 월급·건강보험료에서 환산하지 않으며, 서류·제외업종·선정 심사와 가입 후 유지·지급 조건은 별도 확인으로 남긴다. 접수 마감을 표시하고 다음 연도에는 질문과 이전 답변을 재사용하지 않는다.

2026년 상반기 이사비 지원 질문은 출생일·전입신고·계약과 주민등록·무주택·거래금액·소득·중복지원 기준을 확인한다. 소득은 2026년 3월 건강보험료 고지금액을 공고의 가구원 수·가입 유형별 중위소득 150% 기준표와 비교한 답변을 받는다. 장기요양보험료를 제외하고 피부양자는 주소가 분리되어도 부양자의 고지금액을 사용한다. 가구원 수·가입 유형·부양자 보험료나 대체 소득 증빙이 확인 중이면 미확인으로 남기며, 월급이나 현재 취업 상태로 환산하지 않는다.

중복지원은 신청 전 서울시 이 사업 수혜 여부, 타 기관에서 받은 비용, 확인할 신청 비용을 구분한다. 서울시 이 사업은 생애 1회다. 타 기관에서 한 종류 비용만 받았다면 다른 비용의 중복지원 조건은 충족한다. 두 비용을 함께 확인할 때 한 종류만 중복되면 추가 확인으로 남기고 해당 항목을 제외해 다시 확인하도록 안내한다. 기관·지원 항목·신청 비용이 불명확하면 제한 없음으로 바꾸지 않으며, 타 기관 지원 이력은 공고에 적힌 2022.1.1. 이후 서울 전입·서울 내 이사 범위를 확인한다.

신청 당시 부모 소유 주택 임차, 생계·의료·주거급여 수급, 외국인·재외국민 해당 여부를 각각 확인한다. 교육급여만 받는 경우를 위 세 급여 수급으로 처리하지 않고, 부모와 동거한다는 이유만으로 부모 소유 주택 임차를 추정하지 않는다. 각 항목의 미응답·미확인은 추가 확인으로 남기며 다른 조건의 예외로 면제하지 않는다. 선택한 신청 비용에 맞춰 지출 기간·인정 비용·제외 비용을 안내하되 지급액이나 증빙 적격 여부를 계산하지 않는다. 실제 증빙·기타 참여 제한·선발 심사는 추가 확인으로 남기고 전세사기 피해 주택 소유 예외를 일괄 불충족 처리하지 않는다. 4월 14일 마감 공고를 하반기 모집에 재사용하지 않는다.

## 6. 정책 수집·공개·변경 처리

### 6.1 기본 운영

- 정기적으로 정책을 수집하고 새 정책과 변경 내용을 자동 공개한다. 전건 수동 승인 절차를 두지 않는다.
- 정기 수집은 확인한 호출 한도·최소 간격과 페이지 범위·반복 주기를 설정한 뒤 켠다. 서울 날짜별 요청 예산을 지키며, 한도에 도달하면 마지막 진행 위치를 보존한다. 응답이 저장된 작업은 외부 재요청 없이 재처리하고, 요청 결과가 불명확하면 재전송 전에 확인한다.
- 원본과 출처, 수집 시각, 적용한 정책 버전을 보관하여 변경과 판정의 근거를 추적할 수 있게 한다.
- 동일한 데이터를 다시 수집해도 정책·개정·알림을 중복 생성하지 않는다.
- 형식 검사 통과는 실제 정책 내용과 자격의 정확성을 인증한 것이 아니다.
- AI 조건 추출 요청은 현재 공고 개정·원본·생성 방식에 연결한다. 결과 본문과 처리 사유를 보관하고 최신 개정·최신 요청에 맞는 유효한 결과만 규칙 초안으로 저장한다. 같은 결과의 재수신은 기존 처리 결과를 반환하며 초안을 중복 생성하지 않는다. AI 초안도 관리자 검토 후 별도로 적용한다. 실제 공급자 호출 전에는 기존 예산 예약 절차를 거쳐야 한다.
- 제목·출처 등 표시 자체에 필요한 정보가 깨진 수집 건은 정상 정책을 덮어쓰지 않고 오류로 분리한다. 해석이 어려운 자격 조건만 있다는 이유로 읽을 수 있는 원문 전체를 숨기지는 않는다.

### 6.2 자동화 실패와 예외

| 상황 | 사용자에게 제공할 동작 |
|---|---|
| AI 요약 실패 또는 비용 한도 도달 | 확인 가능한 원문·기존 요약과 규칙 기반 추천 유지. 변경 전 요약을 최신 내용으로 표시하지 않음 |
| 자격 조건 누락·모순·해석 불가 | 추가 확인 필요와 근거 표시 |
| 마감일 누락·충돌 | 날짜 확인 필요 표시, 해당 날짜에 의존하는 마감 알림 보류 |
| 수집 실패 또는 최신 상태 확인 실패 | 마지막으로 확인한 내용과 수집 시각 표시. 최신 상태 확인 실패를 숨기거나 정책 삭제로 간주하지 않음 |
| 정책 내용 변경 | 변경 내용 안내, 영향을 받는 자격 판정과 일정·미발송 알림 갱신 |

- 수집 실패 한 건이 다른 정책의 처리를 멈추게 하지 않는다.
- 관리자는 예외 목록을 선택적으로 확인한다. 매일 30분의 검수를 서비스 운영의 필수 조건으로 두지 않는다.
- 조건 검토 목록은 원문 변경·기간 만료·조건 미등록 정책을 우선 표시한다. 정책명·정책번호 검색과 상태 필터를 제공하고, 상세에서 직전 공개 개정과의 차이·수집 원본·등록된 질문·근거·초안을 확인한다. 직전 개정이 기존 규칙의 검토 원문과 같다는 뜻은 아니다. 조회는 규칙 등록·적용이나 외부 호출을 실행하지 않는다.
- 관리자는 기존 규칙의 적용 기간·안내·질문·선택지·판정표를 화면에서 수정해 새 버전의 초안으로 저장할 수 있다. 질문·선택지 식별자는 유지하고 연령 연결·시기별 안내 등 별도 설정은 보존한다. 원문이 바뀌면 조건과 예외를 검토했다는 확인 후 현재 원문에 연결하며 연도·기간을 자동 이월하지 않는다. 파일 등록·내려받기도 제공한다. 초안 저장은 질문 제공에 영향을 주지 않으며, 원문·질문·판정표·기간을 검토하고 사유를 남겨 별도로 적용한다. 원문·조회한 개정·현재 적용 버전이 바뀌면 적용을 거절한다. 같은 요청·입력·작업자의 재시도는 기존 결과를 반환하며 등록·적용 사유와 작업자를 보관한다.
- 수집 예외 조회는 우선 항목 검증 실패·저장 실패를 대상으로 한다. 실패 목록을 페이지별로 조회하고, 상세에서 저장된 원본과 같은 정책번호의 현재 공개 내용을 확인한다. 재처리로 성공한 항목은 목록에서 제외한다. 세부 실패 사유가 저장되지 않았다면 추정해 표시하지 않는다.
- 페이지 수집 실패는 별도 목록에서 응답 확보 실패·목록 형식 오류를 구분한다. 요청 시작·발송 시작·응답 보관 시각과 보관 여부를 표시하며, 기록하지 않은 실패 시각을 추정하지 않는다. 확인된 오류 유형과 HTTP 상태만 제공하고 원본 응답·임의 오류 문자열은 공개하지 않는다. 같은 수집 실행이 정상 상태로 바뀌면 목록에서 제외하며, 새 실행의 성공으로 이전 실패 이력을 지우지 않는다.
- 수집 실패 상세에서 같은 정책의 현재 내부 개정과 직전 개정을 비교한다. 변경된 표시 항목을 먼저 보여주고 동일한 항목은 펼쳐서 확인한다. 각 개정이 참조하는 원본 수집 시각을 제공하며 개정 적용 시각이나 실패 당시의 내용으로 표현하지 않는다. 이전 개정이 없으면 비교할 내용이 없음을 표시한다.
- 관리자 API는 설정에 명시한 회원 ID의 소셜 로그인 세션만 허용하며, 관리자 설정의 기본값은 비어 있다. `/admin/collection-exceptions`에서 실패 목록·상세를 조회하고 로그인 필요·권한 없음·빈 목록·조회 실패를 구분한다. 로그인 후 관리자 목록으로 돌아온다. 조회 응답은 캐시하지 않으며 원본은 일반 텍스트로 표시한다. 원본 조회·개정 비교만으로 수정·재처리·외부 요청을 실행하지 않는다.
- 보정은 원문과 분리해 근거를 남긴다. 다음 자동 수집이 보정을 조용히 지우거나 오래된 보정을 무조건 적용하지 않게 한다.
- 공개된 정책의 정책명·운영 기관을 한 정책당 한 항목씩 보정할 수 있다. 원본·보정 값·작업자·사유·적용 개정을 분리해 보관한다. 다음 수집에서 보정 대상의 원본 값이 같으면 보정을 유지하고 다른 변경은 반영한다. 대상 값이 달라지면 새 원본을 보관하고 현재 공개 내용을 유지한 채 보정 충돌로 남긴다. 관리자는 확인한 최신 원본을 기준으로 보정을 유지하거나 원본을 적용한다. 조회 후 원본·개정이 바뀌면 재확인을 요구한다. 정책 식별자·자격·마감 조건 및 미공개 정책의 최초 보정 공개는 이 범위에 포함하지 않는다.
- 관리자는 사유를 입력해 실패 항목 하나를 저장된 원본으로 재처리할 수 있다. 외부 재수집 없이 기존 항목 반영 경로를 사용한다. 작업자·사유·처리 결과·처리 후 개정을 항목 반영과 함께 기록하고 관리자 재처리 이력에서 확인한다. 같은 요청을 다시 보내도 한 번만 처리하며, 화면 조회 후 처리 상태가 바뀌었으면 최신 상태를 확인하도록 한다. 저장 장애는 전체 작업을 롤백한다. 표시 값 보정은 별도 보정 관리에서 실행한다.
- 자동 판정 가능 비율은 실제 API 자료 확인 후 측정한다. 모든 정책을 자동 판정할 수 있다고 약속하지 않는다.

## 7. 관심 정책·일정·알림

- 로그인한 사용자가 정책을 저장하면 내 일정에 확인된 신청 마감일을 표시한다.
- 서비스 내 마감 7일·3일·1일 전 알림을 자동 설정한다. 날짜 계산은 서울의 달력 날짜를 기준으로 한다.
- 이미 지난 알림 시점을 저장 직후 몰아서 발송하지 않는다. 아직 남은 시점만 대상으로 한다.
- 이메일 주소는 확인 코드를 입력해 확인한다. 코드는 10분간 유효하고 최대 5회 비교하며, 다시 요청하면 이전 코드는 사용할 수 없다. 요청은 회원별 60초 간격·시간당 3회로 제한한다. 주소 변경은 확인과 수신 동의를 초기화한다.
- 주소 확인과 알림 수신 동의는 별개다. 동의 후 생성되는 알림만 이메일로 보내며 이전 알림을 소급 발송하지 않는다. 주소 삭제는 미발송 요청과 저장된 연락처·확인 코드를 함께 삭제한다.
- 이메일은 사용자가 별도로 활성화한 경우에만 보낸다. 이메일을 끄더라도 서비스 내 일정·알림은 유지한다.
- 이메일 주소가 제공되지 않았거나 사용할 수 없으면 다른 채널로 임의 전환하지 않는다. 주소 입력·확인이 필요한 상태를 안내한다.
- 저장 해제는 아직 발송하지 않은 해당 정책 알림을 취소한다. 이미 발송된 이메일을 회수할 수 있다고 안내하지 않는다.
- 이메일 수신 해제·계정 상태·저장 여부는 실제 발송 직전에도 확인한다.
- 마감일이 변경되면 일정과 미발송 알림을 새 내용에 맞춘다. 확인되지 않은 날짜로 계속 발송하지 않는다.
- 날짜만 있는 마감을 임의의 정확한 시각으로 단정하지 않는다. 상시·예산 소진·마감 미확인은 가짜 마감일을 만들지 않는다.
- 저장한 정책의 변경을 알리고 원문과 최신 내용을 확인할 수 있게 한다. 이메일 변경 알림에도 별도 활성화 조건을 적용한다.
- 발송 성공·실패·결과 미확인을 구분하여 중복 발송을 줄인다. 외부 이메일의 정확히 한 번 전달을 보장한다고 표시하지 않는다.

## 8. 개인정보·운영 비용

- 사용자가 동의한 목적에 필요한 조건만 저장한다. 생년월일, 이메일, 세션·인증 토큰을 로그나 분석 이벤트에 넣지 않는다.
- 공개 정책 페이지의 검색 노출과 사용자별 조건·추천·일정의 비공개 처리를 구분한다.
- AI에 정책 원문을 보내는 것과 사용자 개인정보를 보내는 것은 별개다. MVP 요약·추출에 사용자 생년월일·연락처·개인 조건을 전송하지 않는다.
- 월 운영비는 서버·DB/원본 보관·AI·이메일을 합쳐 3만 원 이내를 기준으로 한다.
- 신규·변경 정책에만 AI를 실행하고 변경 없는 결과는 재사용한다. 초기 전체 적재도 비용 한도를 적용한다.
- AI 한도 소진은 새 요약·추출을 보류하는 사유이며 원문 조회와 가능한 규칙 판정을 중지하는 사유가 아니다.
- 운영 장비·클라우드·배포 형태는 나중에 정한다. 기존 장비 보유, 무료 체험 지속, 특정 공급자 계약을 전제하지 않는다.
- 실제 비용 상한 준수는 공급자 요금·세금·사용량을 포함해 공개 전에 검증한다. 예산 알림만으로 외부 청구가 자동 차단된다고 가정하지 않는다.

## 9. MVP 제외 범위

- 증빙서류 업로드·보관과 정책 신청 대행
- 유료 결제
- 별도 본인확인 절차
- 알림톡·SMS와 외부 캘린더 구독
- 온통청년 외 사이트 크롤링
- 서울 외 지역을 대상으로 한 제품 범위 확대
- AI가 최종 자격이나 선정 가능성을 확정하는 기능

## 10. 성공 지표와 완료 기준

### 10.1 핵심 지표

동일한 측정 기간에 조건 입력을 완료한 사용자 중 **적합 정책을 1개 이상 저장한 사용자 비율**을 본다. 구체적인 측정 기간과 목표 수치는 초기 사용자 관찰 후 정한다. 사용자 식별·비회원에서 회원 전환 시 중복 제거는 개인정보를 최소화하는 방식으로 설계한다.

공식 신청처 이동과 재방문은 보조 지표다. 신청처 이동을 실제 신청 완료로 집계하지 않는다. 저장 시점의 판정 상태와 정책 버전을 구분하여 이후 변경이 과거 지표를 조용히 바꾸지 않게 한다.

### 10.2 필요한 검증

아래는 앞으로 구현할 기능의 완료 기준이며, 현재 테스트 통과 기록이 아니다. 같은 규칙을 모든 계층에서 반복 검증하지 않고 해당 책임 경계의 대표 시나리오를 검증한다.

| 번호 | 완료 기준 | 판단 방법 |
|---|---|---|
| AC-01 | 서울 대상 정책과 전국 공통 정책을 포함하고 실제 지역 제한을 적용한다. | 대표 정책·지역 조합을 코드로 검증 |
| AC-02 | 비회원 검색과 조건 입력이 가능하고 소셜 정보 미제공도 직접 입력으로 보완한다. | API·화면의 대표 흐름 검증 |
| AC-03 | 같은 입력·정책·기준일·규칙으로 같은 결과와 근거가 나온다. | 판정 규칙 단위 검증 |
| AC-04 | 정보 누락, 추가 예외, 알 수 없는 기준일을 신청 가능이나 단순 불충족으로 바꾸지 않는다. | 누락·모순·예외 사례 검증 |
| AC-05 | 동일 자료 재수집과 실패 후 재실행이 정책·개정·알림을 중복 생성하지 않는다. | 실제 PostgreSQL 경계에서 검증 |
| AC-06 | AI 실패·한도 소진 시 원문과 가능한 추천을 유지한다. | 외부 연동 실패 대체 동작 검증 |
| AC-07 | 저장과 마감 변경이 일정·미발송 알림에 반영되고 불명확한 날짜 알림은 보류된다. | 고정 시계와 저장 상태 변경 검증 |
| AC-08 | 이메일 미동의·수신 해제·저장 해제 후 발송하지 않고, 재시도로 중복 발송하지 않도록 처리한다. | 동의·취소·외부 결과 미확인 경계 검증 |
| AC-09 | 계정 변경 후 이전 계정의 조건·저장·일정·늦은 응답이 노출되지 않는다. | 대표 로그인 전환 흐름 검증 |
| AC-10 | 판정 근거·공식 링크·수집 시각·마감 상태를 사용자가 이해하고 정책을 저장할 수 있다. | 초기 사용자와 화면 확인 |
| AC-11 | 월 3만 원 예산과 AI 한도 소진 시 동작을 만족하는 운영안을 확인한다. | 배포 전 견적·제한 시험, 운영 후 실제 청구 확인 |

## 11. 구현·공개 전 확인할 사항

다음은 확정된 MVP를 구현하기 위한 조사와 운영 준비다. 조사 결과 때문에 제품 동작이나 비용 상한을 바꿔야 하면 사용자와 다시 합의한다.

- 온통청년 API 키 발급, 최신 응답 형식·코드 정의·이용 조건·호출 제한·삭제/수정 표시 확인
- 정책 원문의 소득·연령·취업·거주 기준일, 취업·재학 정의와 추가 예외 및 실제 자동 판정 가능 범위 확인
- 수집 주기와 최신 상태 확인 실패 안내 기준 설정
- 날짜형·시각형 마감 사례를 확인한 뒤 일 단위 알림의 발송 시각과 재시도 만료 기준 설정
- 카카오·네이버 정보 제공 권한, 이메일 주소 확인과 발송 공급자 선정
- 개인정보 처리 안내, 보관·탈퇴·삭제 절차와 분석 이벤트 범위 확정
- 예산 내 배포 환경, 외부 백업·복구 확인, 관리자 접근 방식 준비
