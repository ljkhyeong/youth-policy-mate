# AI 요청 예산 예약·정산 상태

## 1. 범위

[PRD 6.2·8절](../PRD/0001_product-baseline/spec.md)과 [AI 요청 전 판단](ai-request-admission.md)을 따른다. 규칙 추출 요청마다 최대 비용을 월 예산에서 예약하고, 외부 호출 이후 결과·청구가 확인되지 않은 금액을 보존하며, 확인된 비용 또는 무과금 근거로 종료하는 상태를 정의한다.

PostgreSQL이 예약·호출 이후 상태 전이의 기준이다. Java에는 별도 상태 엔진이나 이벤트 값 타입을 두지 않고, `PolicyAiRuleCallStore`가 조건부 `UPDATE`로 단계를 바꾼다. DB에는 월 예산과 요청별 호출 기록(예약·발송·결과 미확인·종료 확인)을 저장한다. 공급자 사용량·청구 조회는 없으며, 정산·무과금 정보는 운영자가 확인해 명령으로 전달한 사실만 반영한다. 월 운영비 3만 원 중 AI 배분액과 공급자 가격은 설정으로 받는다.

## 2. 상태와 금액

| 상태 | 의미 | 예약액 처리 |
|---|---|---|
| `HELD` | 입력 토큰 수와 출력 상한으로 계산한 최대 비용을 요청에 확보함 | 유지 |
| `DISPATCHED` | 예약 후 외부 호출을 시작함 | 유지 |
| `OUTCOME_UNKNOWN` | 연결 유실·응답 한도 초과 등으로 결과를 확정하지 못함 | 유지 |
| `SETTLED` | 운영자가 확인한 청구 금액을 확정액으로 반영함 | 최대 비용 예약을 해제하고 실제 비용을 확정액에 추가 |
| `CANCELLED` | 외부 호출 전에 공고 변경·월 경계·요금 만료로 취소함 | 해제 |
| `RELEASED_NO_CHARGE` | 외부 호출 후 무과금을 별도 근거로 확인함 | 해제 |

타임아웃과 요청 실패만으로 무과금을 추정하지 않는다. `OUTCOME_UNKNOWN`은 재시작이나 예산 기간 변경 뒤에도 예약액으로 남는다. 후보 생성 성공 여부와 청구 확인도 별개다. 응답을 받았더라도 실제 비용을 모르면 `DISPATCHED`로 두고 정산하지 않는다.

실제 비용이 최대 예약액보다 크면 그 사실을 버리지 않고 확정액에 반영한 뒤 초과 정산(`OVER_RESERVATION`)으로 구분한다. 이후 잔액 부족은 새 예약을 막는다. 공급자 가격 산정·청구는 별도로 대사해야 한다.

## 3. 중복과 충돌

- 예약 키는 규칙 추출 요청 UUID다. 같은 요청의 재실행은 기존 예약을 반환하고 금액을 더하지 않는다. 재시도는 새 요청 UUID를 사용한다.
- 동시 예약은 예산 행의 조건부 `UPDATE`가 최신 잔액으로 한도를 검사한다. 먼저 커밋한 예약 때문에 남은 금액이 부족해지면 나중 요청을 거절하고, 남은 금액 안이면 함께 예약한다.
- 발송은 `HELD`일 때만 `DISPATCHED`로 바꾼 실행 하나에게 허용한다. 이미 발송했거나 종료한 예약은 다시 호출하지 않는다.
- 정산·무과금 확인은 `DISPATCHED`·`OUTCOME_UNKNOWN`에서만 적용한다. 같은 확인 ID·시각·금액의 재실행은 재생(`REPLAYED`), 다른 종료 결과나 다른 확인 내용은 충돌(`CONFLICT`)로 반환하고 기존 확정을 덮지 않는다.

## 4. PostgreSQL 저장 경계

- `ai_budgets`(V1)는 서울 기준 월 예산 행이다. 기간·한도·확정액·예약액을 저장하고 음수 금액과 잘못된 기간을 막는다. 첫 예약 때 설정 한도로 만들며 이후 설정이 달라도 덮어쓰지 않는다.
- `policy_ai_rule_calls`(V27)는 요청별 호출 한 행에 전송 내용·단가·가격 버전·최대 비용·요금 유효기간과 예약 단계·발송/결과 미확인/완료 시각·확인 ID·실제 비용·원 응답을 둔다. 단계별 필수 열과 시간 순서(예약 → 발송 → 결과 미확인 → 완료)는 CHECK 제약, 전송 내용·비용 예약·저장한 응답의 변경 금지는 트리거로 막는다.
- 예약은 정책 행을 잠근 트랜잭션에서 예산 행의 조건부 `UPDATE`와 호출 행 INSERT를 함께 처리한다. 기본 격리 수준을 유지해 동시 갱신이 직렬화 오류 대신 최신 행 재검사로 끝나게 한다.
- 정산·호출 전 취소·무과금 해제는 호출 행의 단계 전환과 예산 행의 예약 해제·확정을 한 SQL 문장(CTE)으로 처리한다. 다른 종료가 먼저 커밋되면 갱신하지 않아 같은 예약액을 두 번 해제하지 않는다. 예약액이 음수가 되면 CHECK 제약으로 문장 전체가 롤백된다.
- 시각은 UTC `timestamptz`로 저장한다. 재생 판정은 저장한 값과 입력값을 DB에서 함께 비교한다.

## 5. 남은 외부 연결

1. 공급자 사용량·청구 조회로 `DISPATCHED`·`OUTCOME_UNKNOWN` 예약을 정산한다. 지금은 운영자가 확인한 결과를 [관리 명령](../development/ai-rule-drafts.md#openai-설정과-비용)으로 반영한다.
2. 결과 미확인 예약의 자동 재확인이 필요해지면 확인 소유권·펜싱을 다시 설계한다. `OUTCOME_UNKNOWN`을 시간 경과만으로 자동 해제하지 않는다.
3. 내부 최대 비용과 실제 공급자 청구를 대사하고, 초과 청구·가격 변경·환율·세금을 포함한 운영 상한을 공개 전에 검증한다.

현재 구현과 검사 범위는 [개발 기록](../development/ai-budget-reservation-lifecycle.md)을 따른다. 원자적 예약과 상태 전이는 실제 PostgreSQL에서 검증했지만, 이 경계만으로 PRD AC-06·AC-11이나 외부 과금 차단을 완료했다고 보고하지 않는다.
