# AI 미완료 예약 복구 소유권과 확인 이력

## 1. 범위

[AI 예약·정산 상태](ai-budget-reservation-lifecycle.md)와 [AI 실행 경계](policy-ai-execution.md)를 따른다. 서버 재시작 뒤 `HELD`·`DISPATCHED`·`OUTCOME_UNKNOWN` 예약을 여러 작업자가 중복 확인하지 않도록, 제한된 시간의 확인 소유권과 시도 이력을 정의한다.

이번 소유권은 확인할 예약을 한 작업자에게 배정하는 내부 임대다. 인공 복구 조정자는 임대와 예약 상태를 다시 확인한 뒤 정산·무과금·호출 전 취소를 적용한다. 실제 공급자 상태 조회와 AI 재호출은 수행하지 않는다.

## 2. 임대와 시도 상태

호출 측은 시도 ID·작업자 ID·획득 시각·만료 시각을 모두 제공한다. 운영 주기와 공급자 응답 시간이 정해지지 않았으므로 기본 임대 시간을 넣지 않는다.

| 시도 상태 | 의미 |
|---|---|
| `ACTIVE` | 한 작업자가 미완료 예약의 확인 소유권을 가진 상태 |
| `COMPLETED` | 작업자가 임대 시간 안에 확인 시도를 마친 상태 |
| `EXPIRED` | 임대가 끝나 새 작업자가 소유권을 얻거나 늦은 완료가 도착한 상태 |

`COMPLETED`는 AI 결과·청구·예약 상태가 해결됐다는 뜻이 아니다. 확인 시도 결과는 `CHECK_COMPLETED`·`CHECK_FAILED`·`MANUAL_REVIEW_REQUIRED`로 남기고, 소유권 획득 당시 단계와 완료 당시 단계를 따로 저장한다.

## 3. 소유권 획득

- 특정 예약을 직접 선택하거나 가장 오래된 미완료 예약을 선택할 수 있다.
- 다음 예약 선택은 `FOR UPDATE SKIP LOCKED`를 사용한다. 한 작업자가 잠근 예약 때문에 다른 예약의 선택이 기다리지 않는다.
- 같은 예약에는 `ACTIVE` 시도를 하나만 허용한다. 만료 전 다른 작업자는 현재 소유자를 확인하고 획득하지 않는다.
- 만료된 `ACTIVE` 시도는 새 소유권 획득 시 `EXPIRED`로 바꾸고 시도 순번을 증가시킨다.
- 같은 시도 ID와 내용의 재전달은 재생한다. 같은 시도 ID를 다른 작업자·시각·예약에 사용하면 충돌이다.
- 시도 ID 검사는 PostgreSQL 트랜잭션 자문 잠금으로 직렬화한다. 다른 예약의 같은 시도 ID가 동시에 들어와도 한 내용만 저장한다.
- 종료 상태인 예약은 새로 소유하지 않는다.

## 4. 확인 완료

- 소유한 작업자만 시도를 완료할 수 있다.
- 완료 시각은 소유권 획득과 현재 예약 상태보다 빠를 수 없고 임대 만료보다 빨라야 한다.
- 임대 만료 시각과 같거나 늦게 도착한 완료는 적용하지 않고 시도를 `EXPIRED`로 기록한다.
- 같은 완료 정보의 재전달은 재생하고 다른 결과·시각은 충돌로 남긴다.
- 단순 완료는 예약 상태를 바꾸지 않는다. 확인된 청구·무과금·호출 전 중단은 복구 조정자가 펜싱을 통과한 경우에만 기존 `AiBudgetReservationLifecycleStore`로 적용한다.

## 5. 복구 결과 적용과 펜싱

1. 작업자는 임대를 얻은 뒤 현재 예약 단계와 갱신 시각을 읽는다.
2. 외부 확인 포트는 DB 트랜잭션 밖에서 호출한다.
3. 적용 시점에 활성 시도 ID·시도 순번·작업자·만료 시각을 잠가 다시 확인한다.
4. 확인 전후의 예약 단계나 갱신 시각이 다르면 결과를 적용하지 않고 수동 검토 필요로 남긴다.
5. 적용 시각이 임대 만료와 같거나 늦거나 새 시도가 활성화됐으면 오래된 결과를 거절한다.
6. 예약 상태 변경과 복구 시도 완료는 하나의 짧은 트랜잭션으로 처리한다.

시도 순번은 예약마다 증가하는 펜싱 토큰이다. 공급자가 기록한 청구·무과금 시각과 서버가 결과를 적용하는 시각을 구분하고, 임대 유효성은 실제 적용 시각으로 판단한다.

## 6. PostgreSQL 경계

Flyway V3는 `ai_reservation_recovery_attempts`를 만든다. 예약별 시도 순번, 작업자, 임대 기간, 시작·완료 단계와 확인 결과를 보존한다. 부분 유일 인덱스로 예약별 `ACTIVE` 행을 하나만 허용하고, 상태별 필수 열·임대 기간·완료 시각을 제약으로 확인한다.

복구 소유권 저장소는 예약 행만 잠그며 예산 행을 잠그지 않는다. 확인 이력만 기록할 때는 예산 합계를 바꾸지 않기 때문이다. 정산·해제·취소를 적용할 때는 예산→예약→복구 시도 순서로 잠그고, 상태 변경과 시도 완료를 함께 커밋한다. 외부 조회 중에는 DB 트랜잭션을 유지하지 않는다.

## 7. 남은 연결

1. 실제 공급자 상태 조회 어댑터와 작업자·스케줄러를 연결하고 확인 근거를 보존한다.
2. 필요한 경우 임대 갱신 계약을 추가하되, 끝난 임대를 소급 연장하지 않는다.
3. 재확인 주기와 최대 시도 횟수를 정해 완료 직후 같은 예약이 반복 선택되지 않게 한다.
4. 운영자가 오래된 미완료 예약과 시도 이력을 확인할 조회 경계를 만든다.
5. 확인된 AI 결과를 현재 정책 개정과 비교해 후보 상태에 반영한다.

현재 구현은 인공 결과에 대해 복구 경로의 오래된 상태 변경을 막고 만료 이력을 보존한다. 실제 공급자 복구, 정확히 한 번 조회·실행이나 외부 과금 상한을 보장하지 않는다.
