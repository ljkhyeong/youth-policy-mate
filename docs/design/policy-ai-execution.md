# AI 규칙 추출 호출 순서

## 1. 범위

[PRD 6.2·8절](../PRD/0001_product-baseline/spec.md), [AI 요청 전 판단](ai-request-admission.md), [예약·정산 상태](ai-budget-reservation-lifecycle.md)를 따른다. 규칙 추출 요청 한 건의 비용 예약부터 외부 호출 결과 저장까지의 순서를 정의한다. 공급자 요청 형식과 설정은 [규칙 추출 문서](../development/ai-rule-drafts.md)를 따른다.

정책 원문과 요청 기준만 보내며 사용자 생년월일·소득·연락처는 포함하지 않는다.

## 2. 실행 순서

`PolicyAiRuleGenerationService.generate`가 다음 순서로 실행한다. 서비스에는 트랜잭션을 두지 않고 각 저장 단계만 짧은 트랜잭션으로 커밋한다.

1. 저장한 결과가 있으면 그대로 반환한다. 원 응답만 저장돼 있으면 외부 호출 없이 초안 저장만 다시 처리한다.
2. 호출 기록이 `HELD`가 아니면(발송·취소·정산 이후) 다시 호출하지 않고 현재 상태를 반환한다.
3. 설정을 확인하고, 예약이 없으면 입력 토큰 수를 조회한 뒤 `PolicyAiRuleCallStore.reserve`가 정책 행 잠금 아래에서 최대 비용을 예약하고 `HELD` 호출 행을 저장한다.
4. `PolicyAiRuleCallStore.dispatch`가 정책 행을 다시 잠가 공고·요청과 요금 기간을 확인한다. 바뀌었으면 `CANCELLED`로 예약을 해제하고, 그대로면 `HELD`를 `DISPATCHED`로 바꾼 실행만 다음 단계로 간다.
5. 트랜잭션 밖에서 OpenAI를 호출한다. 응답을 기다리는 동안 DB 잠금을 보유하지 않는다.
6. 연결 유실(`RestClientException`)·응답 한도 초과(`IllegalStateException`)는 `OUTCOME_UNKNOWN`으로 기록하고 예약액을 유지한다. 그 밖의 예외는 그대로 전달하며 `DISPATCHED`와 예약액을 유지한다.
7. 응답을 받으면 원 응답부터 별도로 커밋한 뒤 초안을 저장한다. 초안 저장이 실패해도 다시 실행하면 1단계에서 저장한 응답만 처리한다.

AI 응답과 청구 확인은 별개의 사실이다. 응답을 받았다는 이유로 실제 비용을 0원이나 최대 예약액으로 추정하지 않고 `DISPATCHED`로 둔다.

## 3. 재실행과 불명확한 실패

- 같은 요청을 동시에 실행해도 `HELD` 행을 `DISPATCHED`로 바꾼 실행 하나만 외부 API를 호출한다.
- 발송 기록 직후 프로세스가 중단돼 응답이 없는 요청은 자동으로 다시 보내지 않는다. 자동 처리는 운영자 확인 대상으로 남긴다([자동 추출](../development/ai-rule-automation.md)).
- 결과 미확인·청구 대기 예약은 자동으로 재확인하지 않는다. 운영자가 청구·무과금을 확인한 뒤 [관리 명령](../development/ai-rule-drafts.md#openai-설정과-비용)으로 정산·해제한다. 실제 공급자 호출을 정확히 한 번 수행하는 것은 보장하지 않는다.

## 4. 남은 연결

1. 공급자 사용량·청구 조회로 청구 대기 예약을 정산하고 최대 비용 산정과 실제 청구를 대사한다.
2. 미완료 예약을 자동으로 재확인하려면 확인 소유권·임대 만료·상태 변경 펜싱을 다시 설계한다. 이전 구현은 운영 경로에 연결되지 않아 [제거했다](../development/backend-api-review.md#ai-예약-복구-코드-제거--2026-10-05-적용).

현재 구현은 호출 순서와 금액 보존을 검증한 것이다. 실제 AI 품질·공급자 장애·외부 과금 상한이나 PRD AC-06·AC-11을 완료했다고 보고하지 않는다.
