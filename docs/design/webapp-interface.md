# 웹앱 인터페이스 기준

2026-10-06 기준. 이 문서는 모바일을 우선하는 웹앱의 화면 구조와 표현 원칙을 정한다. 제품 기능과 완료 조건은 [PRD](../PRD/0001_product-baseline/spec.md), 현재 조건 입력의 구현 범위는 [비회원 조건 입력](../development/guest-conditions.md)을 따른다.

## 목표

- 사용자가 설명을 읽기 전에 지금 할 수 있는 한 가지 행동을 알 수 있게 한다.
- 작은 화면에서 한 손으로 주요 화면을 오갈 수 있게 한다.
- 실제 정책 데이터가 없는 상태를 가짜 추천이나 예시 정책으로 채우지 않는다.
- 로그인하지 않은 사용자가 입력값의 저장 여부를 행동 전에 알 수 있게 한다.

## 참고한 제품 패턴

2026-09-02 대한민국 App Store 공개 정보를 확인했다. 기능과 시각 표현을 복제하지 않고, 검증된 사용 흐름만 참고한다.

- [토스](https://apps.apple.com/kr/app/%ED%86%A0%EC%8A%A4/id839333328): 한 화면에서 주 행동 하나를 강하게 제시하고 복잡한 정보를 짧은 문장과 단계로 나누는 방식.
- [뱅크샐러드](https://apps.apple.com/kr/app/%EB%B1%85%ED%81%AC%EC%83%90%EB%9F%AC%EB%93%9C/id1195804784): 여러 기능보다 사용자의 현재 상태와 다음 행동을 홈에 우선 배치하는 방식.
- [웰로](https://apps.apple.com/kr/app/%EC%9B%B0%EB%A1%9C/id6444814937): 정책 서비스에서 최소 정보 입력 뒤 맞춤 정책과 마감을 이어서 관리하는 과업 구조. 같은 분야 참고 사례이며 평점이 높은 사례로 분류하지 않는다.

## 화면 구조

### 공통 탐색

- 데스크톱은 상단 앱 바에 `홈`, `정책 찾기`, `내 조건`, `내 정책`을 둔다.
- 모바일은 하단 고정 탭에 같은 네 메뉴를 둔다. 브라우저 안전 영역을 포함해 콘텐츠와 겹치지 않게 한다.
- 현재 화면은 색상과 `aria-current`로 함께 표시한다.
- 앱 이름은 언제든 홈으로 돌아가는 링크다.

### 홈

- 첫 화면은 서비스 소개 페이지가 아니라 사용을 시작하는 앱 홈이다.
- “읽기 어려운 청년 정책 공고, 읽기 쉽게 정리해 뒀어요.”라는 제목 아래 신청서 양식(`□ 해당하는 칸에 표시하세요`)에 다섯 가지 상황을 여러 개 표시하게 한다. 상황은 온통청년 대분류 하나씩에 대응하며, 각 항목에 대응 분야와 정책 수를 함께 적어 어떤 목록으로 가는지 드러낸다. `표시한 칸으로 정책 보기`는 고른 분야를 모두 담은 정책 목록으로, 아무것도 표시하지 않으면 전체 목록으로 이동한다. 수를 불러오지 못하면 상황만 표시한다.
- 상황 항목은 신청서 양식의 네모 칸이다. 실제 체크박스이며 고르면 볼펜 체크가 그려지고 글자가 굵어진다.
- 정책 검색과 검색어 바로가기는 상황 선택 다음에 둔다.
- 조건 비교와 내 정책은 상단 메뉴와 홈 아래 안내 글에서 이동한다.
- 개인정보는 자동 저장하지 않으며 조건 비교를 요청할 때 전송한다는 안내를 행동 가까이에 표시한다.
- 상황 선택·검색 아래에 실제 수집 정책 중 접수 기간인 정책을 최대 4건 보여주고 전체 접수 중 목록으로 연결한다. 해당 정책이 없으면 그 사실과 상시 모집 목록을 안내하고, 조회에 실패하면 이 영역을 표시하지 않는다.
- 하단에서 관심 정책·일정 관리와 공식 신청처 확인을 안내한다. 가짜 정책·성과 수치·처리 시간을 넣지 않는다.
- 데스크톱은 왼쪽에 제목·상황 표시 양식·검색, 오른쪽에 접수 중인 정책을 공고 목록으로 둔다. 모바일은 제목, 양식, 검색, 목록 순서다. 접수 중 정책 다음에 조건 비교 배너와 이용 안내를 둔다.

### 조건 입력

- 정책 둘러보기를 먼저 보여주고 입력은 접기 영역으로 낮춘다. `생년월일로 연령 비교하기`에 `선택` 표시를 붙이고, 거주·취업은 그 안의 두 번째 접기 영역에 둔다. 회원 저장·불러오기도 별도 접기 영역으로 분리한다.
- 접기 영역은 흰 바탕의 둥근 테두리 상자와 오른쪽 화살표로 표시하고, 안쪽 영역은 옅은 보조 면으로 구분한다.
- 입력 항목은 레이블, 컨트롤, 짧은 도움말 순서로 배치한다. `조건 반영`은 기본 버튼, 초기화는 보조 텍스트 버튼으로 낮춘다. 전송·보관 안내는 버튼 바로 아래에 둔다.
- 결과 카드는 공개 목록 카드와 같은 구조로 비교 여부 칩과 접수 상태 배지를 위에 둔다. 비교한 카드는 남색 글자의 칩으로 구분하되 문구에 `다른 조건 확인 필요`를 함께 적어 자격 확정처럼 보이지 않게 한다. 근거는 카드 안의 접기 영역에서 연다.

## 시각 기준

2026-10-06에 기존 화면을 바탕으로 한 재설정(2안 햇살 친근형)을 거둬들이고, 백지에서 다시 짠 Claude Design 새판 시안 중 1안 ‘형광펜 공고문’을 채택했다. 화면은 “읽기 어려운 청년 정책 공고를 읽기 쉽게 정리해 둔 공고 정리함”처럼 보이게 한다. 값은 [디자인 시스템](https://claude.ai/artifact/AW1rPuWSK9acLnwcLWsTMy)과 `frontend/src/app/globals.css`의 `:root` 토큰이 같다.

- 바탕은 흰 종이, 글자는 먹색(`#16181B`), 보조 글자는 `#4A4F57`이다. 카드 상자와 그림자를 쓰지 않고 굵은 먹색 선(2~3px)과 가는 회색 선으로 구역을 나눈다.
- 볼펜 파랑(`#1F3FAE`)은 링크, 손글씨 메모, 볼펜 체크·동그라미, 키보드 초점에 쓴다.
- 형광펜(`#FFF27A`)은 `<mark>`로 공고의 핵심 값(표기 조건 등)에만 칠한다. 데이터에 없는 내용을 강조하려고 문장을 지어내지 않는다.
- 접수 상태는 도장으로 보여준다. `접수 기간`·`상시`는 인주색(`#C8372D`), `접수 전`은 볼펜 파랑, `소진 시 마감`·`기간 미확인`은 갈색, `마감`은 회색 테두리 글자다. 색만으로 구분하지 않도록 도장 문구를 함께 쓴다. D-day는 손글씨 메모로 쓰고, 접수 기간인 정책의 마감일에는 볼펜 동그라미를 친다.
- 글꼴은 세 가지다. 제목과 화면 글자는 운영체제 고딕의 굵은 굵기, 공고 본문은 Noto Serif KR, 여백 메모는 나눔손글씨 펜이다. 웹 폰트는 `next/font`로 빌드할 때 받아 직접 서빙하고, 미리 받지 않으며(`preload: false`) 글꼴이 오기 전에도 글자를 먼저 보여준다(`display: swap`). 화면에 쓰인 글자 조각만 내려받는다.
- 모서리는 각지게(0px) 둔다. 기본 버튼은 먹색 사각 버튼, 보조 버튼은 2px 먹색 테두리다. 입력은 2px 먹색 테두리다.
- 체크박스는 네모 칸에 볼펜 체크를 그린다. 고른 분야·필터는 2px 먹색 테두리와 굵은 글자, 볼펜 체크로 표시한다. 현재 메뉴는 굵은 글자와 먹색 밑줄이다.
- 상세는 공고처럼 짠다. 표기 조건은 `□ 한눈에` 상자, 본문 절은 번호(`1. 지원 내용`)를 붙인 명조 본문이다. 960px 이상에서는 오른쪽 여백 칸에 손글씨 메모를 두고, 좁은 화면에서는 메모를 본문 아래로 내린다. 메모는 남은 날, 표기 조건의 성격, 참여 제한 확인처럼 데이터에서 나온 사실이나 확인 안내만 쓴다.
- 탐색은 모든 폭에서 상단의 글자 메뉴 네 개(홈, 정책 찾기, 내 조건, 내 정책)다. 하단 탭 막대는 쓰지 않는다.
- 분야는 색으로 구분하지 않고 글자로 쓴다. 분야 아이콘·분야 색 면은 쓰지 않는다.
- 원천의 `YYYYMMDD` 날짜는 사용자 화면에서 `YYYY.MM.DD`로 표시한다. 관리자 원본 비교 화면은 수집 값을 그대로 보여준다.
- 조건 입력·상세 본문은 약 680px(상세는 여백 칸 포함 약 1,000px), 홈·정책 목록은 약 1,040px 안에서 구성한다.
- 관리자 화면은 같은 토큰을 쓰되 구조는 바꾸지 않는다.

## 현재 구현과 남은 범위

- 홈·정책 목록·상세·조건 입력과 공통 탐색에 이 기준을 적용했다. 관심 정책·일정·알림은 로그인 후 이용한다.
- 2026-09-11에 대표 화면의 모바일·데스크톱 배치와 검색·필터·질문 이동·키보드 초점을 확인했다. [디자인 점검과 검증](../development/interface-design-review.md)
- 설치형 PWA, 네이티브 앱 패키징, 오프라인 사용, 웹 푸시는 이 문서로 확정하지 않는다.

### 정책 목록·상세

- 목록에는 제목·설명 검색과 확인한 정책 수를 표시한다. 전체 수집 전에는 일부 정책을 제공한다는 안내와 온통청년 이동 경로를 둔다.
- 상세는 신청 기간 바로 아래에서 관심 정책을 저장하고, 지원 내용·신청 안내와 공식 원문을 읽은 뒤 조건 질문으로 이어진다. 저장은 한 줄 행동이라 본문 읽기를 막지 않으며, 분량이 큰 질문은 본문 뒤에 둔다.
- 내 정책의 저장 카드는 목록 카드와 같은 순서(접수 상태·D-day, 제목, 신청기간, 안내, 행동)를 쓴다. 마감 일정 탭은 왼쪽에 연도·월.일·요일 날짜 블록을 둔다. 요일은 날짜 문자열로 계산해 브라우저 시간대로 옮기지 않는다. 상단에 본문·질문 이동 링크를 제공한다. 원문 충돌과 미확인 안내, 출처·수집 시각을 유지한다.
- 검색어와 접수 상태는 하나의 검색 버튼으로 적용한다. 분야·질문 필터는 검색어·접수 상태를 유지한다. 기본 순서는 접수 중인 정책을 마감 임박순으로 먼저 보여준다. 접수 상태 문구는 자격이 있다는 뜻으로 읽히지 않게 ‘신청 가능’ 대신 ‘접수 기간’·‘접수 중’을 쓴다. 같은 순위만 남는 접수 상태 필터(마감·상시 등)에서는 정렬 안내를 표시하지 않는다.
- 카드 위쪽에 분야·접수 상태와 접수 기간인 정책의 D-day를 표시하고(여러 분야로 분류된 정책은 분야를 하나씩 따로 표시) 상태 설명은 펼쳐볼 수 있게 한다. 상세의 신청 기간 영역에도 같은 D-day를 표시한다.
- 연결 실패는 빈 결과와 구분하고 다시 불러오기를 제공한다. 상세 주소가 없으면 정책 목록으로 이동하는 404 안내를 제공한다.
