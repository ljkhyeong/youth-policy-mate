# 관리자 이메일 발송 현황

2026-09-12 구현 기준. 운영 관리의 **이메일 발송** 메뉴(`/admin/collection-exceptions/email`)에서 발송 기록을 조회한다. 공급자 계정·도메인·웹훅 설정은 [외부 API 연결](external-api-runtime.md)을 따른다.

## 제공 기능

- 최근 24시간·7일·30일·90일 요청을 상태·메일 종류로 조회한다. 기본 기간은 최근 7일이며, 필터 변경은 첫 페이지부터 조회한다.
- 선택 기간의 전체 요청·실패/반송/신고/차단·결과 미확인 건수를 표시한다. 이 요약은 상태·종류 필터와 관계없이 기간 전체를 집계한다. 목록의 조회 건수는 필터를 적용한 결과다.
- 현재 발송 활성화 여부와 공급자를 표시한다. 발송을 꺼도 기존 기록을 볼 수 있다. 설정값은 실제 공급자 연결 성공을 뜻하지 않는다.
- 발송 요청 접수·수신 서버 전달·지연·실패·미확인·반송·신고·차단·취소를 구분한다. 수신 서버 전달은 사용자 열람을 뜻하지 않는다.
- 요청 ID·공급자 발송 ID와 요청·발송 시작·처리 완료·공급자 이벤트 발생 시각을 제공한다. 시각이 없으면 `기록 없음`으로 표시하며 모두 서울 시간으로 표시한다.
- Resend 발송 ID가 있는 기록은 [공급자의 최신 상태](email-provider-status.md)를 버튼으로 조회한다. 조회용 키가 필요하며 결과는 기존 발송 기록과 별도로 표시한다.
- 회원 ID·설정 버전·이메일 주소·본문·인증 코드·원문 웹훅은 반환하지 않는다. 개인정보 검색·내려받기·재발송 기능은 추가하지 않았다.

조회 실패는 빈 결과나 발송 꺼짐으로 표시하지 않는다. 비회원은 로그인 안내, 일반 회원은 관리자 권한 안내를 받는다. 조회 오류 후 재시도·페이지 이동은 선택한 필터를 유지한다.

## API와 저장

`GET /api/v1/admin/email-deliveries`

| 매개변수 | 범위·기본값 |
|---|---|
| `page` | 1~1000, 기본 1 |
| `pageSize` | 1~50, 기본 20 |
| `days` | 1~90, 기본 7. 조회 시각에서 해당 일수만큼 이전 요청부터 포함 |
| `state` | 발송 상태. 생략하면 전체 |
| `kind` | `VERIFICATION` 또는 `POLICY`. 생략하면 전체 |

응답은 `AdminEmailDeliveryPage` 생성 계약을 사용한다. 요약·목록 건수·페이지는 읽기 전용 `REPEATABLE_READ` 트랜잭션에서 조회하며 요청 시각 역순·ID 역순으로 정렬한다. 미래 시각의 요청은 제외한다. V30은 기간·정렬 조회용 인덱스를 추가하며 기존 데이터를 변경하지 않는다.

기존 소셜 로그인 세션과 관리자 허용 목록을 사용한다. 401은 로그인 필요, 403은 권한 없음, 400은 잘못된 조회 조건, 503은 조회 실패다. 응답은 `no-store`이며 웹 서버는 고정된 내부 API에 세션 쿠키만 전달한다. 목록 조회는 이메일 배정·상태 복구·공급자 호출을 실행하지 않는다.

## 검증

현재 공급자 조회 기능과 전체 서버·웹 검증은 [Resend 상태 조회](email-provider-status.md#검증)에 기록했다. 아래는 기존 목록·필터 검증 범위다.

- `npm run verify -- test:admin-email`: PostgreSQL에서 관리자 권한·기간 경계·정렬·페이지·필터·개인정보 제외·읽기 전용 동작·오류 응답 통과.
- `npm run generate:api` 후 `check:api-types`, `check:web`, 관리자 이메일/서버 조회/공통 메뉴 `test:web` 통과.
- `build:web`, `package:backend` 통과. 관리자 기능에서 발송 로직을 바꾸지 않아 전체 서버 테스트는 반복하지 않았다. 별도 Resend 변경의 이메일 테스트 통과 기록(`1789187521181-d7fd7098.log`)이 현재 파일과 일치해 재사용했다.
- 임시 API와 별도 Node 24 웹 빌드에서 로그인 필요·권한 없음·조회 실패·필터·다음 페이지·키보드 이동·390px 가로 넘침 없음을 확인했다. 실제 회원 설정이나 이메일 발송은 실행하지 않았다.

로컬 로그는 `.local/verification/1789187417135-f9fe6af8.log`(관리자 API), `1789187413131-d369214c.log`(웹 테스트), `1789187413131-cf482e51.log`(웹 검사), `1789187413131-ed1c63dd.log`(계약), `1789187480307-599727ab.log`(웹 빌드), `1789187480376-5f44998a.log`(서버 실행 파일)에 있다. 브라우저 결과·화면은 `/tmp/youth-admin-email-ui/`에 있다.

별도로 변경된 Resend 전송 헤더·웹훅 응답·운영 예시 등은 이번 관리자 기능의 변경에 포함하지 않았다. 해당 변경의 검증·커밋 상태는 인계 문서를 확인한다.

로컬 API에 V30을 적용했고 상태 응답 200·관리자 API 비회원 401·웹 페이지 200·정책 40건 유지와 임시 검증 서버 종료를 확인했다.
