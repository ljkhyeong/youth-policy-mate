# AI 요청 예산 예약·정산

2026-10-07 구현 기준. [설계](../design/ai-budget-reservation-lifecycle.md)에 따라 규칙 추출 호출 기록 한 행과 월 예산 행으로 요청별 최대 비용 예약과 호출 이후 상태 변경을 처리한다. 공급자 청구 조회는 없다.

## 코드와 동작

`PolicyAiRuleCallStore`가 예약부터 정산까지 담당한다. 단계는 문자열(`HELD` 등)로 저장·반환하며 별도 상태 타입을 두지 않는다.

- `reserve`: 정책 행을 잠가 최신 요청인지 확인하고, 기존 호출이 있으면 그대로 반환한다. 없으면 서울 기준 월 예산 행을 만들거나 읽어 한도 설정이 같은지 확인한다. 요금 유효기간이 지났으면 `COST_EXPIRED`, 예산 기간 밖이거나 잔액이 최대 비용보다 작으면 `BUDGET_LIMIT`로 거절한다. 예산 행의 조건부 `UPDATE` 한 번으로 예약액을 더하고 `HELD` 호출 행을 저장한다.
- `dispatch`: 정책 행을 다시 잠가 공고·요청이 그대로이고 요금 기간 안이면 `HELD`를 `DISPATCHED`로 바꾼다. 바꾼 실행만 `true`를 받아 외부 API를 호출한다. 공고가 바뀌었거나 요금 기간이 끝났으면 `CANCELLED`로 바꾸고 예약액을 해제한다.
- `markOutcomeUnknown`: `DISPATCHED`일 때만 결과 미확인 시각을 기록하고 예약액을 유지한다.
- `settle`·`releaseNoCharge`: `DISPATCHED`·`OUTCOME_UNKNOWN`일 때만 확인 ID·시각과 실제 비용을 기록하고 예산을 갱신한다. 결과는 `APPLIED`, `OVER_RESERVATION`(예약보다 큰 청구), `REPLAYED`(같은 확인의 재실행), `CONFLICT`(호출 전·다른 종료·다른 확인 내용) 중 하나다.

외부 호출은 이 저장소 밖 `PolicyAiRuleGenerationService`에서 트랜잭션 없이 수행한다. 순서는 [실행 순서](../design/policy-ai-execution.md)를 따른다.

## PostgreSQL 저장

| 구성 | 역할 |
|---|---|
| `ai_budgets`(V1) | 예산 ID·기간·한도·확정액·예약액 저장. 음수 금액과 잘못된 기간 차단 |
| `policy_ai_rule_calls`(V27) | 요청 UUID별 전송 내용·단가·가격 버전·최대 비용·요금 유효기간, 단계·발송/결과 미확인/완료 시각·확인 ID·실제 비용, HTTP 상태·원 응답 |

- 단계별 필수 열과 예약 → 발송 → 결과 미확인 → 완료의 시간 순서는 CHECK 제약으로 막는다. 역전된 시각과 음수 청구는 `DataIntegrityViolationException`으로 거절된다.
- 트리거가 전송 내용·단가·가격 버전·최대 비용·예약 시각·요금 유효기간의 변경과 저장한 응답의 변경을 막는다. 응답을 저장한 뒤에도 단계·정산 열은 갱신할 수 있다.
- 정산·취소·무과금 해제는 호출 행과 예산 행을 CTE 한 문장으로 갱신한다. 동시에 도착한 종료 결과 중 먼저 커밋한 하나만 반영된다.
- 예산 행을 만드는 운영 API는 없다. 첫 예약이 설정 한도로 만들고, 이미 있는 달의 한도는 덮어쓰지 않는다.

이전 예약 테이블 `ai_request_reservations`(V1·V2)와 V3–V9 복구 테이블, 이를 쓰던 예약·수명주기 저장소·실행 조정자는 삭제했다([결정 기록](backend-api-review.md#ai-예약실행-계층-통합--2026-10-07-적용)).

## 검사

Docker가 실행 중인 환경에서 저장소 루트의 다음 명령을 실행한다.

```sh
npm run verify -- test:ai-reservation-db
```

`PolicyAiRuleCallStoreTest`가 실제 PostgreSQL 18.6 Testcontainers로 다음을 확인한다.

- 다른 공고의 동시 예약에서 최신 잔액 안의 요청만 예약되고, 같은 요청의 재예약은 금액을 더하지 않음
- 요금 만료·예산 기간 밖·한도 부족·이미 만든 월 예산과 다른 한도 설정의 거절
- 한 번만 발송, 결과 미확인의 예약액 유지, 정산·초과 정산·재생·충돌
- 발송 전 새 요청·요금 만료의 취소와 예약액 해제, 무과금 확인의 적용 범위와 재생
- 동시에 도착한 정산과 무과금 확인 중 하나만 확정
- 단계별 필수 열·역전된 시각·음수 청구·음수 예산의 DB 제약

생성 서비스를 거친 발송·응답 보관·트리거 검사는 `test:ai-rule-generation`이 함께 확인한다. 테스트 금액·식별자·시각은 인공 값이며 운영 예산이나 가격 권장값이 아니다. 실제 AI·공급자 청구는 검사하지 않는다.

## 남은 작업

- 월 운영비 3만 원 내 AI 배분액과 공급자별 최대 비용 산정·갱신 기준
- 결과 미확인 조회·운영 표시·재확인 절차
- 최대 예약액과 실제 청구의 대사, 초과 청구 처리와 운영 상한 검증

현재 저장소는 설정한 한도·단가와 호출 측이 계산한 최대 비용을 신뢰한다. 원자적 예약은 검증했지만 공급자 가격·청구 정확성이나 외부 비용 상한을 보장하지 않는다.
