# AI 요청 전 재사용·비용 판단 모델

2026-08-31 구현 기준. [설계](../design/ai-request-admission.md)에 따라 새 AI 요청을 검토할 때 후보 재사용·호출 보류·예산 예약 필요를 계산하는 순수 Java 모델을 추가했다. 이 모델 자체는 예산을 예약하거나 AI를 호출하지 않는다. 후속 PostgreSQL 예약 경계는 아래 연결 문서에서 구분한다.

## 코드와 입력

코드는 `backend/src/main/java/kr/youthpolicymate/ingestion/`에 있다.

| 코드 | 역할 |
|---|---|
| `AiRequestBudget` | AI 예산과 요청별 최대 비용의 확인 여부. 누락과 0원을 구분 |
| `Balance` | 예산 ID·기간·한도·확정액·예약액. 원화 잔액 계산 |
| `CostCeiling` | 정확한 예정 요청·가격 산정 버전·유효 종료·최대 원화 비용 |
| `PolicyAiRequestAdmission` | 현재 개정·후보·요청·처리 모드·예산·검사 시각의 사전 판단 |

`assess(change, candidates, request, mode, budget, at)`를 호출한다. `change`는 기존 개정 모델의 `Transition`, `candidates`는 AI 후보 상태, `request`는 해당 정책·작업 종류의 예정 요청이다. 모드는 `AUTOMATIC`과 `RETRY`다. 새 요청·예약·실패 기록을 만들거나 원본·후보 상태를 수정하지 않는다.

금액은 소수 원화까지 `BigDecimal`로 비교한다. 한도·비용이 없으면 `Optional.empty()`로 전달하고 기본값을 만들지 않는다. 테스트의 예산·가격은 인공 수치이며 운영 권장값이 아니다. 예산 기간·비용 유효기간도 호출 측이 제공하며 현재 공급자 청구 계약을 뜻하지 않는다.

## 반환 결과

- `Reuse`: 현재 개정·생성 방식에 맞는 기존 후보. 예산·비용이 미설정이거나 소진되어도 추가 호출 없이 재사용할 수 있다.
- `Deferred`: 새 호출 보류. 현재 개정 없음·오래된 근거, 처리한 순번, 새 개정 아님·명시적 재시도 필요·재시도 근거 없음, 예산 미설정·기간 밖·한도 소진, 최대 비용 미확인·요청 불일치·만료를 구분한다.
- `ReservationRequired`: 주어진 입력 기준으로 최대 비용이 잔액 이내다. 비교에 사용한 예산과 비용 정보를 함께 반환한다. **호출 허용이나 예약 완료가 아니다.**

자동 처리는 새 개정을 만든 수집만 대상으로 한다. 같은 개정에 이미 처리 결과가 있으면 자동 반복하지 않는다. 재시도에는 현재 개정·생성 방식의 미생성 결과와 더 높은 요청 순번이 필요하다. 재시도 횟수·대기 시간·반복 실행은 제공하지 않는다.

`ReservationRequired`만으로 같은 잔액을 동시에 통과하는 요청을 막을 수 없다. 후속 [예약·정산 상태 모델](ai-budget-reservation-lifecycle.md)의 PostgreSQL 저장소가 예산 행을 잠그고 최초 `HELD` 예약을 원자적으로 저장한다. 정책·후보·예정 요청은 아직 DB에 없으므로 이들의 최신성 확인은 남아 있다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-admission
npm run test:ingestion
npm run check:backend
```

전용 `test:ai-admission`은 14건이다. 현재 `test:ingestion`은 수집 진행 12·AI 후보 12·실행·복구 결과 연결 8·사전 판단 14·후속 예약 상태 13·복구 재확인 정책 11건, 총 70건을 선택한다. 단위 검사에는 인증키·DB·Docker가 필요하지 않으며 전체 서버 빌드는 PostgreSQL 통합 테스트 때문에 Docker가 필요하다.

전용 명령 14건과 전체 서버 229건(도메인 214·개발 API/계약 13·실제 DB/기본 차단 2), 빌드가 실패·건너뛰기 없이 통과했다. Gradle 캐시·Docker 접근에 권한 확장을 사용했고 기존 JVM 클래스 공유 경고는 유지했다.

주요 검증은 예산과 무관한 후보 재사용, 신규·변경 개정, 확정액·예약액·소수 최대 비용, 잔액과 정확히 같은 비용, 예산 미설정·0원·초과, 기간 시작/종료, 비용 만료·다른 요청의 비용, 단순 재수집·생성 방식 변경의 자동 호출 보류, 명시적 재시도의 비용 재검사다.

화면·API 계약·DB 스키마는 바꾸지 않았다. 웹·브라우저·생성 타입 검사는 다시 실행하지 않았고 기존 웹 53건은 앞선 기록이다. 실제 온통청년·AI 요청, GitHub 푸시·배포는 하지 않았다.

## 남은 작업

- 월 운영비 3만 원 내 AI 배분액, 실제 최대 비용 산정·세금·환율·가격 변경 확인
- 신규 개정·후보·예정 요청의 저장·조회와 예약 시 최신성 확인
- 구현한 호출 전 취소·결과 미확인·정산 상태를 실제 DB 저장과 재시작 복구에 연결
- 한도 보류를 기존 AI 미생성 기록에 연결하고 재시도 주기·횟수를 정하는 작업
- 현재 원문·규칙 판정을 유지하는 실제 API·화면, 공급자 사용량·청구 대사

사용액·예약액·최대 비용은 입력 값을 신뢰해 비교하며 공급자 청구의 정확성을 검증하지 않는다. 사전 판단만으로 PRD AC-06·AC-11의 실제 연동·월 운영비 상한 준수를 완료했다고 보고하지 않는다.
