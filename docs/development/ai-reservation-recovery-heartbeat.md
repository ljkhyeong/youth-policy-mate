# AI 예약 복구 자동 heartbeat 조정

2026-09-02 구현 기준. 복구 작업자가 외부 공급자 상태를 확인하는 동안 호출 측 스케줄러로 활성 임대를 갱신하고, 갱신이 거절되면 외부 확인 결과를 예약에 적용하지 않는다. 실제 공급자 어댑터·운영 작업 스케줄러·공급자별 임대 값은 포함하지 않는다.

## 구성과 책임

| 구성 | 역할 |
|---|---|
| `PolicyAiRecoveryHeartbeat` | 외부 확인 전에 heartbeat를 예약하고 확인이 끝나면 취소하며, 갱신 결과를 다음 실행 여부로 분류 |
| `HeartbeatPlan` | 호출 측이 정한 heartbeat 주기와 갱신 뒤 유지할 임대 길이 보유 |
| `HeartbeatScheduler` | 실제 반복 실행 방식 분리. `ScheduledExecutorService` 어댑터와 결정적인 테스트용 스케줄러 제공 |
| `AiReservationRecoveryLeaseRenewalStore` | 현재 시도·순번·소유자·만료 시각을 다시 확인하고 짧은 트랜잭션으로 갱신 |
| `PolicyAiRecoveryCoordinator` | heartbeat 완료 결과만 기존 응답 검사와 상태 적용으로 전달하고, 거절 결과는 `HeartbeatStopped`로 반환 |

기존 생성자는 heartbeat 없이 실행하는 호환 경로로 유지한다. 자동 작업자는 `PolicyAiRecoveryHeartbeat`를 전달한 조정자를 사용해야 하며, 반복 실행기의 생성·종료도 호출 측이 소유한다.

## 실행 순서

1. 활성 시도와 현재 예약 스냅샷을 읽는다.
2. 종료 예약이 아니면 외부 확인 전에 호출 측 주기로 heartbeat를 예약한다.
3. 각 heartbeat는 서버 시각에 임대 길이를 더해 새 만료를 계산한다. 현재 만료보다 길지 않으면 DB 갱신을 생략한다.
4. 실제 갱신은 기존 저장소에서 별도 짧은 트랜잭션으로 실행한다.
5. 외부 확인이 끝나면 예약된 heartbeat를 취소하고, 이미 진행 중인 갱신과 결과 판정이 겹치지 않게 같은 실행 상태에서 직렬화한다.
6. `RENEWED`·`REPLAYED`만 외부 확인 결과 적용을 허용한다. 다른 갱신 결정은 `HeartbeatStopped`로 반환하고 AI 확인 결과를 폐기한다.
7. 갱신 저장 예외는 외부 확인이 끝난 뒤 호출자에게 전달한다. 이 경우에도 AI 확인 결과는 적용하지 않는다.

새 만료를 이전 만료에 반복해서 더하지 않고 heartbeat 서버 시각을 기준으로 계산한다. 따라서 작업이 오래 걸려도 현재 시각에서 필요한 임대 길이만 유지한다. 임대 길이는 heartbeat 주기보다 길어야 하며 공급자 선정 전에는 기본값을 두지 않는다.

## 갱신 실패와 외부 호출

갱신 실패는 이미 임대가 끝났거나, 다른 작업자가 새 시도를 얻었거나, 예약이 종료됐거나, 관찰한 만료 시각이 오래됐다는 의미일 수 있다. 이때 이전 작업자의 외부 확인 결과를 적용하면 새 소유자의 결과를 덮을 수 있으므로 결과를 사용하지 않는다.

현재 경계는 이미 시작한 외부 호출을 중간에 강제 취소하지 않는다. 외부 포트가 반환할 때까지 기다린 뒤 결과를 버린다. 실제 공급자 SDK가 안전한 취소를 지원하는지와 취소가 청구에 미치는 영향은 공급자 선정 후 별도로 정한다.

제한 목록 작업의 영속 집계에는 heartbeat 전용 열이 없다. `HeartbeatStopped`는 메모리의 후보 결과에는 구분되어 남지만 기존 완료 집계에서는 조정자가 완료 결과를 만들지 못한 수에 포함된다. 운영 지표를 확장할지는 실제 자동 작업 연결 전에 결정한다.

```sh
npm run test:ai-recovery-execution
npm run check:backend
```

- 복구 조정자 16건: 외부 확인 전 heartbeat 예약, 갱신 성공 뒤 최초 만료 이후 정산, heartbeat 취소, 만료 시 갱신 거절과 결과 폐기 포함

- 공급자 응답 시간과 운영 주기를 확인한 임대 길이·heartbeat 주기 결정

- heartbeat 중단을 작업 실행 영속 집계에서 별도 구분할지 결정
