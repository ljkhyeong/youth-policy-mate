# AI 예약 복구 활성 임대 갱신

2026-09-02 구현 기준. 외부 공급자 상태 확인이 최초 임대보다 오래 걸릴 때 같은 작업자가 끝나기 전의 활성 임대를 연장한다. [복구 소유권 설계](../design/ai-reservation-recovery.md)의 소유자·시도 순번·시각 펜싱을 따르며 [자동 heartbeat 조정](ai-reservation-recovery-heartbeat.md)이 이 저장 경계를 호출한다. 고정 주기·실제 공급자 호출은 포함하지 않는다.

## 저장 계약

Flyway V8의 `ai_reservation_recovery_lease_renewals`는 다음 값을 저장한다.

- 재전달과 충돌을 구분할 갱신 ID
- 대상 복구 시도 ID와 예약별 시도 순번
- 현재 임대를 가진 작업자 ID
- 작업자가 확인한 기존 임대 만료 시각
- 갱신 시각과 새 임대 만료 시각

한 시도의 같은 기존 만료 시각에는 성공 기록을 하나만 허용한다. 성공한 감사 기록은 갱신 시각이 기존 만료보다 빠르고 새 만료가 기존 만료보다 늦어야 한다. 최초 소유권 획득 시각·작업자·시도 순번은 바꾸지 않는다.

## 갱신과 펜싱

`AiReservationRecoveryLeaseRenewalStore.renew`는 다음 순서로 처리한다.

1. 갱신 ID를 PostgreSQL 자문 잠금으로 직렬화하고 같은 명령이면 기존 기록을 재전달한다.
2. 예약 행을 잠그고 대상 시도 행을 잠근다.
3. 예약 ID·시도 ID·시도 순번·작업자와 호출 측이 확인한 기존 만료 시각을 현재 값과 비교하고, 갱신 시각이 예약·시도의 마지막 변경보다 과거가 아닌지 확인한다.
4. 미완료 예약의 `ACTIVE` 시도이고 갱신 시각이 현재 만료보다 빠를 때만 새 만료와 감사 기록을 한 트랜잭션에 저장한다.

같은 갱신 ID의 다른 내용, 다른 작업자·시도 순번·예약, 완료·만료된 시도, 종료 예약, 이미 바뀐 만료 시각, 현재 상태보다 과거인 갱신 시각과 끝난 임대는 현재 값을 바꾸지 않는다. 서로 다른 갱신 ID가 같은 임대 스냅샷에 동시에 도착해도 예약·시도 잠금과 DB 유일 제약으로 하나만 반영한다.

갱신 시각은 호출 측이 제공하는 서버 시각이다. 실제 작업자를 연결할 때는 신뢰할 수 있는 서버 시계를 사용하고 클라이언트나 공급자 응답이 제시한 시각을 그대로 사용하지 않아야 한다.

## 기존 결과 펜싱과 연결

갱신 성공은 `ai_reservation_recovery_attempts.lease_until`을 새 만료로 바꾼다. 복구 결과 적용 경계는 예약과 시도 행을 다시 잠근 뒤 DB의 현재 만료 시각을 읽으므로 별도 예외 경로 없이 갱신된 임대를 사용한다.

인공 복구 조정자 검사에서는 트랜잭션 밖 공급자 확인 중 임대를 갱신한 뒤, 최초 만료보다 늦고 새 만료보다 빠른 시각에 결과를 적용해 정산과 시도 완료가 성공하는 것을 확인한다. 갱신에 실패한 작업자가 결과를 적용하면 기존 임대·시도 순번 펜싱이 그대로 거절한다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-recovery
npm run test:ai-recovery-execution
npm run check:backend
```

- 복구 저장소 16건: 연속 갱신·재전달·갱신 ID 충돌, 소유자·시도 순번·이전 만료 시각, 종료·완료 상태, 동시 갱신과 DB 시간 제약 포함
- 복구 조정자 16건: 자동 heartbeat 갱신 후 최초 만료 뒤 결과 적용과 갱신 거절 뒤 결과 폐기 포함
- 전체 백엔드 341건: 실패·오류·건너뛰기 없이 통과

전체 구성은 DB 없는 도메인 246건, 개발 API·계약 13건, PostgreSQL 예약·실행·복구·임대 갱신·heartbeat·운영 조회·기본 차단 82건이다. 화면·API 계약은 변경하지 않았고 Flyway V8까지 적용했다.

## 남은 작업

- 공급자 응답 시간과 운영 주기를 확인한 임대 길이·갱신 간격·최대 연장 기준
- 실제 작업자에서 heartbeat 포함 조정자와 반복 실행기의 생명주기 연결
- 갱신 실패 시 진행 중 외부 확인의 취소 가능 여부와 운영 절차
- 실제 공급자 상태 조회와 관리자 운영 화면
