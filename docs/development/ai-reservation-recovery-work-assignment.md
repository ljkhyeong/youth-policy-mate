# AI 예약 복구 작업 배정

2026-09-02 구현 기준. [내부 운영 조회](ai-reservation-recovery-operations-query.md)에서 선택한 `Ready` 후보를 현재 PostgreSQL 상태로 다시 확인하고 한 작업자에게 배정한다. 배정된 시도는 후속 [인공 복구 조정자](policy-ai-recovery-execution.md)에 연결했다. 실제 공급자 확인과 자동 반복 실행은 포함하지 않는다.

## 배정 흐름

`AiReservationRecoveryWorkAssigner.assign`은 운영 조회 결과, 그 결과에 포함된 후보와 호출 측이 만든 임대를 받는다.

- 후보가 운영 조회 결과에 실제로 포함돼 있어야 한다.
- 조회 당시 판단이 `Ready`가 아니면 DB 소유권 획득을 시도하지 않는다.
- 임대 시작 시각은 운영 조회 판단 시각보다 빠를 수 없다.
- 최대 시도 횟수·재확인 간격·임대 길이는 호출 측이 제공하며 고정 기본값은 없다.

`AiReservationRecoveryStore.claimIfReady`는 시도 ID를 직렬화한 뒤 예약 행을 잠근다. 같은 트랜잭션에서 현재 예약 스냅샷과 전체 복구 이력을 다시 읽고, 실제 임대 시작 시각으로 재확인 정책을 계산한다. 결과가 여전히 `Ready`일 때만 새 활성 시도를 저장한다.

조회 뒤 활성 임대·재확인 대기·수동 검토·최대 횟수 도달·종료 상태가 생기면 현재 판단을 반환하고 새 시도를 만들지 않는다. 같은 배정 요청은 기존 시도를 재전달하며, 같은 후보에 대한 서로 다른 작업자의 동시 배정은 한 작업자만 통과한다.

## 현재 연결 범위

배정 결과인 `ReadyClaimed`는 `PolicyAiRecoveryCoordinator.recoverAssigned`의 입력이다. 조정자는 전달받은 값만 믿지 않고 DB의 같은 시도를 다시 읽는다. 시도가 없거나 완료·교체됐다면 외부 확인을 시작하지 않는다. 현재 시도가 그대로 `ACTIVE`이면 예약 상태를 읽고 트랜잭션 밖에서 인공 확인 포트를 호출한 뒤 기존 펜싱 적용기로 결과를 처리한다. 배정 후 예약이 종료됐다면 공급자 조회 없이 시도를 `MANUAL_REVIEW_REQUIRED`로 마친다.

기존 `PolicyAiRecoveryCoordinator.recoverNext`는 자체 `claimNext`를 사용하는 호환 경로로 남아 있다. 재확인 정책이 필요한 자동 작업은 운영 조회→작업 배정→`recoverAssigned` 순서를 사용해야 한다.

후속 [제한 목록 실행](ai-reservation-recovery-work-runner.md)은 한 운영 조회 결과에서 `Deferred`·`Stopped`를 건너뛰고 `Ready`만 배정·실행한다. 조회 뒤 판단이 바뀌어 미배정된 후보와 후보 단위 외부 확인 실패도 결과에 남기고 다음 항목을 계속 처리한다.

관리자 API·화면·인증·권한, 스케줄러, 공급자 어댑터, 실제 재확인 간격과 최대 횟수는 아직 없다. 같은 활성 배정 요청이 동시에 실행될 때 공급자 조회를 정확히 한 번만 수행한다고 보장하지 않는다. 실제 공급자 확인은 조회 성격과 멱등 계약을 확인한 뒤 연결해야 한다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-recovery-operations
npm run check:backend
```

기존 운영 조회 5건에 배정 5건을 더한 PostgreSQL 18.6 Testcontainers 검사 10건이 통과했다. 배정 검사는 다음을 확인한다.

- 조회 당시 `Ready` 후보의 첫 소유권 획득
- 조회 당시 활성 임대로 보류된 후보의 미배정
- 조회 뒤 수동 검토가 기록된 후보의 잠금 후 재확인
- 같은 오래된 조회 결과를 사용한 동시 배정 중 한 작업자만 획득
- 동일 배정 요청의 기존 시도 재전달

후속 배정 실행 4건·제한 목록 실행 4건과 전체 백엔드 314건도 실패·오류·건너뛰기 없이 통과했다. 구성은 DB 없는 도메인 245건, 개발 API·계약 13건, PostgreSQL 예약·실행·복구·연결·운영 조회·작업 배정·제한 목록 실행/기본 차단 56건이다. 화면·API·Flyway 계약은 변경하지 않았다.
