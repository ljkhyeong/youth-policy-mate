# AI 예약 복구 작업 실행 기록

2026-09-02 구현 기준. [제한 목록 실행](ai-reservation-recovery-work-runner.md)의 한 번의 호출을 식별하고, 같은 실행의 중복 기동을 막으며 후보별 결과 개수를 PostgreSQL에 보존한다. 실제 공급자·주기 스케줄러·고정 운영값은 포함하지 않는다.

## 실행 식별자와 시작

`AiReservationRecoveryWorkRunStore.start`는 다음 값을 한 실행 요청으로 저장한다.

- 호출 측이 만든 실행 ID와 작업자 ID
- 최대 복구 시도 횟수와 재확인 간격
- 오래된 예약 기준 시각과 판단 시각
- 최대 조회 후보 수

같은 실행 ID와 모든 값이 같으면 현재 상태에 따라 `ALREADY_RUNNING` 또는 `REPLAYED`를 반환한다. 실행 ID를 다른 작업자나 조회 조건에 사용하면 `RUN_ID_CONFLICT`로 거절한다. 동시 INSERT는 실행 ID 기본 키로 직렬화되므로 같은 실행 ID에서는 한 호출만 `STARTED`를 받는다.

이 중복 방지는 같은 실행 ID에 한정한다. 서로 다른 실행 ID는 동시에 시작할 수 있고, 같은 예약에 대한 실제 소유권 경쟁은 기존 예약 행 잠금과 예약별 활성 임대 하나 제약이 처리한다. 실행 ID를 모든 작업의 전역 잠금으로 사용하지 않는다.

## 실행 상태와 트랜잭션

Flyway V4의 `ai_reservation_recovery_work_runs`는 다음 상태를 저장한다.

| 상태 | 의미 |
|---|---|
| `RUNNING` | 실행 시작을 저장했고 제한 목록 처리가 끝나지 않음 |
| `COMPLETED` | 제한 목록 처리를 끝내고 후보별 집계를 저장함 |
| `FAILED` | 조회·임대 생성·배정 같은 실행 전체 경계에서 예외가 발생함 |

`AiReservationRecoveryWorkRunCoordinator`는 `RUNNING` 저장을 커밋한 뒤 제한 목록 실행기를 호출하고, 완료 또는 전체 실패를 별도 짧은 트랜잭션으로 기록한다. 외부 AI 상태 확인 동안 실행 기록 행의 잠금을 유지하지 않는다.

후보 하나의 공급자 확인 예외는 제한 목록 실행기의 `RecoveryFailed`이며 실행 전체는 `COMPLETED`로 남는다. 조회나 임대 생성처럼 목록 자체를 계속할 수 없는 예외만 실행 상태를 `FAILED`로 만든다. 예외 메시지는 정책 원문이나 공급자 응답이 섞일 수 있으므로 DB에 저장하지 않는다.

프로세스가 시작 기록 뒤 강제로 종료되면 행은 `RUNNING`으로 남는다. 현재는 이를 자동 만료하거나 다른 실행 ID로 소급 변경하지 않는다. 새 실행 ID의 작업은 시작할 수 있고 예약별 임대가 실제 중복 확인을 다시 막는다. 오래된 `RUNNING`을 명시적으로 종료하는 운영 계약은 후속 작업이다.

## 완료 집계

완료 실행은 조회한 후보 수와 다음 결과 개수를 저장한다.

- 운영 조회에서 보류·중단된 수
- 조회 뒤 잠금 재판정이나 소유권 충돌로 배정하지 못한 수
- 복구 조정자가 실제 결과 적용 경계를 수행한 수
- 배정 뒤 조정자가 시작하지 않은 수
- 후보 단위 외부 확인 예외 수

다섯 결과의 합은 조회 후보 수와 같아야 한다. Java `Summary`와 PostgreSQL CHECK 제약이 같은 조건을 확인하며, 완료 시각은 실행 판단 시각보다 빠를 수 없다.

현재 실행 기록은 후보별 시도 ID 목록을 별도 외래 키로 저장하지 않고 집계만 보존한다. 예약별 상세 이력은 `ai_reservation_recovery_attempts`에서 확인한다. 실제 운영 추적 요구가 확인되면 실행과 시도의 연결을 추가한다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-recovery-work
npm run check:backend
```

새 PostgreSQL 18.6 Testcontainers 검사 6건은 다음을 확인한다.

- 실행 ID·작업자·조회 조건과 후보별 완료 집계 저장
- 완료한 동일 실행의 집계 재전달과 외부 확인 미반복
- 같은 실행 ID의 동시 기동 한 건
- 다른 작업자·조회 조건의 실행 ID 충돌
- 실행 전체 실패 기록과 동일 실행 미반복
- 완료 집계 누락·합계 불일치의 DB 제약

기존 제한 목록 4건을 포함한 전용 10건과 전체 서버 320건이 실패·오류·건너뛰기 없이 통과했고 빌드도 성공했다. 전체 구성은 DB 없는 도메인 245건, 개발 API·계약 13건, PostgreSQL 예약·실행·복구·연결·운영 조회·작업 배정·제한 목록·작업 실행 기록/기본 차단 62건이다. 화면·API 계약은 변경하지 않았고 Flyway V4를 추가했다.

- 공급자 선정 뒤 실제 재확인 간격·최대 시도 횟수·임대 길이 확정
- 스케줄러 실행 주기와 실행 ID·작업자 ID 생성 규칙
- 인증·권한을 갖춘 관리자 조회와 수동 검토 재개 감사 기록
