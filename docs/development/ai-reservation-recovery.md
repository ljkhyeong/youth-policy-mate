# AI 미완료 예약 복구 저장소

2026-09-01 구현 기준. [복구 소유권 설계](../design/ai-reservation-recovery.md)에 따라 미완료 예약의 확인 소유권·임대 만료·시도 이력을 PostgreSQL에 저장한다. 후속 [인공 복구 조정자](policy-ai-recovery-execution.md)가 이 소유권을 상태 변경에 강제한다. 실제 복구 작업자·스케줄러·공급자 상태 조회는 없다.

## 코드와 저장

| 구성 | 역할 |
|---|---|
| Flyway V3 `ai_reservation_recovery_attempts` | 예약별 소유 작업자·임대 기간·시도 순번·시작/완료 단계·확인 결과 저장 |
| `AiReservationRecoveryStore.claim` | 지정한 미완료 예약의 확인 소유권 획득 |
| `AiReservationRecoveryStore.claimNext` | 가장 오래된 획득 가능 예약을 잠금 대기 없이 선택 |
| `AiReservationRecoveryStore.complete` | 소유자·임대 기간을 확인하고 확인 시도 완료 또는 만료 기록 |
| `AiReservationRecoveryStore.history` | 예약별 복구 시도 순번 조회 |

같은 예약의 활성 시도는 하나만 저장한다. 만료 전에는 다른 작업자를 거절하고, 만료 뒤 새 작업자가 소유하면 이전 시도를 `EXPIRED`로 남긴다. 시도 ID와 완료 정보의 같은 재전달은 재생하며 내용이 다르면 충돌로 반환한다.

`COMPLETED`는 작업자가 확인 절차를 마쳤다는 뜻이다. AI 결과·비용·무과금이 확인됐다는 뜻이 아니며 예약 상태를 자동으로 바꾸지 않는다. 시작·완료 당시 예약 단계를 함께 저장해 실제 상태 변화와 확인 결과를 구분한다.

저장소의 일반 완료 메서드는 확인 이력만 기록한다. 복구 조정자 경로의 정산·해제·취소 메서드는 활성 시도 순번과 관찰한 예약 상태를 같은 트랜잭션에서 다시 확인한다. 일반 AI 실행 경로는 복구 임대를 사용하지 않는다. 임대 갱신과 자동 만료 배치는 없으며, 새 소유권 획득이나 늦은 완료가 도착할 때 만료를 기록한다. 후속 [재확인 정책](ai-reservation-recovery-retry-policy.md)은 주어진 일정과 이력으로 다음 확인 가능 여부를 계산하고, [내부 운영 조회](ai-reservation-recovery-operations-query.md)는 오래된 대상·전체 이력·판단을 읽기 전용으로 묶는다. [작업 배정](ai-reservation-recovery-work-assignment.md)은 예약을 잠근 뒤 이 판단을 다시 계산하고 `Ready`일 때만 활성 시도를 만든다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-recovery
npm run check:backend
```

`test:ai-recovery` 7건은 실제 PostgreSQL 18.6 Testcontainers에서 다음 경계를 확인한다.

- 직접 소유권 획득과 같은 요청 재생·시도 ID 충돌
- 활성 임대의 다른 작업자 차단과 만료 뒤 다음 시도
- 두 작업자의 동시 다음 예약 선택 중 한 작업자만 획득
- 시작 단계와 완료 단계·확인 결과 기록
- 다른 작업자의 완료 차단과 늦은 완료 만료 처리
- 종료 예약의 직접·다음 대상 획득 차단
- 잘못된 임대 기간의 DB 제약

저장소 전용 7건, 복구 조정자 10건, 재확인 정책 10건, 내부 운영 조회·작업 배정 10건과 전체 서버 306건이 실패·오류·건너뛰기 없이 통과했고 빌드도 성공했다. 전체 구성은 DB 없는 도메인 245건, 개발 API·계약 13건, PostgreSQL 예약·실행·복구·연결·운영 조회·작업 배정/기본 차단 48건이다.

검사 식별자·작업자·시각·금액은 인공 값이다. 실제 다중 서버, 프로세스 강제 종료, 네트워크·공급자 조회와 임대 갱신은 검사하지 않았다. 화면·API 계약은 변경하지 않았다.

## 남은 작업

- 실제 공급자 조회 결과와 결과 미확인·정산·무과금 전이 연결
- 배정된 시도를 복구 조정자의 트랜잭션 밖 확인 입력으로 연결
- 공급자 선정 뒤 실제 재확인 간격·최대 시도 횟수 확정과 자동 순회·스케줄러 연결
- 내부 운영 조회를 인증·권한이 있는 관리자 API·화면과 수동 재개에 연결
- 후보 상태의 PostgreSQL 저장과 저장 직전 현재 정책 개정 재검사
