# 수집 공고의 AI 자동 추출

`ee34aca` 기준. DB에 반영된 최신 공고를 확인해 기존 [AI 호출·예산 예약·초안 저장](ai-rule-drafts.md) 경로로 한 건씩 처리한다. 수집이 AI 응답을 기다리지 않으며 처리 중에도 정책 조회와 기존 규칙 판정은 유지한다. 실제 AI 키·모델·요금·한도 설정과 생성 품질 검증은 운영 전에 필요하다.

## 대상과 실행

- 공개된 최신 개정을 대상으로 한다. 현재 개정 또는 같은 원문 해시의 추출 요청이 있거나 같은 원문의 규칙 버전이 있으면 새 요청을 만들지 않는다. 관리자 준비 요청·수동 초안도 존중한다.
- 자동 실행을 처음 켰을 때의 미처리 공고에도 한도를 적용한다. 매년 공고가 바뀌면 수집된 새 개정과 해시로 판단하며 이전 연도 자료를 복사하지 않는다.
- `PolicyAiRuleAutoStore`가 최신 정책을 잠그고 추출 요청과 실행 기록을 함께 저장한다. 짧은 PostgreSQL advisory 잠금으로 여러 서버의 선택·일일 한도·간격을 조정하며 외부 호출 전에는 잠금을 해제한다.
- `PolicyAiRuleAutoRunner`는 기존 생성 서비스를 호출한다. 비용 예약, 발송 직전 최신성 확인, 응답 저장, 관리자 초안 생성은 수동 호출과 같다. AI 결과를 자동 적용하지 않는다.
- `PolicyAiRuleScheduler`는 웹 서버에서만 별도 활성화한다. 60초 간격으로 한 번 확인하며 AI 전용 스레드를 사용한다. 수집·알림은 기본 스케줄러를 사용한다. 실제 작업 시작 간격은 DB의 최근 시작 시각으로 제한한다.

## 설정과 명령

[AI 기본 설정](ai-rule-drafts.md#openai-설정과-비용)에 더해 루트 `.env`에서 설정한다.

| 설정 | 범위·동작 |
|---|---|
| `AI_AUTO_ENABLED` | 기본 `false`. 웹 서버에서 정기 자동 처리를 활성화 |
| `AI_AUTO_DAILY_LIMIT` | 1~100건. 기본 0으로 실행 차단. 한국 날짜 기준이며 재개 시도도 한 건으로 계산 |
| `AI_AUTO_INTERVAL_SECONDS` | 60초 이상. 기본 300초. 여러 서버를 합친 최소 작업 시작 간격 |
| `AI_AUTO_MAX_ATTEMPTS` | 요청당 1~5회. 기본 3회. 최초 실행·중단된 시도도 포함 |

설정이 없거나 잘못되면 `CONFIGURATION_REQUIRED`로 보류하며 요청을 만들지 않는다. 월 예산이 이미 설정돼 있으면 한도 변경으로 덮어쓰지 않는다. 잔액이 출력 상한 비용 이하이면 새 예약을 보류한다. 입력 토큰까지 포함한 실제 최대 예약액 검사는 기존 생성 경로에서 다시 수행한다. 기존 예약이나 저장한 응답으로 재개하는 작업에는 새 예산을 요구하지 않는다.

```sh
# 정기 실행을 켜지 않고 자동 선택·처리를 한 번 실행한다. 설정한 한도·간격은 그대로 적용한다.
npm run ai:policy-rules -- --args='auto-run'

# 최근 실행 20건의 정책·개정·요청·시도·결과·예약 상태를 확인한다.
npm run ai:policy-rules -- --args='auto-status'
```

`auto-run`은 AI 기본 설정과 자동 처리 한도가 있어야 실행된다. `auto-status`는 외부 호출 없이 조회한다. 운영 명령에서는 정기 스케줄러를 끄므로 명령 실행 중 다른 공고가 자동으로 처리되지 않는다.

## 재개와 운영 확인

[관리자 AI 추출 화면](admin-ai-runs.md)에서 요청별 마지막 시도·현재 결과·비용 상태를 검색하고 조건 검토로 이동할 수 있다. 실행 기한이 지난 기록과 현재 공고·최신 요청 여부를 구분하며 조회로 작업을 재개하지 않는다.

V28의 `policy_ai_rule_auto_runs`에 요청·시도 번호·시작/만료/완료 시각·상태·결과 코드를 남긴다. 원문·인증키·예외 본문은 작업 로그에 복사하지 않는다.

| 상태 | 의미 |
|---|---|
| `COMPLETED` | 검토용 초안 저장 완료 |
| `RETRY_PENDING` | 호출 전 실패 또는 저장된 응답 처리 실패. 같은 요청으로 제한된 횟수만 재개 |
| `INTERRUPTED` | 작업자 중단. 최신 공고·예약 상태를 다시 확인해 재개 가능 여부 판단 |
| `REVIEW_REQUIRED` | 결과 미확인·잘못된 추출·재시도 소진 등 운영자 확인 필요 |
| `SUPERSEDED` | 원문이나 최신 요청이 바뀌어 자동 재개 대상에서 제외 |

작업 기록의 유효기간은 10분이다. 기간 안에는 다른 자동 작업을 배정하지 않는다. 만료 후에도 발송 기록이 있고 응답이 없으면 같은 요청을 다시 보내지 않는다. 호출 전에 멈췄거나 원 응답이 저장됐으면 기존 요청으로 재개한다. 원문·최신 요청이 달라지거나 재시도 횟수를 소진하면 재개하지 않는다. 만료된 작업자의 늦은 완료 기록은 기존 실행 상태를 덮어쓰지 않으며, 실제 후보·예약 상태는 조회 결과에서 별도로 확인한다.

선택 결과의 `BUSY`·`WAITING`·`DAILY_LIMIT`·`BUDGET_LIMIT`은 새 작업을 시작하지 않았다는 뜻이다. `EMPTY`는 현재 새로 추출하거나 안전하게 재개할 대상이 없다는 뜻이며 모든 공고의 조건 검토 완료를 의미하지 않는다. 예산 부족·공급자 오류 등 호출 전 실패가 최대 횟수에 도달하면 설정을 고친 뒤 현재 공고로 명시적인 새 요청을 준비한다. 실제 청구·무과금 확인에는 [정산 명령](ai-rule-drafts.md#openai-설정과-비용)을 사용한다.

## 검증

검증 명령은 `npm run verify -- test:ai-rule-auto`다. 실제 PostgreSQL과 가짜 HTTP 공급자로 신규/변경 공고·같은 내용 재수집·관리자 작업 제외·동시 배정·일일 한도·제한 재시도·중단 후 재개·결과 미확인 재호출 차단·예산 소진 후 기존 예약/응답 재처리를 확인한다. 스케줄러 기본 비활성화·웹 서버 한정 등록·기존 작업과 스레드 분리도 확인한다.

Java 25.0.3·PostgreSQL 18.6에서 다음 검증을 통과했다. 검증 이후 변경은 문서뿐이다.

| 검증 | 결과·로그 |
|---|---|
| `npm run verify -- test:ai-rule-auto` | 위 자동 처리·복구·스케줄러 검사와 기존 생성 경로 통과. `.local/verification/1789175310104-87761747.log` |
| `npm run verify -- check:backend` | 전체 서버·DB·API 계약 검사 통과. `.local/verification/1789175362712-74f1cda6.log` |
| 운영 명령·로컬 서버 | `auto-status` 조회·V28 적용·서버 상태 조회 200 확인. `/tmp/youth-ai-auto-command.log`, `/tmp/youth-ai-auto-runtime.log` |

로컬 정책 40건·적용 규칙 11건·AI 요청/호출/자동 실행 0건을 확인했다. 로컬 자동 실행은 비활성화했으며 실제 AI 과금·정기 수집은 실행하지 않았다. 화면·HTTP 계약·생성 타입은 변경하지 않아 웹 검증은 이전 `e05fa3d` 결과를 유지했다. 실제 제공자의 생성 품질·청구, 관리자 로그인, 원격 CI와 배포는 이번 검증 범위가 아니다.
