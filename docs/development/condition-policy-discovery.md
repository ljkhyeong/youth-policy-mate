정책별 추가 질문과 같은 연령 비교 함수를 사용한다. 기준의 출처는 [응시료](exam-fee-questions.md), [K-패스](kpass-questions.md), [청년정책네트워크](seoul-youth-network-questions.md), [이사비](moving-fee-questions.md), [청약통장](youth-housing-savings-questions.md), [저축계좌](youth-tomorrow-savings-questions.md), [햇살론유스](haetsalron-youth-questions.md), [청년 미래이음 대출](miso-youth-future-questions.md), [미래 청년 일자리](future-youth-jobs-questions.md), [K-뉴딜 아카데미](k-newdeal-academy-questions.md), [국민취업지원제도](employment-support-questions.md), [AI학업장려 학자금대출](ai-study-loan-questions.md), [청년도약 인재양성 부트캠프](youth-leap-bootcamp-questions.md)에 있다. 검토된 원문 해시가 일치하고 각 규칙의 적용 기간 안에 있을 때만 적용한다. 검토되지 않은 정책·바뀐 원문·적용 기간 밖에서는 연령을 미확인으로 남긴다. 국가근로장학금·보증료 지원은 기본 조건만으로 비교하지 않는다.

청약통장은 기존 상세 질문의 연령 규칙을 재사용한다. 서울 날짜의 오늘 가입을 가정해 만 19~34세를 충족, 만 19세 미만을 불충족으로 비교한다. 만 35세 이상은 병역기간을 추정하지 않고 추가 확인으로 남긴다. 결과에 만 나이·서울 기준일과 실제 가입일이 다르면 재확인이 필요하다는 안내를 표시한다. 상세 질문의 연령 답변을 자동으로 채우지 않는다. 미확인 사유는 각 정책의 설명을 사용해 병역기간 차감과 연령 연장을 구분한다.

저축계좌는 상세 질문과 같은 출생일 비교 함수를 사용한다. 2026년 5월 모집 기준으로 양 끝 날짜를 포함하며 오늘의 만 나이를 대입하지 않는다. 결과와 정렬에 같은 비교값을 사용하고 모집 마감·수집 안내와의 소득 및 출생일 기준 차이를 함께 표시한다. 다른 조건은 추가 확인으로 남기고 상세 질문의 답변을 자동으로 채우지 않는다.

햇살론유스는 오늘 보증신청을 가정한 서울 날짜·만 나이를 표시한다. 만 19~34세만 연령 충족이며 실제 신청일 재확인을 안내한다. 군입대 예정자의 추가 거치기간을 연령 상한 연장으로 적용하지 않는다. 이용 대상·소득·생애 보증한도와 최종 심사는 별도 질문·확인 항목으로 남긴다.

연령 외 조건은 현재 입력만으로 확정하지 않는다. 서울 자치구 입력은 과거 모집 신청 당시의 주소·전입 이력을 증명하지 않으며, 주된 취업상태는 다른 취업·학력·소득 조건을 대신하지 않는다. 모든 항목의 전체 자격은 `NEEDS_REVIEW`다. 마감된 공고는 결과와 질문에 해당 회차·마감을 표시한다.

## 검색·정렬과 개인정보

- `POST /api/v1/policies/checks?page=1&q=&sort=OPEN_FIRST`에 기본 조건을 JSON 본문으로 보낸다. 모든 항목은 선택이며 빈 객체(`{}`)도 받는다. 생년월일이 없으면 연령 규칙을 적용하지 않고 각 항목을 `미입력`·추가 확인으로 응답한다. 생년월일·자치구·취업상태를 URL이나 저장소에 넣지 않으며 응답은 `no-store`다.
- 정렬은 세 가지다. 화면은 생년월일을 반영하기 전 `OPEN_FIRST`, 반영한 뒤 `AGE_MATCH`를 기본으로 보낸다. `sort`를 생략한 요청은 이전처럼 `AGE_MATCH`다.
  - `OPEN_FIRST`(접수 중 우선): 공개 목록과 같은 `AVAILABILITY_ORDER`다. 접수 중인 정책을 마감 임박순으로 먼저 두고 접수 전·상시·기간 미확인·마감 순으로 잇는다.
  - `AGE_MATCH`(연령 조건 충족 우선): 연령 `MET` → `UNKNOWN` → `NOT_MET` 순이며 같은 그룹은 `OPEN_FIRST` 순서다. 생년월일이 없으면 모두 같은 그룹이라 `OPEN_FIRST`와 같다.
  - `RECENT`(최근 수집순): 수집 시각·정책번호만 사용한다.
  - 마지막 동률은 수집 시각 내림차순·정책번호순이다. 미확인·불충족 정책을 제외하지 않는다.
- `q`는 공개 목록과 같은 단어 검색(최대 80자)이다. 공백으로 나눈 단어가 공백을 뺀 정책명·설명·운영 기관에 모두 들어 있어야 하며 `%`와 `_`는 와일드카드가 아니다. 전체 결과에 검색·정렬을 적용한 후 20건씩 조회한다. [단어 검색](policy-region-filter.md#단어-검색)
- `PolicyRuleDefinition`에서 만든 `PolicyAgeComparison`을 SQL 정렬과 응답 표시에 함께 사용한다. 정책별 추가 조회 없이 규칙 조회 한 번과 건수·페이지 조회 두 번으로 처리한다. 현재 [공고별 조건 데이터](policy-rule-data.md)로 13개 정책의 연령을 비교하고 생년월일 답변을 재사용한다.
- 응답에 항목별 `outcome`, 정책 개정, 연령 규칙 `ruleVersion`, `evaluatedAt`을 제공한다. 비교 기준이 없으면 규칙 버전은 빈 문자열이다.
- 검색·정렬 변경은 1페이지로 돌아간다. 이전 요청을 취소하고 늦은 응답은 무시한다. 실패해도 입력과 검색 조건을 유지하고 재시도할 수 있다.
- 추가 질문으로 이동해도 기본 조건을 자동 답변으로 넣지 않는다.

## 검증

미래 청년 일자리 추가 시 출생일 경계·군복무 연장 미확인·공고일·연도 만료·원문 변경을 확인했다. PostgreSQL 정책 API·계약 일치·실제 기본 조건 검색도 확인했다. 최신 명령·로그는 [미래 청년 일자리 검증](future-youth-jobs-questions.md#연결과-검증)에 있다. 기존 정책의 코드가 같은 검증 결과는 재사용한다.

실제 로컬 정책으로 기본 조건 검색, 연령·기준일·전체 자격 추가 확인 표시, 상세 질문 이동을 확인했다. 조건 입력을 URL에 넣지 않으며 질문을 자동으로 채우지 않는다. PC·모바일 질문 결과와 입력 삭제도 확인했다. 이전 정책의 날짜·예외 검증은 각 정책 문서와 Git 이력에서 확인한다.

### 2026-10-30 접수 중 우선 정렬

## 로컬 실행 상태

현재 실행 명령·JDK 경로·로그는 [미래 청년 일자리 검증](future-youth-jobs-questions.md#연결과-검증)에 있다. 정기 수집·알림·이메일 발송은 비활성화이며 다음 작업에서 프로세스 상태를 확인한다.
