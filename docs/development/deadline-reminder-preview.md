# 마감·알림 후보 미리보기

2026-08-31 구현·검증 기준. [PRD 7절](../PRD/0001_product-baseline/spec.md#7-관심-정책일정알림)과 [후보 날짜 설계](../design/deadline-reminder-candidates.md)의 의미를 표시한다. 제품 규칙이나 서버 계산은 변경하지 않았다.

## 현재 구현 범위

- `frontend/src/features/reminders/deadline-reminder-view.ts`: 신청기간·모집 상태·후보 결과·기준 정보의 화면 모델. 확정 REST DTO나 생성 API 타입이 아니다.
- `frontend/src/features/reminders/deadline-reminder.tsx`: 전달받은 날짜와 상태를 표시하는 읽기 전용 컴포넌트.
- `frontend/src/app/dev/reminders/`: 일곱 가지 고정 인공 자료와 예시 선택 화면.
- `frontend/src/features/reminders/deadline-reminder.test.tsx`: 날짜·상태·근거 표시 테스트 8건.

루트에서 `npm run dev:web`을 실행한 뒤 [개발 미리보기](http://127.0.0.1:3000/dev/reminders)를 연다. 인증키·백엔드·DB가 필요하지 않다. 운영 빌드에서는 HTTP 404를 반환하며 검색 노출도 차단한다.

실제 정책·서버 응답이 아닌 화면 점검용 자료다. `/conditions`나 앞선 질문의 답변을 읽지 않으며 API 호출·브라우저 저장·분석 전송을 추가하지 않았다. 정책 저장·알림 예약·발송 버튼도 없다. 서버의 [후보 계산 모델](deadline-reminder-candidates.md)과 연결하지 않았다.

## 표시 기준

| 대상 | 화면 동작 |
|---|---|
| 날짜형 신청기간 | 시작일·종료일을 날짜 문자열 그대로 표시한다. 임의의 자정·23:59 마감으로 바꾸지 않는다. |
| 시각형 신청기간 | 원래 시작·마감 시각과 각 시간대를 표시하고, 같은 마감 순간의 서울 시각도 함께 표시한다. 마감 시각부터 종료된다는 의미를 안내한다. |
| 서울 마감 날짜 | 결과에 전달된 `deadlineOnSeoul`을 표시한다. 화면에서 마감 시각을 날짜로 변환해 후보 계산에 쓰지 않는다. |
| 상시·소진 시 종료·기간 미확인 | 확인된 마감 날짜가 없음을 표시한다. 기간 미확인의 구체적인 이유를 보존한다. |
| 모집 마감 | 확인된 원래 기간이 있으면 유지한다. 원문에 마감만 기록된 경우 날짜·시각을 채우지 않는다. |
| 모집 상태 | 후보 결과와 분리하고 계산 시점의 모집 안내임을 표시한다. 개인 자격을 뜻하지 않는다. |
| 오늘 후보 | 전달받은 `TODAY_REQUIRES_SEND_TIME_CHECK`를 발송 시각 확인 필요로 표시한다. 즉시 발송·놓친 알림으로 단정하지 않는다. |
| 미래 후보 | `FUTURE_DATE`는 미래 후보·예약 미확정으로 표시한다. |
| 빈 후보 | 마감일 미확인·모집 마감·남은 후보 날짜 없음의 결과와 설명을 유지한다. 빈 목록을 기존 예약 취소로 안내하지 않는다. |
| 근거와 기준 정보 | 정책 식별자·개정·자료 위치·발췌문·계산 시각을 접어 제공한다. 계산 시각과 수집 시각은 구분한다. |

날짜는 `YYYY-MM-DD`, 정확한 시각은 오프셋이 포함된 ISO 문자열과 시간대를 받는다. `Date`·`Intl.DateTimeFormat`은 정확한 시각의 표시 형식에만 사용한다. 날짜 차감, 오늘 여부, 모집 상태와 후보 없음 사유를 브라우저에서 계산하지 않는다. 후보 순서도 전달받은 순서를 유지한다.

예시의 ‘오늘’은 고정 계산 기준일인 2026-08-31이다. 현재 날짜가 달라져도 이 값이나 후보 상태를 바꾸지 않는다. 실서비스 결과의 갱신·최신 개정 선택·직렬화 검증은 서버 연결 때 구현해야 한다.

## 인공 예시와 조작

1. 날짜형·오늘 후보: 9월 7일 마감, 8월 31일 D-7과 미래 D-3·D-1을 표시한다.
2. 시각형·시간대: UTC 9월 6일 18:00 마감을 서울 9월 7일 03:00과 함께 표시한다. 후보의 기준 마감 날짜는 9월 7일이다.
3. 마감일 미확인: 본문과 신청기간 항목의 날짜 충돌을 보존하고 후보를 표시하지 않는다.
4. 상시 모집: 고정 마감 날짜 없음과 실제 접수 여부 확인을 안내한다.
5. 소진 시 종료: 소진 여부·소진 날짜를 추정하지 않는다.
6. 모집 마감: 지난 종료일은 보존하고 모집 마감으로 후보가 없다고 표시한다.
7. 후보 날짜 모두 지남: 모집은 날짜 기준 접수 기간이지만 D-7·D-3·D-1이 모두 지났다. 지난 후보를 오늘로 옮기지 않는다.

예시 선택에는 버튼과 `aria-pressed`, 변경 안내에는 `role="status"`를 사용한다. 기본 `details`·`summary`로 근거를 펼치며 예시를 바꾸면 다시 접힌다. 새로고침하면 첫 예시와 빈 변경 안내로 돌아간다.

## 검증 결과와 한계

```sh
npm run test:web
npm run check:web
npm run build:web
```

- 웹 32건: 기존 24건과 이번 표시 테스트 8건이 통과했다. 날짜형 비변환·시간대 표시·고정 기준일 유지·후보 없음 사유·날짜 없는 마감·발췌문 누락·근거 HTML 비실행을 확인했다. 서버의 날짜 경계 테스트를 화면에 중복 구현하지 않았다.
- 린트·타입 검사·프로덕션 빌드가 통과했다. 타입 생성과 빌드는 차례로 실행했다. 빌드는 로컬 포트 제한을 피하도록 실행 권한을 확장했으며 캐시 삭제나 환경 우회용 코드 변경은 하지 않았다.
- 개발 `/dev/reminders`는 200, 임시 운영 서버의 같은 경로는 404, 운영 `/conditions`는 200이었다. 확인용 3100 서버는 종료하고 기존 개발 서버는 유지했다.
- 브라우저에서 일곱 예시 전환, 상태 변경 안내, 시각형 마감의 UTC·서울 표시, 근거 펼치기와 예시 변경 시 접힘을 확인했다. 새로고침 후 화면 스냅샷에서 첫 예시·빈 변경 안내·접힌 근거를 확인했다. 조회한 오류·경고 로그는 없었다.
- 1280×900·390×844 뷰포트에서 표시를 확인했다. 모바일의 후보 날짜·시간대 영역에 가로 넘침이 없었다. 실제 휴대전화나 저장소 E2E 자동 테스트로 검사한 것은 아니다.
- 근거 클릭 시 포커스와 펼침, 포커스 테두리를 확인했다. 도구의 Enter·Tab 입력은 펼침 상태·포커스를 바꾸지 않아 키보드 전용 전체 흐름은 미확인이다. 새로고침 후 일부 요소 조회도 시간 초과되어 초기 상태는 화면 스냅샷으로 확인했다. 도구에 맞춘 별도 이벤트 처리는 추가하지 않았다.
- 서버·PostgreSQL 통합 검사는 다시 실행하지 않았다. 실제 API 결과 변환·원문 정확도·저장·예약·발송·취소를 검증한 것은 아니다.

## 다음 연결

인증키 없이 서버 계산까지 확인하려면 개발 전용 인공 자료 조회 API의 계약과 운영 모드 차단부터 정한다. 서버가 계산한 모집 상태·후보 날짜·원래 기간·개정·근거·계산 기준을 생성 타입과 화면 어댑터로 연결한다. 실제 정책 API 성공 응답, 회원 저장·동의, 예약·발송 연결은 별도다. 발송 시각과 재시도 만료 정책도 아직 정하지 않았다.
