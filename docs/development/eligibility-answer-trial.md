# 인공 답변 변경과 서버 재판정

2026-08-31 구현·검증 기준. [고정 자격 결과 조회](eligibility-preview-api.md)에 이어, 정해진 취업 답변·소득 구간을 바꾸고 기존 서버 비교기로 계산하는 개발 화면을 추가했다. 실제 개인정보·정책 추천·로그인·저장은 없다. PRD의 제품 범위와 기존 판정 규칙은 바꾸지 않았다. 전송·실패 경계는 [ADR-0002](../ADR/0002_서버_DTO_기반_API_계약_생성.md)를 따른다.

## 실행과 범위

저장소 루트의 서로 다른 터미널에서 실행한다.

```sh
npm run dev:web
```

```sh
npm run dev:preview-api
```

[인공 답변 재판정 화면](http://127.0.0.1:3000/dev/eligibility/interactive)을 연다. 기존 8081 서버가 실행 중이면 코드 변경 후 재시작한다. 인증키·DB·Docker는 필요하지 않으며 Java 도구체인과 의존성은 준비되어 있어야 한다. 운영에서 `preview` 프로필을 켜면 안 된다.

- 생년월일·서울 마포구 거주·연령 규칙·계산 시점은 인공 값으로 고정한다.
- 취업은 선택 안 함·해당함·해당하지 않음·모름 중 고른다.
- 소득은 선택 안 함·모름·0원·정해진 네 구간 중 고른다. 자유 입력은 없다.
- ‘처음 질문’과 ‘개정·기준 변경 질문’은 정책 개정·취업 정의·기준일·소득 대상 기간이 다른 인공 자료다.
- 기존 `/conditions`, `/dev/employment`, `/dev/income`의 입력은 읽거나 전송하지 않는다. 세 화면의 기존 동작도 유지한다.

## API와 계산

| 요청 | 역할 | 응답 |
|---|---|---|
| `GET /api/dev/eligibility-trial` | 인공 질문 두 버전·근거·선택지 조회 | `SYNTHETIC`, 질문·선택지 목록 |
| `POST /api/dev/eligibility-trial` | 선택한 인공 답변 계산 | `SYNTHETIC`, 질문 버전, 자격 결과·별도 모집 상태 |

정상 응답과 입력 오류는 JSON·`Cache-Control: no-store`다. POST에는 다음 다섯 필수 enum 필드가 있다. 누락·null·지원하지 않는 값은 `400 INVALID_SYNTHETIC_ANSWER`이며 입력 원문을 응답하지 않는다.

| 필드 | 의미 |
|---|---|
| `questionSet` | 현재 계산할 질문 버전: `INITIAL` / `REVISED` |
| `employmentQuestionSet` | 취업 답변 당시의 질문 버전 |
| `employmentChoice` | 취업 선택 코드 |
| `incomeQuestionSet` | 소득 답변 당시의 질문 버전 |
| `incomeChoice` | 소득 선택 코드 |

`EligibilityTrialController`는 `preview`에서만 등록된다. `SyntheticEligibilityPolicy`는 코드에 대응하는 인공 사실·구간을 조립해 기존 연령·거주·취업·소득 비교기와 `EligibilityDecision`으로 계산한다. 질문 문구·선택지·결과는 서버 DTO → OpenAPI → 생성 TypeScript를 사용한다. 화면에서 전체 판정을 합치지 않는다.

답변은 **작성 당시 질문의** 정책·개정·정의·기준일·소득 기간으로 복원한다. 현재 질문과 다르면 기존 비교기가 사용자 정보 추가 확인으로 남긴다. `UNANSWERED`는 답변 없음, `UNKNOWN`은 명시적인 모름이며 0원·비해당으로 바꾸지 않는다. 금액의 포함 경계·구간 겹침은 기존 소득 비교기가 판단한다. 모집 상태는 자격과 별도로 계산한다.

`INITIAL`/`REVISED`는 이 개발 예시만의 식별자다. 실제 정책·원문 개정·질문 저장소와 사용자 답변 저장 계약은 아직 구현하지 않았다.

## 화면 상태와 실패 처리

코드는 `frontend/src/app/dev/eligibility/interactive/`에 있다.

- 서버 컴포넌트가 질문을 조회하고 Server Action이 다섯 코드 필드만 전달한다. 고정 루프백 주소·5초 제한·리다이렉트 거절·캐시 미사용을 적용한다.
- 질문 조회 실패는 다시 불러오기 안내로 표시한다. 계산 실패는 선택 답변을 남겨 재시도하게 하되 이전 결과를 보여주지 않는다.
- 답변 변경·초기화·계산 시작은 이전 결과를 지운다. 현재 대기 중인 요청 번호에 맞는 응답만 반영한다. 오래된 요청을 취소하는 기능은 아니다.
- 질문 내용이 바뀌면 폼을 새로 만들며 이전 버전으로 돌아가도 답변·결과를 복원하지 않는다. 새로고침해도 초기화된다.
- ‘추가 확인 필요’는 서버의 판정이다. 전송 오류를 이 상태로 표시하지 않는다.
- 운영 레이아웃은 스트리밍 전에 404를 반환한다. 조회 함수와 Server Action도 개발 모드가 아니면 백엔드를 호출하지 않는다.

## 검증

```sh
npm run generate:api
./backend/gradlew -p backend build --no-daemon
npm run test:web
npm run check:api-types
npm run check:web
npm run build:web
```

- 서버 180건 통과: 기존 도메인 165건, 개발 API·계약 13건, 실제 PostgreSQL·기본 차단 2건. 실패·건너뛰기 없음.
- 새 API 5건: 질문·선택지, 구간을 좁힌 재판정, 이전 질문 답변의 재사용 차단, 미선택/모름 구분, 잘못된 요청·다른 메서드 차단. 기존 비교 규칙의 입력 행렬을 중복하지 않았다.
- 웹 53건 통과: 기존 45건과 전송·화면 상태 8건. 답변 변경 후 늦은 성공/실패 무시, 이전 요청 무시, 실패 후 재시도, 다섯 필드만 전송, 운영 호출 차단과 초기 표시를 검사했다.
- OpenAPI 계약·생성 타입 최신 여부, 린트·타입 검사·웹/서버 빌드 통과. 웹 타입 검사와 빌드는 차례로 실행했다.
- 실제 운영 서버의 재판정 경로는 404, `/conditions`는 200이었다. 확인용 3100 서버는 종료했다.

- 브라우저에서 질문 조회 오류 → 다시 불러오기, 취업 비해당·소득 일부 겹침 → 구간을 좁힌 뒤 충족, 취업 해당 → 불충족을 확인했다. 답변 변경 직후에는 이전 결과가 사라졌다.
- 질문 버전 전환·복귀, 답변과 결과 지우기, 새로고침 시 초기화를 확인했다. 개정 질문의 취업 기준일·소득 기간도 바뀌었다.
- 계산 중계 서버를 종료한 뒤 다시 계산하자 오류 안내·선택 답변 유지·이전 결과 제거를 확인했다. API를 재기동한 뒤 같은 답변으로 재시도해 복구했다.
- 1280×900·390×844에서 질문·선택지·결과·근거 펼치기를 확인했다. 모바일의 긴 소득 설명·구간·근거에 가로 넘침이 없었고 조회한 브라우저 오류·경고 로그는 비어 있었다.
- 근거 클릭·포커스는 확인했지만 도구의 Enter 입력으로 펼침 상태가 바뀌지 않았다. 키보드 전용 전체 흐름은 미확인이다. 늦은 응답 무시는 리듀서 테스트로 확인했으며 브라우저에서 네트워크 순서를 조작하지 않았다.

실제 정책 정확도·개인정보 처리·소셜 인증·원천 수집·저장·예약·발송·운영 배포 검증이 아니다. 로컬 Gradle·Docker·빌드·서버 실행에 권한 확장을 사용했다. 기존 JVM 클래스 공유 경고는 유지했다.
