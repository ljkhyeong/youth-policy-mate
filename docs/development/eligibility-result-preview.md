# 자격 결과·근거 미리보기

2026-08-30 구현·검증 기준. [PRD의 자격 안내](../PRD/0001_product-baseline/spec.md#5-자격-안내와-추천-근거)와 [서버 결과 집계](eligibility-decision.md)의 의미를 화면에 표시한다. 제품 규칙이나 서버의 계산 순서는 변경하지 않았다.

## 현재 구현 범위

- `frontend/src/features/eligibility/eligibility-result-view.ts`: 결과 표시용 TypeScript 모델. 확정 REST DTO·생성 API 타입이 아니다.
- `frontend/src/features/eligibility/eligibility-result.tsx`: 전체 자격 상태·모집 안내·정책 검토 이슈·항목별 결과·기준 정보를 받는 읽기 전용 컴포넌트.
- `frontend/src/app/dev/eligibility/`: 네 가지 고정 인공 자료와 예시 선택 화면. 개발 모드에서만 제공한다.
- `frontend/src/features/eligibility/eligibility-result.test.tsx`: 표시 의미와 근거 문자열 처리를 확인하는 테스트 7건.

루트에서 `npm run dev:web`을 실행한 뒤 [개발 미리보기](http://127.0.0.1:3000/dev/eligibility)를 연다. 인증키·백엔드·DB가 필요하지 않다. 운영 빌드에서는 HTTP 404를 반환하며 검색 노출도 차단한다.

정책·입력 값·근거는 모두 인공 자료다. `/conditions`, 취업 질문, 소득 질문의 입력을 읽지 않으며 서버 호출·브라우저 저장·분석 전송을 추가하지 않았다. 실제 정책 목록·추천·판정 API·결과 변환 어댑터는 아직 없다. 예시의 상태는 자료에 미리 지정한 값이며 화면에서 자격이나 모집 상태를 계산하지 않는다.

## 표시 기준

| 대상 | 화면 동작 |
|---|---|
| 전체 자격 상태 | 전달받은 `ELIGIBLE`·`INELIGIBLE`·`NEEDS_REVIEW`를 그대로 표시한다. 항목 수나 결과를 집계하지 않는다. |
| 모집 상태 | 자격 안내 옆의 별도 영역에 표시한다. 신청 가능 안내여도 모집 종료일 수 있음을 보여준다. |
| 정책 검토 미완료 | 미확인 조건·예외의 설명과 근거를 항목 목록 위에 표시한다. |
| 개별 항목 | 충족·불충족·추가 확인 필요를 문구와 색상으로 구분한다. 적용 조건·비교 값·기준일·이유를 표시한다. |
| 사용자 정보 부족 | `MISSING_USER_INPUT`은 사용자 정보 추가 확인으로 표시한다. 답변 누락과 소득 구간의 일부 겹침은 설명으로 구분한다. |
| 정책 조건 미해석 | `UNRESOLVED_POLICY`는 정책 조건 해석 필요로 표시한다. 사용자 답변만으로 확정할 수 있다고 안내하지 않는다. |
| 값의 부재 | 비교 값·기준일·발췌문의 `null`은 해당 기록이 없다고 표시한다. 0원·오늘 날짜·미입력으로 임의 변환하지 않는다. |
| 근거 | 자료 식별자·위치·기록된 문구를 기본적으로 접어 표시한다. HTML을 실행하거나 식별자를 URL로 바꾸지 않는다. |
| 기준 정보 | 정책 식별자·개정·규칙 버전과 판정 시각을 표시한다. 판정 시각은 서울 시간으로 표시한다. |

화면 모델의 조건 기준일은 날짜 문자열 `YYYY-MM-DD`, 판정 시각은 시간대가 포함된 ISO 시각을 받는다. 기준일은 날짜 그대로 보존하고 시각으로 바꾸지 않는다. 실제 API를 연결할 때 직렬화·누락·널 계약과 입력 검증 책임을 따로 정해야 한다.

취업 제한 없음처럼 사용자 값을 비교하지 않은 항목도 비교 값이 없을 수 있다. 따라서 단순한 `null`을 미입력으로 표시하지 않는다. 판정 시각은 각 조건의 적용 기준일과 다르며, 이를 한 날짜로 합치지 않는다.

## 인공 예시

1. 전체 충족·모집 종료: 전체 결과는 신청 가능이지만 현재 접수 중이라는 뜻이 아님을 표시한다.
2. 사용자 정보 부족: 본인의 2025년 소득 구간이 예시 경계에 걸쳐 추가 확인이 필요하다.
3. 정책 조건 미해석: 연령 항목 불충족이 있어도 미확인 예외와 취업 조건 미해석 때문에 전체 결과가 보류된 자료다.
4. 명확한 조건 불충족: 정책 검토가 완료되어 전체 결과는 불충족이지만 소득 답변 누락은 별도로 표시한다.

예시 선택에는 버튼과 `aria-pressed`를 사용하고 변경된 예시·전체 상태를 알림 영역으로 안내한다. 근거는 기본 `details`·`summary`로 펼친다. 예시를 바꾸면 이전 근거 펼침 상태를 초기화하고 새로고침하면 첫 번째 예시로 돌아간다. 실제 답변 수정이나 재판정 버튼은 제공하지 않는다.

## 검증 결과와 한계

```sh
npm run test:web
npm run check:web
npm run build:web
```

- 웹 24건: 기존 17건과 결과 표시 7건이 통과했다. 전체 상태 유지, 두 미확인 원인 구분, 정책 검토 이슈, 빈 목록, 비교 값·날짜·개정 보존과 근거 HTML 비실행을 확인했다.
- 린트·타입 검사·프로덕션 빌드가 통과했다. 타입 생성과 빌드는 차례로 실행했다. 빌드는 기존 샌드박스의 로컬 포트 제한을 피하도록 실행 권한을 확장했으며 환경 우회를 위한 소스 수정이나 캐시 삭제는 하지 않았다.
- 개발 `/dev/eligibility`는 200, 임시 운영 서버의 같은 경로는 404, 운영 `/conditions`는 200이었다. 확인용 3100 서버는 작업 후 종료했다.
- 브라우저에서 네 예시 전환, 상태 변경 알림, 근거 펼치기, 발췌문 없음 표시, 예시 변경 시 접힘과 새로고침 초기화를 확인했다. 조회한 오류·경고 로그는 없었다.
- 1280×900·390×844 뷰포트에서 배치를 확인했다. 모바일의 열린 예외·소득 근거에도 가로 넘침이 없었다. 실제 휴대전화 검증이나 저장소에 추가한 E2E 자동 테스트는 아니다.
- 근거 클릭 시 포커스와 펼침 상태는 확인했다. 브라우저 도구의 Enter 입력으로는 접힘 상태가 바뀌지 않아 키보드 전용 전체 흐름은 미확인이다. 도구에 맞춘 별도 키보드 처리 코드는 추가하지 않았다.
- 서버·PostgreSQL 통합 검사는 다시 실행하지 않았다. 실제 정책 판정 정확도·서버 결과 직렬화·API 오류 복구 검증은 아니다.

## 다음 연결 시 확인할 사항

실제 결과 API가 생기면 서버가 계산한 전체 상태·항목·근거와 정책 검토 이슈의 의미를 보존하도록 화면 어댑터를 작성한다. 사용자 결과를 공용 캐시나 로그에 넣지 않고 정책 개정·규칙 버전·입력이 달라졌을 때 이전 결과를 그대로 사용하지 않는다. [모집 기간의 별도 서버 계산](recruitment-period.md)은 추가했지만 이 미리보기와 연결하지 않았다. API 직렬화와 생성 타입·실제 정책 연결은 후속 작업이다.
