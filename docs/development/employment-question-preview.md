# 추가 확인 질문 미리보기

2026-08-30 구현 기준. 제품 요구는 [PRD 4~5절](../PRD/0001_product-baseline/spec.md#4-조건-입력과-로그인), 질문의 의미는 [취업 조건 설계](../design/employment-condition.md)를 따른다.

## 실행과 현재 범위

저장소 루트에서 `npm run dev:web`을 실행하고 <http://127.0.0.1:3000/dev/employment>을 연다. 인증키·백엔드·DB가 필요하지 않다.

이 경로는 **개발 전용 인공 예시**다. 실제 정책명·지원 금액·신청 링크·추천 결과를 만들지 않았다. 정의·기준일·근거 예문은 화면 점검용이며 원천 API 성공 응답이나 실제 정책 원문이 아니다. 주 메뉴에는 링크를 추가하지 않았다.

- 질문에는 확인할 사실, 기준일, 추가 질문이 필요한 이유와 근거 표시 예시를 함께 보여준다.
- ‘해당함·해당하지 않음·모름’ 중 하나를 명시적으로 선택한다. 처음에는 아무 항목도 선택하지 않는다.
- 미선택 상태에서 확인하면 안내를 표시하고 첫 라디오로 포커스를 옮긴다. ‘모름’도 유효한 답변이며 비해당으로 바꾸지 않는다.
- 확인 화면에서 선택한 답변과 질문 기준일·예시 개정을 보여준다. 수정할 때 선택값을 유지하고, 지우면 미선택 상태로 돌아간다.
- ‘기준일 변경 예시’는 날짜와 개정을 바꿔 선택·확인 상태를 초기화한다. 처음 질문으로 돌아와도 이전 답변을 복원하지 않는다.
- 확인 화면은 답변만 표시한다. 충족·불충족·전체 자격 상태를 계산하지 않으며 공식 자격 인증으로 안내하지 않는다.

## 코드와 개인정보 경계

코드는 `frontend/src/app/dev/employment/`에 있다.

| 파일 | 책임 |
|---|---|
| `page.tsx` | 개발 모드 접근 허용, 메타데이터와 인공 예시 안내 |
| `employment-question-preview.tsx` | 예시 선택, 질문·근거 표시, 답변 확인·수정·초기화 |
| `employment-question-preview.test.tsx` | 최초 미선택 마크업, 표시 의미와 모름 처리 검증 |

예시의 정책 ID·개정·조건 ID·정의·기준일을 포함하는 객체를 React `key`로 사용한다. 예시가 바뀌면 답변을 가진 컴포넌트를 새로 만든다. 이는 개발 화면의 입력 초기화이며 [서버 비교기](employment-condition.md)의 답변 일치 검사나 최종 판정을 프런트엔드에 복제한 것이 아니다.

답변은 컴포넌트 상태에만 두고 서버 전송·브라우저 저장소·로그·분석 이벤트를 추가하지 않았다. 폼 제출 없이 라디오와 버튼을 사용한다. 새로고침하면 초기화되고 `/conditions`의 입력값을 가져오거나 바꾸지 않는다. 현재의 표시용 타입은 REST 계약이나 서버 생성 타입이 아니다.

`NODE_ENV`가 `development`가 아니면 서버 페이지에서 `notFound()`로 종료한다. `noindex, nofollow`도 유지하되 접근 차단을 메타데이터에 맡기지 않는다. 운영 빌드에 미리보기 UI가 표시되지 않는지 HTTP 응답으로 확인했다.

## 검증 결과와 한계

macOS arm64·Node.js 25.4.0·npm 11.7.0에서 확인했다.

| 검사 | 결과 |
|---|---|
| `npm run test:web` | 기존 8건 + 질문 표시 4건, 총 12건 통과 |
| `npm run check:web` | 린트 경고 없음, 경로 타입 생성·TypeScript 검사 통과 |
| `npm run build:web` | 프로덕션 빌드 통과 |
| HTTP 응답 | 개발 `/dev/employment` 200, 운영 `/dev/employment`·`/dev/states` 404, 운영 `/conditions` 200 |
| 브라우저 동작 | 미응답 오류·첫 라디오 포커스, 세 답변의 확인, 수정 시 값 유지, 답변 삭제, 개정 변경·되돌리기와 새로고침 시 초기화 확인 |
| 반응형 | 데스크톱 1280px·모바일 390px의 질문·근거·확인 화면 점검, 모바일 가로 넘침 없음 |

확인 시 제목으로, 수정·삭제 시 첫 라디오로 포커스를 옮긴다. 기본 라디오·fieldset·legend와 기존 포커스 스타일을 사용한다. 브라우저 도구의 방향키 입력이 선택 이동으로 반영되지 않아 키보드 전용 전체 흐름은 확인하지 못했다. 실제 휴대전화·스크린리더 검증도 별도다. 브라우저 검증은 수동 도구 실행이며 저장소에 추가한 E2E 자동 테스트가 아니다.

빌드 초기에 Turbopack의 로컬 포트 권한 오류가 발생했다. 권한을 허용한 재실행에서도 반복되어 프로젝트의 `.next/cache/turbopack`을 임시 폴더에 보관하고 새 캐시로 빌드한 뒤 통과했다. 소스·의존성·전역 설정은 이 문제 때문에 바꾸지 않았다.

`check:web`과 `build:web`은 `.next/types`를 함께 갱신하므로 동시에 실행하지 않는다. 최종 확인 중 동시 실행에서 생성 타입 파일 누락 오류가 발생했고, 빌드 완료 후 `check:web`을 단독 실행해 통과했다.

백엔드·API·DB는 변경하지 않아 서버 테스트를 다시 실행하지 않았다. 실제 정책의 질문 생성, 정책 미해석 화면, 서버 답변 제출·재판정, 복수 답변 충돌·회원 저장은 구현·검증 범위에 포함하지 않는다.
