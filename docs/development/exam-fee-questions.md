# 청년 국가기술자격 응시료 지원 공통요건

2026-09-12부터 질문·판정은 [공고별 조건 데이터](policy-rule-data.md)로 관리한다. 아래 원문 검토 기준은 유지하며 운영 코드의 정책별 클래스는 제거했다.

2026-09-05에 두 번째 실제 정책의 공통요건 비교를 연결했다. 제품 상태와 근거 표시 원칙은 [PRD 5절](../PRD/0001_product-baseline/spec.md#5-자격-안내와-추천-근거)을 따른다. 기존 [국가근로장학금 질문](work-study-questions.md)은 그대로 유지한다.

## 확인한 원문

- 정책번호: `20260527005400113224`, 로컬 정책 개정: `1`.
- 규칙: `exam-fee-2026-v1`.
- 검토한 정규화 내용 해시: `7d7880c52f4f696225afd12d0871c41bf155ab568dd7b72f3d34b7f76b800d56`.
- 공식 출처: [한국산업인력공단 충북지사의 2026년 안내](https://hrdc.hrdkorea.or.kr/hrdc/196105), 게시일 2026-01-28, 확인일 2026-09-05.
- [첨부 PDF](https://hrdc.hrdkorea.or.kr/hrdc/download/downloadFile.hrd?attachSeq=580570)의 본문과 표를 직접 확인했다. 내려받은 파일의 SHA-256은 `94999324baa7767a87365d65ecf8d5268ab1d9c04b2e3acfbd0488be7130264c`다. PDF 전체 파일은 저장소에 복제하지 않았다.

공식 2026년 안내의 출생일 범위와 공단 시행 국가기술자격시험, 연간 3회 한도를 비교한다. 오늘 기준 만 나이로 다시 계산하거나 서비스의 만 19~34세 범위를 이 정책의 조건으로 덮어쓰지 않는다. 국민취업지원제도 등 다른 사업의 조건도 섞지 않는다.

## 질문과 결과

| 질문 | 비교 방식 |
|---|---|
| 출생일 범위 | 1991년 1월 1일을 포함한 이후 / 그 이전 / 모름. 실제 생년월일은 받지 않음 |
| 시험과 시행기관 | 한국산업인력공단 시행 국가기술자격으로 확인 / 다른 시험 / 미확인 |
| 2026년 큐넷 잔여 횟수 | 1·2·3회 / 0회이며 복구 대기 없음 / 취소 후 복구 확인 중 / 미확인 |

앞선 두 조건과 남은 횟수가 맞으면 검토한 공통요건을 충족한 것으로 표시한다. 출생일 범위 밖, 대상 외 시험, 확정된 잔여 횟수 0은 해당 항목의 불충족이다. 누락·모름·복구 확인 중은 추가 확인으로 남긴다. 사용자가 시험에 가지 않았다는 이유만으로 횟수를 돌려주거나 취소 이력을 자체 계산하지 않는다.

시험별 응시자격과 접수 일정, 현재 지원 예산과 실제 결제 적용은 확인하지 않는다. 따라서 전체 `status`는 `NEEDS_REVIEW`를 유지한다. 원문의 2026년 1월 6일은 지원 시작일이며, 예산 소진 종료에 임의의 마감 날짜를 만들지 않는다. 지원 자동 적용과 선택 해제, 결제 전 확인 사항을 결과에 안내한다. 잔여 횟수가 있다는 답변만으로 현재 지원 가능·결제 할인 완료를 표시하지 않는다.

## 서버와 화면 연결

`ExamFeeRules`가 세 항목을 비교하고, `PolicyQuestionService`가 정책번호와 검토한 내용 해시에 맞는 규칙을 선택한다. 국가근로장학금 규칙과 응시료 규칙을 분리했으며 범용 규칙 엔진은 추가하지 않았다.

기존 질문 GET·비교 POST와 `PolicyQuestionnaire` 화면을 그대로 사용한다. 새 경로·DTO·DB 테이블이나 사용자 답변 저장은 없다. 프런트엔드는 서버의 세 질문과 결과를 표시하며 지원 기준을 다시 계산하지 않는다. 답변 수정·삭제·새로고침 때 이전 결과를 지우는 흐름을 유지한다.

원문 내용 해시가 달라지면 질문 제공을 중단한다. 제출한 개정·규칙이 현재와 다르면 409 `POLICY_CHANGED`다. 응시료 질문은 서울 기준 2026년에만 제공하고, 2027년이 되면 재검토 안내를 반환한다. 이는 검토 범위의 제한이며 사업의 공식 종료일을 뜻하지 않는다. 판정 요청에서 현재 시각을 한 번만 읽어 질문 검사와 결과의 기준 시각이 자정 양쪽으로 나뉘지 않게 한다.

공식 사이트를 독립적으로 자동 감시하는 기능은 없다. 온통청년이 반영하기 전에 공식 안내가 바뀌면 별도 재검토가 필요하다. 다른 연도 기준을 채택할 때는 출생일·횟수·공식 출처·규칙 버전과 검토한 내용 해시를 함께 갱신한다.

## 검증

규칙 5건과 PostgreSQL API 2건을 추가했다. 출생일 범위·대상 시험·잔여 횟수, 누락과 복구 대기, 잘못된 질문·중복 답변, 서울 새해 경계, 정책별 규칙 선택, 해시·개정 변경과 동일 판정 시각을 확인했다. API의 활성화 자료는 인공 내용과 해시를 사용한 저장 경계 검사이며 원문 검토를 대신하지 않는다.

- 전용 정책 검사 24건, 서버 전체 420건·실패/오류/건너뜀 0, 빌드 통과.
- 기존 실제 OpenAPI 계약 일치 검사 통과. API 구조와 생성 TypeScript·프런트엔드 소스는 변경하지 않아 웹 검사·빌드는 재실행하지 않았다.
- 전체 테스트 종료 중 기존 Spring Session 만료 정리 작업의 DB 연결 중단 경고가 재현됐다. JUnit 실패는 없으며 테스트 종료 순서 정리는 별도 작업이다.
- 실제 로컬 개정 1에서 미응답 → 공통 충족 → 횟수 복구 중 → 잔여 0회 → 출생일 범위 밖 → 대상 외 시험을 확인했다. 결과와 원문 근거·공식 링크, 답변 수정 시 이전 결과 제거, 답변 삭제·새로고침 초기화를 점검했다. 실제 서버 응답을 사용했으며 인공 API 응답으로 교체하지 않았다.
- 모바일 390px과 데스크톱 1280px에서 확인했고 모바일 가로 넘침이 없었다. 키보드 Enter로 질문 시작·결과 제출, Tab으로 선택상자 간 이동, 결과 제목으로 초점 이동을 확인했다. 기본 선택상자의 방향키·Enter 선택은 도구에서 값이 바뀌지 않아 미확인으로 남겼다. 대표 답변 값은 도구의 선택 기능으로 지정했다.
- 기존 국가근로장학금의 6개 질문도 실제 화면에서 확인했다. 새 서버는 로컬 8080에서 정상 상태이고 응시료 규칙 `exam-fee-2026-v1`·개정 1이 활성화됐다. DB 스키마와 수집 원문, 외부 연동 설정을 바꾸지 않았다.

검사 명령은 `./backend/gradlew -p backend test --tests 'kr.youthpolicymate.policy.catalog.*' bootJar --no-daemon`, `./backend/gradlew -p backend test build --no-daemon`이다.
