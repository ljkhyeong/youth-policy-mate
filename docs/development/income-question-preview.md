# 개발 전용 소득 질문 미리보기

2026-08-30 구현 기준. 제품 요구는 [PRD 4~5절](../PRD/0001_product-baseline/spec.md#4-조건-입력과-로그인), 소득 의미와 미확인 처리는 [소득 조건 설계](../design/income-condition.md)를 따른다.

## 실행과 범위

저장소 루트에서 `npm run dev:web`을 실행하고 <http://127.0.0.1:3000/dev/income>을 연다. 인증키·백엔드·DB가 필요하지 않다.

이 경로는 **화면 점검용 인공 예시**다. 실제 정책이나 소득을 사용하지 않는다. 표시된 금액 구간은 제품의 공통 입력 기준이나 공식 정책 기준표가 아니다. 정확한 금액 입력란·증빙서류·가구원 수·보험료 입력은 추가하지 않았다.

- 본인 소득이라는 대상, 양 끝 날짜를 포함하는 대상 기간, 원화 단위를 질문 위에 표시한다. 정의와 합계 방식, 질문이 필요한 이유도 안내한다.
- 기본 예시는 0원·세 금액 구간·모름 중 하나를 선택한다. ‘초과·이하’의 끝값 포함 여부를 숫자와 문구로 함께 설명한다.
- 처음에는 미선택이다. 답변 없이 확인하면 안내를 표시하고 첫 라디오로 포커스를 옮긴다. ‘모름’은 유효한 답변이며 0원이나 소득 제한 없음으로 바꾸지 않는다.
- 확인 화면은 선택한 구간·대상·연도·단위만 보여준다. 수정 시 선택을 유지하고 삭제 시 미선택으로 돌아간다. 구간을 대표 금액으로 바꾸거나 자격을 판정하지 않는다.
- ‘대상 기간 변경 예시’는 2025년에서 2024년으로 기간·개정을 바꾼다. 선택·확인 상태를 지우며 원래 질문으로 돌아와도 복원하지 않는다. 새로고침하면 처음 질문·미선택 상태로 돌아간다.

## 구간 추가 확인 예시

별도의 버튼으로 **미리 정한 상황**을 연다. 가정한 이전 답변은 `20,000,000원 초과 ~ 30,000,000원 이하`, 인공 허용 기준은 `25,000,000원 이하`다. 이를 `20,000,000원 초과 ~ 25,000,000원 이하`와 `25,000,000원 초과 ~ 30,000,000원 이하`, 모름으로 나눠 묻는다.

이 상황은 현재 선택한 답변에서 계산하거나 서버가 반환한 결과가 아니다. 화면에도 그 차이를 명시했다. 실제 답변의 일부 겹침 여부와 추가 질문 생성은 향후 서버 연결에서 처리한다. [서버 소득 비교기](income-condition.md)를 Next.js에 복제하지 않았다.

## 코드·개인정보·접근 제한

코드는 `frontend/src/app/dev/income/`에 있다.

| 파일 | 책임 |
|---|---|
| `page.tsx` | 개발 모드 접근 허용, 메타데이터, 인공 예시 안내 |
| `income-preview-data.ts` | 표시용 정의·기간·선택 구간과 추가 확인 상황 |
| `income-question-preview.tsx` | 질문·선택·확인·수정·삭제, 질문 변경 시 초기화 |
| `income-question-preview.test.tsx` | 최초 표시, 구간·모름의 의미, 인공 추가 확인 자료 검증 |

질문 객체 전체를 입력 컴포넌트의 React `key`로 사용한다. 정책 식별자·개정·정의·대상·기간·단위·선택 구간이 바뀌면 이전 답변을 가진 컴포넌트를 교체한다. 표시용 타입은 REST DTO나 생성 API 계약이 아니다. 구간은 표시 문자열이며 숫자로 파싱·비교하지 않는다.

답변은 React 상태에만 둔다. 폼 제출·서버 전송·브라우저 저장소·로그·분석 이벤트·AI 호출은 없다. `/conditions`의 값을 가져오거나 수정하지 않는다. 소득 확인이나 자격 인증으로 안내하지 않는다.

`NODE_ENV`가 `development`가 아니면 서버 페이지에서 `notFound()`로 종료한다. `noindex, nofollow`도 설정했지만 접근 제한을 메타데이터에 맡기지 않는다. 주 메뉴에는 개발 경로를 추가하지 않았다.

## 검증 결과와 한계

| 검사 | 결과 |
|---|---|
| `npm run test:web` | 기존 12건 + 소득 질문 5건, 총 17건 통과 |
| `npm run check:web` | 린트 경고 없음, 경로 타입 생성·TypeScript 검사 통과 |
| `npm run build:web` | 프로덕션 빌드 통과 |
| HTTP 응답 | 개발 `/dev/income` 200, 운영 `/dev/income`·`/dev/employment` 404, 운영 `/conditions` 200 |
| 브라우저 흐름 | 미응답 오류·첫 라디오 포커스, 0원·모름·좁은 구간 확인, 수정 시 값 유지, 삭제·기간 변경·되돌리기·새로고침 초기화 |
| 반응형 | 데스크톱 1280px·모바일 390px의 정의·구간·확인 화면 점검. 가로 넘침 없음 |

확인 시 요약 제목, 수정·삭제 시 첫 라디오로 포커스를 옮긴다. 기본 라디오·fieldset·legend와 기존 포커스 스타일을 사용한다. 브라우저 도구의 `ArrowDown` 입력이 선택 이동으로 반영되지 않아 키보드 전용 전체 흐름은 미확인이다. 실제 휴대전화·스크린리더 검증도 별도다. 브라우저 점검은 수동 도구 실행이며 저장소의 E2E 자동 테스트가 아니다.

빌드 첫 실행은 로컬 포트 권한 제한으로 실패했다. 프로젝트의 생성 캐시 `.next/cache/turbopack`만 `/tmp/youth-policy-income-build.VC4fn1/turbopack`에 임시 보관한 뒤 권한을 허용해 재실행했고 통과했다. 소스·의존성·전역 설정은 이 문제 때문에 바꾸지 않았다. 타입 검사와 빌드는 생성 파일 충돌을 피하도록 순서대로 실행했다. 검증용 3100 포트 서버는 확인 후 종료했다.

백엔드·API·DB는 변경하지 않아 서버 117건과 PostgreSQL 통합 테스트를 다시 실행하지 않았다. 실제 정책 질문 생성, 금액 입력 검사·단위 변환, 서버 판정·재질문 연결, 회원 저장은 아직 없다.
