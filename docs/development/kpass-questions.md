## 질문과 비교 범위

| 질문 | 답변과 처리 |
|---|---|
| 기본 연령 | 현재 만 19세 이상 / 미만 / 미확인. 생년월일 전체는 받지 않는다. 만 35세 이상을 기본 가입 대상에서 제외하지 않는다. |
| 회원가입·이용 카드 등록 | 모두 완료 / 카드만 발급 / 가입·등록 미완료 / 미확인. 카드 발급만 한 상태는 현재 이용 준비 미충족이다. |
| 참여 지자체 거주 확인 | 공식 확인 완료 / 확인 진행 중 / 미확인. 진행 중·미확인을 불충족으로 바꾸지 않는다. 국적·주소·증빙을 받지 않는다. |
| 해당 월 인정 이용 | 15회 이상 / 가입 첫 달 1~14회 / 이후 달 1~14회 / 실제 0회이며 반영 대기 없음 / 반영 대기 / 미확인. |

첫 가입 월의 1~14회는 횟수 예외를 적용한다. 실제 이용이 0회인 답변을 예외 충족으로 바꾸지 않는다. 이용내역 반영 대기와 미확인은 추가 확인으로 남긴다. 회원가입이나 연령이 미충족이면 첫 달 횟수 예외로 그 항목까지 충족시키지 않는다.

월 중간의 횟수 미달은 현재 답변 기준의 미달이다. 이후 이용과 반영에 따라 다시 비교할 수 있으며 최종 미지급을 확정하지 않는다. 기본 조건 화면의 생년월일·자치구·취업상태를 추가 질문 답변으로 자동 입력하지 않는다.

공통요건 결과는 충족·불충족·추가 확인을 구분하되 전체 `status`는 `NEEDS_REVIEW`다. 본인·주소·카드 확인, 실제 적립 인정, 제외 교통수단, 청년 등 대상별 분류, 지역·한시 혜택, 환급 방식·금액과 카드사 지급을 확인 사항으로 남긴다. 카드 이용내역이나 외부 회원 계정을 조회하지 않는다.

## 기존 API·화면 연결

`KPassRules`를 `ReviewedPolicyQuestions`와 `PolicyQuestionService`에 등록했다. 검토한 원문에 한해 질문과 목록의 제공 표시·필터에 함께 반영한다. 기존 질문 GET·비교 POST·생성 타입·화면을 사용하며 API 구조와 DB 스키마는 바꾸지 않았다.

질문과 결과의 범위에 대상 연월을 표시한다. `PolicyQuestionService`는 한 번 읽은 시각으로 질문 검사와 결과를 계산한다. 서울 기준 월이 바뀌면 같은 원문 개정이어도 `ruleVersion`이 달라져 이전 답변 제출을 409 `POLICY_CHANGED`로 거절한다. 기존 화면은 답변·결과를 지우고 새 질문을 받는다.

원문 내용 해시·개정·규칙이 바뀌어도 이전 답변을 거절한다. 검토한 2026년을 지나면 질문과 목록 필터에서 제외한다. 이는 규칙 검토 범위의 제한이며 K-패스 사업의 공식 종료일을 설정한 것이 아니다.

공식 홈페이지를 독립적으로 자동 감시하는 기능은 없다. 온통청년 반영 전 공식 안내가 바뀌면 별도 검토가 필요하다. 원문 재수집·새 정책 추가·한시 환급률 계산은 이번 구현 범위가 아니다.

## 검증과 로컬 반영

- 새 규칙 단위 검사 6건과 PostgreSQL API 검사 3건을 추가했다. 공통요건과 전체 상태, 첫 달 예외, 0회·반영 대기, 가입·연령 미달, 임의·중복 답변, 원문·개정 변경과 서울 월말·연말을 확인했다.
- 서버 전체 **431건**, 실패·오류·건너뜀 0, 빌드 통과. 실제 생성 OpenAPI와 저장 계약의 일치 검사도 통과했다. API 구조·생성 TypeScript·프런트엔드 소스를 바꾸지 않아 웹 테스트와 웹 빌드는 재실행하지 않았다.
- 실제 로컬 개정 1에서 질문 4개·2026년 9월 범위·월별 규칙 버전을 확인했다. 정책 수는 40건이며 질문 제공 필터는 응시료·K-패스·국가근로 3건이다.
- 브라우저에서 미응답, 가입 첫 달 1~14회, 이후 달 1~14회, 실제 0회, 이용 반영 대기, 주소 확인 대기, 15회 이상, 카드만 발급, 만 19세 미만을 실제 서버 응답으로 확인했다. 답변 수정 시 결과 삭제, 답변 삭제·새로고침 초기화, 근거·전체 추가 확인 상태도 확인했다.
- 월 변경 화면만 브라우저 시험 응답으로 확인했다. 409 뒤 기존 답변·결과를 지우고 10월 질문을 표시하는지 확인한 후 시험 응답을 제거했다. 실제 서버의 월말 차단은 고정 시계의 PostgreSQL API 검사로 확인했다.
- 모바일 390px·데스크톱 1280px에서 문구·결과·가로 넘침을 확인했다. Enter로 질문 시작, 결과 초점, 필터의 질문 링크 Enter와 Tab·Enter로 질문 시작을 확인했다. 기본 선택상자의 키보드 답변 선택 전체 흐름은 이번 검증에 포함하지 않았다.
- 서버를 새 빌드로 교체하고 정상 상태·실제 질문·필터를 확인했다. 외부 소셜 로그인·SMTP·수집 일정·실제 `.env`는 변경하지 않았다.
- 전체 테스트 종료 때 기존 Spring Session 정리 작업의 DB 연결 중단 경고가 재현됐다. JUnit 실패는 없으며 종료 순서는 이번 변경에서 다루지 않았다.
