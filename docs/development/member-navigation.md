# 내 정책 화면 이동과 로그인 복귀

기본 화면 복원은 `c1c9014`, 저장 정책 검색은 `bae7b16` 기준이다. 내 정책의 탭·정책명 검색어·변경 필터·일정 필터·알림 페이지와 필터·이메일 설정 펼침 상태를 주소에 반영한다.

## 동작

| 주소 | 화면 |
|---|---|
| `/my` | 관심 정책 |
| `/my?view=calendar` | 마감 일정 |
| `/my?view=calendar&status=CLOSED` | 접수가 마감된 일정 |
| `/my?q=주거&changed=1` | 정책명에 ‘주거’가 포함된 변경 정책 |
| `/my?view=notifications` | 서비스 내 알림 |
| `/my?view=notifications&page=3&filter=UNREAD` | 안 읽은 알림의 3페이지 |
| `/my?view=email` | 알림 탭의 이메일 설정을 펼쳐서 표시 |

- 새로고침·뒤로 가기·앞으로 가기·새 탭에서 선택 화면을 복원한다. 일정 필터와 알림 페이지·필터는 다른 탭을 오가도 유지하며 관심 정책 목록에는 적용하지 않는다.
- 탭은 Next.js 링크, 일정 필터는 `router.push`, 이메일 설정 펼침은 `router.replace`로 주소를 갱신한다. `useSearchParams`를 사용하는 회원 화면은 `Suspense` 안에서 렌더링한다.
- 탭·필터 이동만으로 회원 세션과 저장 목록을 다시 조회하지 않는다. 새로고침 버튼은 기존처럼 최신 데이터를 조회한다.
- 사용할 수 없는 수신 해제 링크의 ‘내 알림 설정으로’는 이메일 설정을 연다. 비회원과 로그인 만료 상태에서는 `next=my`와 화면 선택값을 로그인 페이지에 전달한다.
- 로그인 실패 후 재시도에도 목적지를 유지한다. 이미 로그인했다면 같은 목적지의 이동 버튼을 제공한다. 완료 후 복귀 기록을 지우고 일반 로그인에서는 이전 목적지를 사용하지 않는다.
- 로그인 복귀는 관리자·정책 경로를 우선한다. 내 정책 경로는 정책명 검색어와 허용된 화면·변경 여부·접수 상태·알림 페이지와 필터만 다시 구성하며 외부 주소와 다른 매개변수는 전달하지 않는다. 개인 조건·이메일 주소·인증값은 주소에 넣지 않는다.
- 알림 필터 변경은 첫 페이지로 이동한다. 안 읽은 목록의 읽음 처리는 첫 페이지 주소로 교체해 목록 감소에 따른 누락을 피한다. 전체 알림은 같은 페이지를 다시 조회한다. 기본값인 1페이지·전체 필터는 주소에서 생략한다.
- 알림 페이지·필터가 바뀌면 React의 `key`로 목록과 요청 상태를 새로 만든다. 이전 요청을 중단하고 주소와 맞지 않는 늦은 응답은 무시한다. 읽음 응답을 기다리는 동안 다른 탭으로 이동했다면 현재 탭을 유지한다.
- 읽음 처리나 재조회 후의 키보드 초점은 사용자가 다른 영역으로 옮기지 않았을 때만 복원한다. 뒤로 가기와 재조회는 읽음 요청을 반복하지 않는다.

기존 3000 포트 서버와 모의 회원·OAuth 응답을 사용했다. 같은 페이지에서 탭만 바꾸면 알림을 다시 조회하지 않고, 알림 이동·읽음 처리가 회원 정책 목록을 다시 조회하지 않는 것을 요청 횟수로 확인했다. 통과한 두 알림 흐름의 읽음 요청 10건은 모의 응답에서만 처리했다. 실제 회원 변경과 브라우저 실행 오류는 없었으며 390px 화면의 가로 넘침·키보드 페이지 이동을 확인했다.

최초 코드 검사에서 컴포넌트에 전달하는 ref 이름을 React Compiler가 인식하는 `Ref` 접미사로 수정했다. 기존 알림 검증에서 탭 이동과 읽음 응답이 겹칠 때 초점이 알림으로 돌아가는 문제를 재현하고, 현재 초점 위치를 확인하도록 수정한 뒤 전체 흐름을 통과했다. 스크립트와 캡처는 `/tmp/youth-notification-navigation/`에 있고 전용 세션은 종료했다.

서버·DB·API 계약·운영 환경은 변경하지 않았다. 실제 OAuth·메일 공급자 연동과 이미지 빌드·홈서버 배포는 실행하지 않았다.
