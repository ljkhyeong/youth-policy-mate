# 내 정책 화면 이동과 로그인 복귀

2026-09-12, 코드 `43b85cd`. 내 정책의 탭·일정 필터·이메일 설정 펼침 상태를 주소에 반영한다.

## 동작

| 주소 | 화면 |
|---|---|
| `/my` | 관심 정책 |
| `/my?view=calendar` | 마감 일정 |
| `/my?view=calendar&status=CLOSED` | 접수가 마감된 일정 |
| `/my?view=notifications` | 서비스 내 알림 |
| `/my?view=email` | 알림 탭의 이메일 설정을 펼쳐서 표시 |

- 새로고침·뒤로 가기·앞으로 가기·새 탭에서 선택 화면을 복원한다. 일정 필터는 다른 탭을 오가도 유지하며 관심 정책 목록에는 적용하지 않는다.
- 탭은 Next.js 링크, 일정 필터는 `router.push`, 이메일 설정 펼침은 `router.replace`로 주소를 갱신한다. `useSearchParams`를 사용하는 회원 화면은 `Suspense` 안에서 렌더링한다.
- 탭·필터 이동만으로 회원 세션과 저장 목록을 다시 조회하지 않는다. 새로고침 버튼은 기존처럼 최신 데이터를 조회한다.
- 사용할 수 없는 수신 해제 링크의 ‘내 알림 설정으로’는 이메일 설정을 연다. 비회원과 로그인 만료 상태에서는 `next=my`와 화면 선택값을 로그인 페이지에 전달한다.
- 로그인 실패 후 재시도에도 목적지를 유지한다. 이미 로그인했다면 같은 목적지의 이동 버튼을 제공한다. 완료 후 복귀 기록을 지우고 일반 로그인에서는 이전 목적지를 사용하지 않는다.
- 로그인 복귀는 관리자·정책 경로를 우선한다. 내 정책 경로는 허용된 화면·접수 상태만 다시 구성하며 외부 주소와 다른 매개변수는 전달하지 않는다. 개인 조건·이메일 주소·인증값은 주소에 넣지 않는다.
- 알림 목록 내부의 페이지·안 읽은 필터는 기존 화면 상태를 사용한다. 이번 주소 복원 범위에 포함하지 않는다.

기존 3000 포트 서버와 모의 회원·OAuth 응답을 사용했다. 탭 이동에 따른 회원 목록 재조회와 문서 전체 새로고침이 없음을 요청 횟수로 확인했다. 정책 목록 조회가 실패해도 이메일 설정을 이용할 수 있었다. 390px·1280px 화면을 확인했고 모바일 탭은 51px 높이이며 가로 넘침이 없었다. 회원 변경 요청과 브라우저 실행 오류는 없었다.

최초 코드 검사에서 React Compiler가 요구한 상태 갱신 함수의 의존성을 추가한 뒤 통과했다. 최초 브라우저 검사에서는 이메일 설정의 주소 이동이 끝나기 전에 새로고침해 대기 시간이 초과됐다. 검증 스크립트가 이동 완료를 기다리도록 수정한 뒤 전체 흐름을 통과했다. 스크립트와 화면 캡처는 `/tmp/youth-member-navigation/`에 있고 전용 세션은 종료했다.

서버·DB·API 계약·운영 환경은 변경하지 않았다. 실제 OAuth·메일 공급자 연동과 이미지 빌드·홈서버 배포는 실행하지 않았다.
