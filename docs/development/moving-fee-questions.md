# 2026년 상반기 중개보수·이사비 지원 질문

## 원문과 적용 범위

2026-09-08에 서울시 공고 제2026-1109호의 소득 기준을 다시 확인했다.

- [서울시 상반기 모집 공지](https://youth.seoul.go.kr/bbs/view.do?key=2303300002&pstSn=2604010002)
- [공고 PDF](https://soco.seoul.go.kr/coHouse/cmmn/file/fileDown.do?atchFileId=12817e11dea24565ae8f7a84b98175db&fileSn=1): 1쪽 접수 기간, 2쪽 주소·연령·소득, 3쪽 주택·참여 제한·지원 비용, 4쪽 선발 기준

온통청년 정책 `20260614005400213232`의 현재 저장 원문 해시 `e3f828c1c37c1ecddde5a2dc59065e1179642d0fd7be3e919ec8cb9b07441c42`에만 연결한다. 이 원문의 신청 기간은 2026.4.1.~4.14.이며, 동일 제목의 다른 정책번호나 갱신된 하반기 안내로 확대하지 않는다. 규칙 버전은 `moving-fee-2026-h1-v2`이다. 소득 질문이 없던 `v1` 답변은 HTTP 409로 차단하며 기존 화면이 답변을 지우고 최신 질문을 다시 받는다.

## 질문과 남은 확인

질문은 공고의 출생일 범위, 이사·전입신고 기간, 세대주·임차인·주민등록, 본인 무주택, 주택 거래금액, 건강보험료 기준 소득을 확인한다. 공고에 적힌 날짜와 양 끝 경계를 사용한다. 현재 서울 거주를 과거 신청 당시 전입 완료로 바꾸지 않는다.

무주택 판단에는 분양권·입주권·공유지분이 포함되며, 전세사기 피해 주택 취득 등 예외가 확인 중이면 미확인으로 남긴다. 청약의 무주택 기준을 가져오지 않는다. 주택 거래금액은 보증금과 월세를 기준으로 하며 사용자가 확인한 범위를 답한다.

소득은 2026년 3월 건강보험료 고지금액을 공고 2쪽의 가구원 수·가입 유형별 중위소득 150% 기준표와 비교한 답변을 받는다. 기준 이하(같은 금액 포함)는 충족, 초과는 불충족이다. 장기요양보험료는 제외하며 피부양자는 주소가 분리되어도 부양자의 고지금액을 사용한다. 부양자 보험료·가구원 수·가입 유형이 확인 중이거나 보험료 조회가 어려워 대체 증빙을 확인하는 경우는 미확인으로 남기고 각각의 확인 사유를 표시한다. 월급·취업 상태를 보험료로 환산하거나 피부양자의 본인 보험료를 0원으로 판정하지 않는다. 보험료 금액·가구원 정보·서류 자체를 수집하지 않는다.

모든 질문을 충족해도 소득 증빙 인정, 중복지원, 부모 주택 임차, 급여 수급·국적 관련 제한, 실제 지출·증빙·선정은 추가 확인이 필요하다. 다른 기관에서 비용 한 종류를 지원받은 사람에게 다른 비용 지원이 가능한 예외를 안내한다. 최종 자격을 신청 가능으로 표시하지 않는다.

접수는 서울 시각 2026.4.1. 10:00~4.14. 18:00이다. 질문과 평가 결과에 접수 전·마감을 표시하되 조건 충족 여부와 분리한다. 검토한 연도가 끝나거나 원문·개정·규칙이 바뀌면 이전 답변의 평가를 중단한다.

| 실행 | 확인 범위·결과 | 로컬 로그 |
|---|---|---|
| `npm run verify -- test:policy-catalog -- --tests 'kr.youthpolicymate.policy.catalog.*RulesTest'` | 정책 규칙과 PostgreSQL API 검사 통과. 소득 기준 이하·초과·미확인 사유, 다른 조건과의 독립성, 소득 질문 응답과 구버전 409 차단 확인 | `.local/verification/1788825474707-cec73262.log` |
| `npm run verify -- package:backend` | 서버 실행 파일 생성. 테스트 반복 없음 | `.local/verification/1788825513995-bb652d47.log` |

기존 질문 화면에서 실제 로컬 정책의 소득 기준 이하·부양자 미확인 결과, 답변 변경 시 결과 초기화, 최종 자격 추가 확인 유지를 확인했다. PC와 375px 모바일에서 안내·선택지 표시를 확인했으며 가로 넘침이 없었다. 검증용 답변을 지우고 임시 브라우저를 종료했다. 개발 화면의 기존 `/favicon.ico` 404 외에 질문 요청 실패는 없었다.

웹 소스·API DTO·DB 스키마는 바꾸지 않았다. API 재생성·웹 전체 검사·전체 서버 검사는 반복하지 않았다. 기본 연령 비교는 기존 규칙을 그대로 사용하며 이전 기록은 [개인 조건 탐색](condition-policy-discovery.md#검증)에 있다. 로컬 서버는 새 실행 파일로 반영했으며 로그는 `/tmp/youth-moving-income-backend.log`다. 정기 수집·이메일·알림 실행은 비활성화했다.
