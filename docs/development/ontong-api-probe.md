# 온통청년 API 응답 점검

이 명령은 인증키 발급 후 실제 요청·응답을 확인하는 개발 도구다. 정책을 DB에 적재하거나 화면에 공개하는 운영 수집기가 아니다. Node.js 기본 기능만 사용하므로 추가 패키지 설치나 서버·DB 기동이 필요하지 않다.

현재 인증키는 승인 대기 중이다. 아래 명령의 요청 생성·실패 처리·파일 저장은 인공 응답으로 테스트했으며, 실제 온통청년 성공 응답은 아직 확인하지 않았다. 확인할 계약은 [API 조사 문서 8절](../research/ontong-api-contract.md#8-유효-인증키-확보-후-필요한-최소-확인)을 따른다.

## 1. 인증키 설정

발급된 키는 저장소 루트의 `.env`에서 `ONTONG_API_KEY` 값으로 설정한다. `.env`가 없으면 `.env.example`의 내용을 복사해 새 `.env`를 만든다. 기존 `.env`는 덮어쓰지 않는다.

- 실제 키를 `.env.example`에 쓰거나 커밋하지 않는다. `.env`는 Git에서 제외된다.
- 키를 채팅, 명령줄 인수, `NEXT_PUBLIC_*` 변수에 넣지 않는다.
- 명령은 루트 `.env`를 읽으며, 같은 이름의 셸 환경변수가 이미 있으면 환경변수가 우선한다.
- 키가 비어 있으면 네트워크 요청과 결과 파일 생성 없이 종료 코드 1로 끝난다.

환경 파일 처리는 [Node.js의 `--env-file-if-exists`](https://nodejs.org/api/cli.html#--env-file-if-existsfile)를 사용한다.

## 2. 최소 호출 순서

저장소 루트에서 실행한다. 아래 명령은 각각 별개의 외부 요청 1회를 보낸다. 연속 실행이나 전체 페이지 수집은 하지 않는다.

먼저 지역 필터 없이 목록 1건을 요청한다.

```sh
npm run probe:ontong
```

저장된 응답에서 실제 정책번호를 확인한 뒤 상세를 요청한다. 아래 `정책번호`는 확인한 값으로 바꾼다.

```sh
npm run probe:ontong -- --policy-number 정책번호
```

이후 지역 필터의 차이를 볼 때만 서울 또는 한 자치구를 지정한다.

```sh
npm run probe:ontong -- --region 11000
npm run probe:ontong -- --region 11680
```

공식 요청 표의 이름인 `apiKeyNm`, `pageNum`, `pageSize`, `pageType`, `plcyNo`, `zipCd`, `rtnType`을 사용한다. 주소는 `https://www.youthcenter.go.kr/go/ythip/getPlcy`로 고정한다. 목록은 `pageType=1`, 정책번호가 있으면 `pageType=2`다. 모든 요청의 페이지는 1, 크기는 1이다. 지역 옵션은 점검 범위를 줄이기 위해 5자리 코드 하나만 받는다.

이 설정은 명세를 바탕으로 만든 점검 요청이며, 서버가 해당 조합을 어떻게 처리하는지는 실제 응답으로 확인해야 한다. 지역 목록 한 건만으로 전국·서울 자치구 정책의 누락 여부를 검증할 수 없다. 목록 결과를 `0건`으로 해석하거나 상세 응답의 필드 구조를 추정하는 코드도 없다.

사용법만 보기:

```sh
npm run probe:ontong -- --help
```

## 3. 저장 결과와 실패 처리

HTTP 200이고 JSON 문법을 읽을 수 있으면 `.local/ontong-api/`에 새로운 JSON 파일을 만든다. 같은 명령을 다시 실행해도 이전 파일은 덮어쓰지 않는다. 생성 파일의 읽기·쓰기는 소유자에게만 허용하며, 저장 경로는 Git에서 제외한다.

| 항목 | 저장 내용 |
|---|---|
| `capturedAt` | 응답을 확보한 UTC 시각 |
| `reviewStatus` | 항상 `UNVERIFIED`. 정상 정책 응답인지 아직 확인하지 않았다는 뜻 |
| `request` | 인증키를 제외한 고정 주소와 요청 조건 |
| `response` | HTTP 상태, Content-Type, 바이트 수, UTF-8 원문 문자열 `rawBody` |

`rawBody`는 원문 문자열이다. JSON 파싱은 문법·키 노출 확인에만 쓰고, 파싱 결과를 다시 직렬화해 원문을 대체하지 않는다. 예를 들어 큰 정수가 JavaScript 숫자로 바뀌면서 자릿수를 잃는 일을 피한다.

- 1회 요청, 자동 재시도 없음, 15초 시간 제한, 응답 본문 최대 1 MiB를 적용한다. 이 수치는 점검 도구의 제한이며 온통청년의 공식 한도가 아니다.
- 리다이렉트를 따라가지 않는다. 키를 다른 주소로 전달하지 않기 위한 제한이다.
- HTTP 오류와 HTML 등 JSON이 아닌 본문은 출력·저장하지 않는다. HTTP 상태와 고정된 오류 안내만 출력한다.
- 응답이나 저장할 요청 조건에서 키 또는 일반적인 URL 인코딩 형태의 키가 발견되면 저장하지 않는다. 연결 오류의 원문 메시지나 키가 포함된 URL도 출력하지 않는다.
- **HTTP 200의 JSON 오류는 저장될 수 있다.** 성공·오류 코드의 실제 구조를 아직 모르기 때문에 모든 저장 결과를 미검증으로 표시한다.
- 원문에는 담당자 연락처 등이 들어 있을 수 있다. 저장 파일은 그대로 커밋하거나 공유하지 않고 필요한 정책 필드만 검토한 뒤 테스트 자료로 옮긴다.

## 4. 확인 후 다음 작업

1. 응답이 인증·요청 오류인지 정상 정책 목록인지 확인한다.
2. 실제 목록 경로, 페이지 정보, 정책번호와 필드 타입을 조사 문서에 기록한다.
3. 같은 정책의 목록·상세에서 누락·널·빈 문자열·복수 코드·날짜 형식을 비교한다.
4. 호출 한도와 수정·삭제 의미는 승인 화면이나 공식 안내로 확인한다. 부하를 주어 한도를 실험하지 않는다.
5. 필요한 표본이 확보되면 원천 DTO·정규화·Flyway 스키마와 첫 수집 흐름을 구현한다.

도구 검증:

```sh
npm run check:tools
```

테스트는 외부 요청 없이 인공 응답을 사용한다. 키 누락, 한 번의 요청과 원문 보존, 상세·지역 파라미터, HTTP·HTML 실패, 키 반사·연결 오류, 응답 크기 제한, 파일 권한·덮어쓰기 방지를 확인한다. 이 결과를 실제 API 계약 검증으로 보고하지 않는다.
