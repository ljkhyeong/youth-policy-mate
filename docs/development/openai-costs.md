# OpenAI 프로젝트 비용 조회

2026-09-12 코드 `98f3ac5` 기준. 지정한 프로젝트의 UTC 월 비용을 조회하는 독립 명령을 제공한다. 실제 관리자 키·공급자 조회·운영 설정은 사용자가 진행한다.

## 실행

[전용 환경변수 예시](openai-costs.env.example)의 두 값을 명령 프로세스에 주입한다. 파일을 자동으로 읽거나 `.env`를 변경하지 않는다.

| 변수 | 용도 |
|---|---|
| `OPENAI_ADMIN_KEY` | 비용 조회 권한이 있는 OpenAI 관리자 키. 생성용 `OPENAI_API_KEY`를 대신 사용하지 않는다. |
| `OPENAI_COSTS_PROJECT_ID` | 조회할 한 프로젝트의 ID. 미설정이면 조직 전체를 조회하지 않고 중단한다. |

관리 API에는 관리자 키가 필요하며 이 키는 일반 생성 API에 사용할 수 없다. 키 발급·권한과 프로젝트 선택은 운영자가 확인한다. 관리자 키를 일반 API·웹 컨테이너나 AI 생성 작업에 전달하지 않는다. [OpenAI 관리 API 안내](https://developers.openai.com/api/reference/administration/overview)

저장소 루트에서 조회할 월만 인자로 전달한다. 키를 명령 인자에 넣지 않는다.

```sh
npm run ai:costs -- --args=2026-08
```

배포 이미지의 별도 명령으로 실행하려면 기존 시작 명령을 다음과 같이 지정한다. `/app/app.jar`는 현재 API Dockerfile의 경로다.

```sh
java -Dloader.main=kr.youthpolicymate.ingestion.OpenAiCostsCommand \
  -cp /app/app.jar org.springframework.boot.loader.launch.PropertiesLauncher 2026-08
```

DB·웹 서버·Flyway·정기 작업을 시작하지 않는다. 모델·요금 설정이나 `AI_ENABLED` 활성화도 필요하지 않다. 실행 중인 API를 중지할 필요는 없으며 기본 API 시작 명령은 유지한다. 정상 조회는 종료 코드 0, 인자·설정·조회 오류는 1이다.

## 조회 범위와 해석

- `GET /v1/organization/costs`에 프로젝트 필터와 `group_by=project_id`, 일 단위 집계를 지정한다. 시작 시각을 포함하고 끝 시각은 제외한다. [공식 Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)
- 월의 시작·끝은 UTC 기준이다. 지난달은 한 달 전체, 현재 월은 명령 시작 시각까지 조회한다. 미래 UTC 월은 요청하지 않는다. 한국 시간 월 경계와 다를 수 있다.
- 프로젝트 ID·조회 기간·조회 시각·통화별 합계를 출력한다. 서로 다른 통화를 더하거나 원화로 환산하지 않는다. 금액은 `BigDecimal`로 합산하며 소수 자릿수와 음수 조정액을 유지한다.
- 한 번에 31개 일별 버킷을 요청하고 다음 페이지가 있으면 이어서 읽는다. 월 일수만큼의 페이지를 읽어도 끝나지 않거나 같은 페이지·날짜가 반복되면 중단한다. 일부 합계를 정상 월 비용으로 출력하지 않는다.
- 다른 프로젝트·범위 밖 날짜·누락 금액·잘못된 통화는 불완전한 응답으로 처리한다. 비용 항목이 없으면 해당 사실만 안내하며 무과금으로 확정하지 않는다.
- 권한 오류·요청 한도·공급자 장애를 구분하고 자동 재시도하지 않는다. 연결 제한은 3초, 응답 제한은 10초다. 오류 본문·인증키·전체 원문은 출력하거나 저장하지 않는다.

조회 결과는 해당 시점에 공급자가 반환한 프로젝트 집계다. 같은 프로젝트를 쓰는 다른 프로그램의 비용도 포함될 수 있으므로 AI 생성 키가 속한 프로젝트를 지정한다. 최종 청구서·세금·환율·개별 요청의 청구 또는 무과금 근거를 대체하지 않는다. 현재 월의 집계가 끝났거나 비용 정보가 모두 반영됐다고 보장하지 않는다.

기존 [예산 예약과 수동 정산](ai-rule-drafts.md)은 유지한다. 이 명령은 예약액·월 한도·요금표·AI 요청 상태를 바꾸지 않는다. 프로젝트 합계를 여러 요청에 나누어 넣거나 비용 항목 없음만으로 예약을 해제하지 않는다. 요청별 자동 대사·정산과 정기 조회는 구현하지 않았다.

- 최초 검사는 테스트 라이브러리의 문자열 비교 인자를 잘못 사용해 컴파일 단계에서 실패했다. 테스트 호출만 수정한 뒤 위 범위를 통과했다.
- `npm run verify -- package:backend`: 배포용 JAR 빌드 통과. `.local/verification/1789224289325-d1045aad.log`.
- JAR의 `PropertiesLauncher`에서 비용 조회 명령을 실행하고 키 미설정 시 공급자 호출 전에 종료하는 것을 확인했다. `/tmp/youth-openai-costs-jar.log`.
- 기존 앱의 빈·설정·생성/정산 코드·DB·공개 API·웹을 변경하지 않았다. `42e8c78`의 전체 서버 검사와 기존 웹 검증을 재사용했다. 비용 조회는 독립 모의 연동 검사와 컴파일·패키징으로 확인했으며 이번에 전체 서버 검사를 반복하지 않았다.
- 실제 OpenAI 요청·키 등록·비용 대조·Docker 이미지·k3s 실행은 하지 않았다. 모의 공급자와 명령 프로세스는 모두 종료했다.
