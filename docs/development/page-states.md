# 공통 상태 화면

2026-08-30 구현 기준. 제품 요구는 [PRD](../PRD/0001_product-baseline/spec.md), 실행 방법은 [로컬 개발 환경](local-development.md)을 따른다. 실제 정책 조회나 자격 판정 API를 연결한 작업은 아니다.

## 현재 동작

| 상태 | 표시·행동 | 현재 연결 위치 |
|---|---|---|
| 로딩 | 불러오는 중 안내, 움직임 줄이기 설정을 따르는 표시 | `/conditions`의 Next.js 로딩 경계와 개발 미리보기 |
| 빈 결과 | 검색 결과가 없다는 안내와 조건 변경 행동 | 개발 미리보기만. 실제 검색·필터는 아직 없음 |
| 오류 | 오류 안내, 다시 불러오기, 서비스 소개로 이동, 미저장 입력 손실 가능성 안내 | Next.js 공통 오류 경계와 개발 미리보기 |
| 404 | 주소 확인 안내, 서비스 소개·내 조건 입력으로 이동 | 존재하지 않는 주소와 운영 빌드의 개발 미리보기 차단 |

오류·로딩·빈 결과를 신청 가능 여부로 바꾸지 않는다. 빈 결과 예시는 검색 결과 없음과 자격 불충족을 구분한다. 가상 정책·추천 건수·지원 금액·신청 마감일은 만들지 않았다.

`PageState`는 화면 표시 컴포넌트이며 API DTO나 서버 판정 상태 모델이 아니다. 제목·설명·행동은 호출하는 화면이 전달한다. 실제 검색에서는 조회에 성공했고 결과가 비었을 때만 빈 결과 화면을 사용한다. 정책 조건 미해석·추가 정보 필요는 별도의 자격 안내로 다뤄야 한다.

## 코드와 책임

- `frontend/src/components/page-state.tsx`: 공통 표시, `LoadingState`, `LoadErrorState`.
- `frontend/src/app/conditions/loading.tsx`: 조건 입력 페이지를 불러오는 동안 표시할 화면.
- `frontend/src/app/error.tsx`: Next.js가 전달한 `retry()`를 버튼에 연결하고 오류 제목으로 포커스를 옮긴다.
- `frontend/src/app/not-found.tsx`: 없는 주소의 공통 안내.
- `frontend/src/app/dev/states/`: 개발 모드에서 상태를 선택해 보는 미리보기.
- `frontend/src/components/page-state.test.tsx`: 상태 안내 역할, 오류 원문 비노출, 404 복귀 경로 검사.

`app/error.tsx`는 페이지와 하위 구간의 렌더링 오류를 처리한다. 같은 구간의 루트 `layout.tsx`, 이벤트 핸들러, 렌더링과 연결되지 않은 비동기 처리의 모든 오류를 잡는 것은 아니다. `global-error.tsx`나 외부 오류 수집은 추가하지 않았다.

사용자 화면에 원본 오류 메시지·스택·digest를 표시하지 않고 별도 오류 로그·분석 전송도 추가하지 않았다. 이는 Next.js 개발 도구나 프레임워크 자체의 진단 로그까지 비활성화했다는 뜻은 아니다. 실제 개인정보·인증키를 예외 메시지에 넣지 않는다.

오류 복구에는 설치된 Next.js 16.3.3의 `retry()`를 사용한다. 성공을 보장하거나 입력값 복원을 약속하지 않는다. 화면 밖에 입력을 저장하는 기능은 추가하지 않았다. 재조회 없이 오류 상태만 초기화하는 `reset()`과는 구분한다. [Next.js 오류 화면 문서](https://nextjs.org/docs/app/api-reference/file-conventions/error)

로딩 경계는 최상위가 아닌 `/conditions`에만 둔다. 최상위 `loading.tsx`가 있으면 개발 미리보기에서 `notFound()`를 호출해도 스트리밍 응답이 먼저 시작되어 HTTP 200이 나올 수 있었다. 경계를 옮긴 뒤 운영 빌드의 `/dev/states`가 HTTP 404를 반환하는 것을 확인했다. 이후 정책 화면도 필요한 구간에 로딩을 연결하고 상태 코드를 함께 확인한다. [Next.js 404와 스트리밍 응답](https://nextjs.org/docs/app/api-reference/file-conventions/not-found)

## 개발 미리보기

저장소 루트에서 실행한다.

```sh
npm run dev:web
```

<http://127.0.0.1:3000/dev/states>에서 로딩·빈 결과·오류를 선택한다. 재시도·검색 조건 변경 버튼은 확인 메시지만 표시한다. 외부 요청, 검색, 개인정보 입력·저장은 수행하지 않는다. 화면 아래 링크는 실제로 존재하지 않는 주소의 404 안내로 이동한다.

주 메뉴에는 미리보기 링크를 추가하지 않았다. `NODE_ENV`가 `development`가 아니면 `notFound()`로 종료하며 운영 빌드에서는 접근할 수 없다. `noindex, nofollow`도 유지한다. 운영 접근 차단은 메타데이터에 의존하지 않는다.

## 접근성과 검증

- 로딩·빈 결과는 `role="status"`, 오류 본문은 `role="alert"`로 구분한다. 행동 버튼은 알림 영역 밖에 둔다.
- 제목과 영역을 연결하고 페이지에서는 `h1`, 미리보기 안에서는 `h2`를 사용한다.
- 로딩 장식은 보조기기에서 숨기고 `motion-safe`일 때만 회전시킨다. 제목·본문은 애니메이션 없이도 읽을 수 있다.
- 기존 버튼 크기와 포커스 표시를 재사용한다. 오류·404에서 현재 메뉴를 잘못 표시하지 않도록 `SiteShell`의 활성 메뉴는 선택값으로 바꿨다.

macOS arm64·Node.js 25.4.0·npm 11.7.0에서 다음을 확인했다.

| 검사 | 결과 |
|---|---|
| `npm run test:web` | 기존 조건 입력 5개 + 상태 화면 3개, 총 8개 통과 |
| `npm run check:web` | 린트·경로 타입 생성·TypeScript 검사 통과 |
| `npm run build:web` | 프로덕션 빌드 통과 |
| 개발 모드 | `/dev/states` HTTP 200, 상태 선택·확인 버튼 동작 |
| 운영 빌드 | `/dev/states`와 없는 주소 HTTP 404, `/conditions` HTTP 200 |
| 브라우저 | 데스크톱 1280px·모바일 390px 배치, 모바일 가로 넘침 없음, 404에서 조건 입력으로 이동, 빈 입력 오류·첫 항목 포커스 |

브라우저의 Tab 입력이 실제 포커스 이동으로 반영되지 않아 키보드만 사용하는 전체 흐름은 확인하지 못했다. 실제 휴대전화·스크린리더·움직임 줄이기 OS 설정도 별도 검증이 필요하다. 회전 제한은 코드와 마크업에서 확인한 범위다.

오류 원문 비노출은 컴포넌트 렌더링 테스트로, 버튼 호출은 미리보기로 확인했다. 실제 페이지 오류를 강제로 발생시켜 `retry()`로 복구하는 브라우저 흐름과 외부 API 실패·복구는 아직 확인하지 않았다. 백엔드·API·DB를 변경하지 않아 서버 테스트는 이번 작업에서 다시 실행하지 않았다.
