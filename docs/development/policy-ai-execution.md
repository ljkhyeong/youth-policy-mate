# AI 요청 실행 포트와 인공 실행기

2026-09-01 구현 기준. [실행 경계 설계](../design/policy-ai-execution.md)에 따라 공급자와 분리된 실행 포트와 예약·실행 조정자를 추가했다. 실제 AI 공급자·정책 본문·프롬프트·후보 DB 저장은 없다.

## 코드와 동작

| 코드 | 역할 |
|---|---|
| `PolicyAiExecutionPort` | 실행 신원과 호출 식별 정보를 받고 응답·청구 상태 또는 결과 미확인을 반환 |
| `PolicyAiExecutionCoordinator` | 예약, 호출 기록, 트랜잭션 밖 실행, 미확인·정산·무과금 상태 반영 |
| `PolicyAiExecutionCoordinatorTest.ScriptedPort` | 정해진 인공 결과를 반환하고 실행 중 트랜잭션 여부를 기록하는 테스트 대역 |

조정자는 Spring 빈이나 트랜잭션 서비스로 등록하지 않았다. 실제 공급자 어댑터가 없기 때문에 현재는 통합 테스트에서 저장소와 인공 포트를 직접 조립한다. 각 저장소의 짧은 트랜잭션이 끝난 뒤 포트를 호출한다.

포트가 반환한 `PolicyAiResult`는 호출 측에 돌려주지만 후보 상태나 DB에 자동 저장하지 않는다. 응답 요청이 원래 예정 요청과 다르거나 응답·청구 시각이 호출 순서보다 빠르면 적용하지 않고 예약액을 유지한다.

응답을 받은 뒤 청구가 미확인이면 예약 단계는 `DISPATCHED`로 남는다. 예상하지 못한 실행기 예외도 결과 미확인 사유를 만들어내지 않고 예외를 전달하며 같은 단계와 예약액을 유지한다. 이미 호출을 기록한 재전달은 포트를 다시 호출하지 않는다. 후속 [복구 저장소](ai-reservation-recovery.md)는 이런 미완료 예약의 확인 소유권과 시도 이력을 저장한다.

## 검사

저장소 루트에서 실행한다.

```sh
npm run test:ai-execution
npm run check:backend
```

`test:ai-execution` 7건은 실제 PostgreSQL 18.6 Testcontainers와 인공 실행기로 다음 경계를 확인한다.

- 외부 실행 중 Spring 트랜잭션이 열려 있지 않음
- 확인된 비용 정산
- 타임아웃의 `OUTCOME_UNKNOWN` 기록과 예약액 유지
- 응답 후 청구 대기의 예약액 유지
- 확인된 무과금 해제
- 예약 거절·이미 호출한 재전달의 포트 호출 차단
- 예상하지 못한 실행기 예외와 다른 요청 응답의 예약액 유지

전용 7건과 전체 서버 261건이 실패·건너뛰기 없이 통과했고 빌드도 성공했다. 전체 구성은 도메인 227건, 개발 API·계약 13건, PostgreSQL 예약·실행·연결/기본 차단 21건이다.

검사에 사용한 정책·금액·식별자와 AI 결과는 모두 인공 값이다. 실제 네트워크, 공급자 사용량·청구, 정책 본문·프롬프트, 후보 저장과 화면은 검사하지 않았다. API 계약과 Flyway 스키마도 변경하지 않았다.

## 남은 작업

- 실제 공급자 요청에 필요한 정책 본문·프롬프트·출력 검증 경계
- 현재 정책 개정 재검사와 후보 DB 저장의 원자성
- 호출 직전 중단과 서버 재시작 후 임대 펜싱·재확인 실행 연결
- 청구 대기 예약의 공급자 조회·정산과 초과 비용 대사
- 실제 AI 비용 배분·최대 비용 산정·외부 상한 검증
