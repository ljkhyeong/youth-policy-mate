# 실제 정책 저장·검색·상세 조회

2026-09-05 구현. 온통청년의 실제 성공 응답을 로컬 PostgreSQL에 저장하고 비회원이 목록과 상세를 조회하는 첫 기능이다. 정기 수집·전체 데이터 확보·개인별 자격 판정·로그인·관심 정책 저장·알림은 아직 연결하지 않았다.

같은 날 후속 작업으로 [직접 한 페이지 수집·실행 이력·저장 원본 재처리](limited-policy-collection.md)를 추가했다. 아래 로컬 캡처 반입 기록은 최초 조회 구현의 검증 범위다. 직접 수집 이후에는 요청 순번으로 오래된 응답을 차단하고, 해당 정책을 순번 없는 과거 캡처로 덮어쓰지 않는다.

## 실제 확인한 자료

- 인증키로 기본 목록 1건, 같은 정책의 상세 1건, 서울 필터 목록 1건, 서울 필터 목록 10건을 각각 요청했다. 전체 페이지를 순회하지 않았다.
- 마지막 목록의 `resultCode=200`, `result.pagging.pageSize=10`, 정책 10개를 확인했다. 이 응답의 전체 건수 표시는 481이었지만 적재한 정책은 첫 10건뿐이다.
- 목록·상세 배열 경로는 `result.youthPolicyList`다. 상세에는 `pagging`이 없고 분류·키워드 세 필드는 null이었다. 런타임 특화코드 이름은 `sbizCd`다.
- 원본 캡처는 `.local/ontong-api/`에서 Git 제외·소유자 전용 권한으로 보관한다. 테스트에는 첫 목록에서 담당자명·등록기관 계층 필드를 뺀 자료를 사용한다. 이것은 API의 현재 내용을 항상 보장하는 자료가 아니다.
- 지역 필터의 완전한 포함 규칙·페이지 정렬 안정성·호출 한도·삭제 의미는 미확인이다. [확인한 계약과 남은 항목](../research/ontong-api-contract.md)을 따른다.

## 실행

저장소 루트에서 실행한다. 발급된 인증키는 루트 `.env`의 `ONTONG_API_KEY`에만 둔다. 키는 채팅·명령 인수·화면에 넣지 않는다.

```sh
npm run db:up
npm run probe:ontong -- --region 11000 --page-size 10
```

점검 결과의 정상 코드·필드 구조를 확인한 뒤 아래 `캡처파일.json`을 실제 생성된 목록 파일명으로 바꿔 실행한다. 파일 경로는 저장소 루트 기준이며 상세 캡처는 받지 않는다.

```sh
npm run import:policy -- --args=.local/ontong-api/캡처파일.json
```

적재 명령은 최대 10개의 항목을 각각 짧은 트랜잭션으로 저장한다. 성공한 항목 뒤에 잘못된 항목이 있어도 뒤의 항목을 계속 처리한다. 실패 개수는 종료 코드 1과 고정 안내로 보고하며 원문·DB 예외는 출력하지 않는다. 실패 원본은 입력 캡처 파일에 남는다. 수집 실행 이력을 DB에서 관리하는 운영 배치는 아니다.

다른 터미널에서 각각 실행한다.

```sh
npm run dev:backend
npm run dev:web
```

- 공개 목록: `http://127.0.0.1:3000/policies`
- 상세: 목록의 정책 제목 또는 상세 보기로 이동한다.
- Next.js 서버의 공개 API 주소: `POLICY_API_BASE_URL`, 기본 `http://127.0.0.1:8080`. 바꾸려면 웹 프로세스 환경 또는 `frontend/.env.local`에서 설정한다. `NEXT_PUBLIC_*` 변수가 아니다.
- 키·원천 API는 점검 명령에서만 사용한다. 저장 후 화면 조회에는 온통청년 키나 외부 API 요청이 필요하지 않다.

## 저장과 적용 순서

Flyway V10이 다음 테이블을 만든다.

| 테이블 | 저장하는 내용 |
|---|---|
| `policies` | 문자열 원천 정책번호, 현재 내용·개정·마지막 캡처 수신 시각 |
| `policy_source_snapshots` | 정책번호, 캡처 식별 해시·수신 시각, 공백·null을 보존한 원천 정책 JSON |
| `policy_revisions` | 정책별 내부 개정 번호, 원본 스냅샷 연결, 해당 개정의 표시 내용 |

- 새 정책 행을 만들고 정책 행을 잠근 뒤 원본·개정·현재 내용을 같은 트랜잭션에서 반영한다. 외부 API 요청 중에는 DB 잠금을 유지하지 않는다.
- 같은 캡처와 같은 표시 규칙의 재전달은 원본과 개정을 다시 만들지 않는다. 표시 규칙 버전이 바뀌면 현재 캡처의 원본을 재사용해 새 개정을 만들 수 있다. 새 캡처의 같은 내용은 확인 시각만 갱신하고 원본 스냅샷을 남긴다.
- 조회수·등록/수정 일시만 바뀐 것은 새 개정으로 만들지 않는다. 그 밖의 원천 필드나 표시 규칙 버전이 바뀌면 새 개정으로 저장한다. 필드명 순서는 정렬하여 비교한다.
- A→B→A로 내용이 돌아오면 세 번째 개정이다. 전체 이력의 내용 해시에 유일 제약을 두지 않는다.
- 늦게 적재한 낮은 수신 시각의 캡처는 원본만 남기고 현재 내용을 덮지 않는다. 수신 시각은 온통청년의 개정 순서를 보장하지 않으므로 향후 자동 수집의 요청 순번·중첩 실행 제어를 대신할 수 없다.
- 원본의 업무 필드는 JSON 값으로 보존하고 원래 응답 바이트는 로컬 캡처에 남긴다. 운영 원본 저장소·보관 기간·수집 실패 감사 테이블은 후속 작업이다.

## 공개 계약과 화면

| 요청 | 동작 |
|---|---|
| GET `/api/v1/policies?q=검색어&page=1&pageSize=20` | 제목·설명 부분 문자열 검색. 검색어 최대 80자, 페이지 1~1000, 크기 1~50 |
| GET `/api/v1/policies/{policyNumber}` | 현재 개정·표시 내용·공식 출처·수집 시각 |

목록은 `items`, `page`, `pageSize`, `total`, `hasNext`를 제공한다. 수집 시각 내림차순·정책번호 오름차순으로 정렬한다. 검색의 `%`와 `_`는 와일드카드가 아닌 검색어 자체로 처리한다. 현재 표본은 10건이므로 전체 수집용 검색 성능·지역 필터는 후속 작업이다.

항상 있는 문자열의 빈 값은 빈 문자열로, 없는 표시 섹션·링크·지역은 빈 배열로 전송한다. 신청기간은 원문을 표시하며 상시·마감 코드의 빈 날짜에 가짜 날짜를 만들지 않는다. 시간대 없는 원천 수정 일시는 문자열로 제공한다. 서버의 실제 수집 시각만 `date-time`이다.

잘못된 검색은 400 `INVALID_SEARCH`, 없는 정책은 404 `POLICY_NOT_FOUND`, DB 조회 실패는 503 `POLICY_UNAVAILABLE`이다. 오류는 `code`, `message`를 제공하고 입력·DB 원문을 포함하지 않는다. 공개 GET 외 쓰기·관리 경로는 허용하지 않는다.

서버 DTO에서 `api/openapi.policy.json`과 `frontend/src/generated/policy-api.d.ts`를 생성한다. 기본 서버에서 명세를 공개하지 않는다. 생성용 명세 허용은 테스트 설정에만 있다.

화면은 기존 파란색·모바일 하단 메뉴를 유지하고 `정책 찾기`를 추가했다. 일부 정책만 제공한다는 안내, 목록 검색, 상세의 지원·신청 안내와 원문 이동, 수집 시각을 제공한다. 본문은 HTML로 실행하지 않고 텍스트로 표시한다. 링크는 HTTP(S)와 정상 호스트·사용자 정보 없음이 확인된 주소만 제공한다.

자격 코드를 자동 판정하거나 모든 원천 코드의 표시명을 해석하지 않는다. 0·0 같은 연령 숫자와 제한 여부 코드의 관계를 확정하기 전에는 숫자를 연령 범위처럼 표시하지 않는다. 따라서 상세에는 자격 추가 확인 안내와 공식 원문 경로를 항상 둔다. 사업 종료일을 신청 마감으로 대신하지 않으며 모집 상태·알림 날짜를 새로 계산하지 않는다. 공개 목록·상세는 서버 렌더링하지만 배포 전의 전역 검색엔진 차단 설정은 유지한다.

## 검증

```sh
npm run test:policy-catalog
npm run check:backend
npm run check:tools
npm run test:web
npm run check:api-types
npm run check:web
npm run build --workspace frontend -- --webpack
```

- 원천 파서 4건, PostgreSQL·공개 API·계약 7건을 포함한 서버 전체 363건: 실패·오류·건너뛰기 0건.
- 웹 56건, 점검 도구 8건, 린트·타입·생성 타입 일치 검사 통과.
- 기본 Turbopack 빌드는 실행 환경에서 내부 포트 생성이 차단됐다. Webpack 프로덕션 빌드와 모든 경로 생성을 확인했다.
- 실제 정책 10건을 로컬 DB에 적재했고 적재 프로세스 종료 후 별도 서버 프로세스에서 10건을 조회했다. 서버 미기동 오류 → 기동 후 다시 불러오기 → 실제 목록 복구를 확인했다.
- 모바일 390×844·데스크톱 1280×900에서 목록·상세 배치를 확인했다. 모바일 검색 입력 뒤 Tab·Enter로 장학금 2건 검색 → 국가근로장학금 상세 이동을 확인했다. 없는 검색어는 빈 결과, 없는 정책은 웹·API 모두 404, 운영 빌드의 `/dev/states`는 404였다. 브라우저의 기존 favicon 404는 남아 있다.
- 연령 표시 보정 후 전체 검사에서 테스트용 PostgreSQL 연결 시간 초과로 정책 테스트 7건이 시작되지 못했다. 코드 변경 없이 재실행한 최종 363건은 모두 통과했다.
