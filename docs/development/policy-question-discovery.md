# 공통요건 질문이 있는 정책 찾기

2026-09-05 구현. [PRD의 공개 탐색과 자격 안내](../PRD/0001_product-baseline/spec.md)에 따라 정책 목록과 기본 조건 확인 결과를 기존 공통요건 질문에 연결했다.

## 사용 흐름

- `/policies`에서 ‘조건 확인 질문 있음’을 선택하면 현재 질문을 제공하는 정책만 표시한다. 제공 범위는 [현재 구현 상태](../../HANDOFF.md#구현검증-범위)를 따른다. 최근 [청년내일저축계좌 신규 가입 질문](youth-tomorrow-savings-questions.md)을 추가했다.
- 검색어를 입력해도 필터를 유지한다. 페이지 이동은 검색어·필터를 유지하고, 필터 변경은 첫 페이지로 이동한다. ‘검색·필터 초기화’는 검색 입력과 필터를 함께 지운다.
- 질문이 있는 카드의 ‘질문에 답하기’는 상세의 질문 영역으로 이동한다. 화면 이동과 키보드 초점을 함께 맞춰 Tab으로 질문 시작 버튼에 접근할 수 있다.
- `/conditions`의 기본 조건 확인 결과에서도 질문 제공 여부와 이동 링크를 표시한다. 실제 현재 정렬에서는 응시료가 1페이지, 국가근로가 2페이지에 있다. 페이지별 정책 순서는 바꾸지 않았다.
- 기본 조건을 정책 질문의 답변으로 자동 변환하거나 저장하지 않는다. 상세에서 필요한 답변을 직접 선택한다.
- 검색 결과가 없다는 것은 자격 불충족이 아니다. 정책은 있지만 요청한 페이지가 비어 있으면 검색어·필터를 유지해 첫 페이지로 돌아갈 수 있다.

질문 제공 표시는 자격 충족·접수 중·추천 순위를 뜻하지 않는다. 최종 자격은 계속 추가 확인 필요이며, 기관 심사와 남은 예외는 각 질문의 안내 범위를 따른다.

## 서버와 계약

`GET /api/v1/policies`에 선택 인수 `questionsOnly`를 추가했다. 기본값은 `false`이며, `true`일 때 현재 검토한 질문이 있는 정책만 조회한다. 기존 검색어·페이지·페이지 크기의 범위는 유지한다.

`PolicySummary`와 `PolicyCheckItem`의 필수 불리언 `questionnaireAvailable`은 현재 원문·적용 시점에 맞는 질문 제공 여부다. 실제 Springdoc OpenAPI와 생성 TypeScript 계약을 함께 갱신했다. 기존 `operationId`와 15개 API 경로는 유지한다.

`ReviewedPolicyQuestions`가 적용 시점별 정책번호와 검토한 내용 해시를 제공한다. 목록 조회와 `PolicyQuestionService`가 같은 정의를 사용한다. 응시료의 서울 기준 2026년 제한은 기존 규칙을 따른다. 원문 해시가 바뀌거나 적용 연도가 지나면 필터와 표시에서도 제외하며, 상세의 질문 조회와 제출에서 최신 기준을 다시 검사한다.

`PolicyCatalogStore.list`는 질문 조건을 전체 건수와 페이지 조회 전에 적용한다. 정책번호·해시·검색어는 SQL 인수로 바인딩하고, 페이지마다 모든 정책을 읽어 걸러내거나 질문별 추가 조회를 하지 않는다. 건수와 항목은 같은 읽기 트랜잭션의 스냅샷을 사용한다. 목록 요청은 시각을 한 번 읽으며 기본 조건 확인은 기존 판정 시각을 목록에도 전달한다.

DB 스키마·원본·개정·사용자 조건 저장 방식은 변경하지 않았다. 새 정책을 수집하거나 규칙 검토 범위를 확대한 작업은 아니다.

## 검증

- 서버 전체 **422건**, 실패·오류·건너뜀 0, 빌드 통과. 새로운 PostgreSQL API 검사 2건과 기존 검사 보강으로 필터 전후 건수·페이지·검색, 질문 제공과 자격 상태 분리, 원문 변경·서울 새해·단일 비교 시각을 확인했다.
- 웹 **66건**, 실패 0. 생성 계약 일치·린트·타입·Webpack 빌드 통과. 목록 렌더링 검사 4건과 조회 검사 보강으로 필터 유지·전환·답변 링크·빈 결과·빈 페이지 복구를 확인했다.
- 실제 로컬 서버와 브라우저에서 전체 40건·필터 2건·검색 1건/0건·검색 및 필터 초기화·2페이지에서 필터 전환·빈 페이지 복구를 확인했다. 목록용 가짜 서버 응답은 사용하지 않았다.
- 실제 기본 조건 확인의 1·2페이지에서 두 질문 링크를 확인했다. 인공 생년월일·자치구·취업상태로 비회원 조회만 했으며 계정 저장은 요청하지 않았다.
- 모바일 390px·데스크톱 1280px에서 목록과 질문 이동을 확인했다. 모바일 조건 결과의 문구·링크도 확인했으며 가로 넘침이 없었다. Tab·Enter로 필터 선택, 링크 실행, 질문 영역 초점과 질문 시작을 확인했다. 응시료 3질문·국가근로 6질문과 빈 초기 답변을 확인했다.
- 선택상자의 키보드 답변 선택 전체 흐름은 이번 작업의 검증 대상이 아니다. 기존 상세 기록의 미확인 범위를 완료로 바꾸지 않는다.
- 전체 서버 테스트 종료 때 기존 Spring Session 정리 작업의 DB 연결 중단 경고가 다시 발생했다. JUnit 실패는 없으며 이번 변경에서 종료 순서는 수정하지 않았다.

로컬 서버와 웹을 새 빌드로 교체하고 정상 상태·실제 필터 결과를 확인했다. 외부 소셜 로그인·이메일 발송·정기 수집 설정은 변경하지 않았다. 다음 작업은 다른 정책의 조건·예외 검토 확대와 별도 공급자 설정 후 실제 연동 검증이다.
