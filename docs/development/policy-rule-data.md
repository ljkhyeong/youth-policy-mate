# 공고별 조건 데이터

현재 제공하는 11개 정책 모두 공고 데이터를 읽어 질문과 조건 비교를 제공한다. 연도·출생일 범위·만 나이·성적 구간·예외·질문 문구를 바꿀 때 Java 코드 수정이나 서버 재시작이 필요 없다. 새로운 비교 방식은 공통 코드 보완이 필요하다. 원문 충돌 안내와 검색용 모집 기간 보정은 질문 규칙과 별도로 유지한다.

## 적용 범위

- `PolicyRuleDefinition`: 질문·선택지·판정표·근거·적용 기간·모집 안내와 출생일·만 나이 연결.
- `PolicyRuleStore`: 변경 불가 버전과 현재 적용 버전. Flyway V22는 테이블·변경 방지, V23은 기존 검토 데이터 2건, V24는 나머지 9건을 추가한다.
- `PolicyQuestionService`: 현재 원문 해시와 기간을 확인하고 같은 데이터로 질문·판정·출생일 답변을 만든다.
- [관리자 조건 검토](policy-rule-review.md): 원문 변경·기간 만료·미등록 정책을 검색하고 직전 개정·질문·초안·근거를 확인한다. 규칙 등록·적용은 아래 운영 명령을 사용한다.
- `PolicyCatalogStore`: 목록의 질문 표시·필터와 기본 연령 정렬에도 같은 규칙을 적용한다. 질문·답변 제출은 SELECT 한 번, 목록·기본 비교는 규칙 조회 한 번과 건수·페이지 조회 두 번이다. 정책 수만큼 조회하지 않는다.

질문 답변은 저장하지 않는다. 적용한 규칙은 수정할 수 없고 새 버전으로 교체한다. 원문 변경이나 적용 기간 만료 시 질문·기본 연령 비교를 중단하며 `status`에 재검토 사유를 표시한다. 모집 마감과 규칙 적용 기간은 별개다. 기존 국가근로장학금에도 2026년 적용 종료를 명시했다.

## 운영 명령

저장소 루트에서 로컬 DB와 `.env` 설정을 사용한다. DB 접근 권한이 있는 운영자가 실행하며 운영 기록의 작업자는 실행 계정 이름이다. 공개 웹 API로 규칙을 수정하지 않는다. 명령은 정기 수집·알림·이메일 실행을 비활성화한다.

```sh
npm run rules:policy -- --args='status'
npm run rules:policy -- --args='export ba390000-0000-4000-8000-000000000001 /tmp/exam-next.json'
```

`export`는 기존 파일을 덮어쓰지 않는다. 파일에서 새 `ruleVersion`과 검토한 `contentHash`, 적용 기간, 질문·선택지·판정표·근거를 함께 수정한다. 이전 연도 문구나 선택지 이름도 확인한다. 적용 기간은 시간대가 있는 시각이며 시작 포함·종료 제외다. 서울 자정은 `+09:00`으로 적는다.

```sh
npm run rules:policy -- --args="draft /tmp/exam-next.json '공고 기준 변경'"
npm run rules:policy -- --args='publish <등록한 초안 UUID> exam-fee-2026-v1'
```

첫 적용이면 직전 버전에 `none`을 사용한다. 월별 정책의 직전 버전은 `status`에 나온 저장 버전이다. 질문 응답에 붙는 `-2026-09` 같은 기준 월은 입력하지 않는다. `publish`는 현재 적용 기간, 원문 해시, 직전 버전을 확인한다. 원문이 없거나 바뀌었으면 적용할 수 없다. 같은 직전 버전으로 동시에 적용하면 하나만 성공한다. 정책 수집과 같은 정책 행을 잠그므로 수집 중 원문 변경과 적용이 엇갈리지 않는다. 미래에 적용할 버전은 초안으로 보관했다가 적용일에 공개한다. 예약 적용은 제공하지 않는다.

적용 후 `status`와 해당 정책의 질문·결과를 확인한다. 되돌릴 때도 새 버전으로 초안을 만든다. DB 직접 수정이나 이전 적용 버전 재공개를 운영 절차로 사용하지 않는다.

## 판정표 형식

각 판정 항목의 `cases`를 위에서부터 비교해 첫 일치 행을 적용한다. `when` 안의 질문은 모두 일치해야 하며 선택지 배열은 그중 하나와 일치하면 된다. 일치하지 않으면 `UNKNOWN`과 `unknownExplanation`을 반환한다. `when`의 선택지 `""`는 미응답을 뜻하며 `UNKNOWN` 선택지와 구분한다. 실제 답변 API는 빈 선택지를 받지 않고 해당 질문을 생략하게 한다. 임의 수식·JavaScript·SQL은 실행하지 않는다.

```json
{
  "when": {"grade": ["BELOW_70"], "gradeException": ["NONE"]},
  "outcome": "NOT_MET",
  "explanation": "입력한 성적은 기준에 맞지 않고 적용 제외 대상에도 해당하지 않아요."
}
```

성적·소득 기준은 충족 행과 확인된 예외 행을 먼저 두고, 명확한 불충족 행을 뒤에 둔다. 예외를 확인하지 못했으면 불충족으로 단정하지 않는다. `remainingChecks`에 기관별 심사·참여 제한 등 남은 확인을 기록한다. 현재 형식은 공통요건 비교에 한정하며 최종 자격은 추가 확인으로 유지한다.

`birthBinding`은 포함 경계인 `minimumInclusive`·`maximumInclusive` 중 하나 이상과 구간별 선택지를 연결한다. 해당 질문만으로 판단할 수 있어야 하며, 다른 질문의 군복무·예외 답변이 필요한 조건을 단순 출생일 범위로 등록하지 않는다. `ageBinding`은 만 나이의 최소·최대 연령과 구간별 선택지를 연결한다. `referenceDate`를 지정하면 그 날짜, 생략하면 서울의 현재 날짜로 기존 `AgeConditionEvaluator`에서 계산한다. 상한이 없으면 최대 연령을 생략한다. 병역 예외가 필요한 상한 초과는 확인 대기 선택지로 연결하며 복무기간을 생년월일에서 추정하지 않는다.

`monthly: true`는 기준 월을 질문 범위와 답변 버전에 붙인다. 서울 자정에 달이 바뀌면 이전 답변을 거부한다. `periodNotice`는 모집 전·접수 중·마감 뒤 질문 안내를 선택한다. 검색용 모집 상태나 실제 접수 기간을 덮어쓰지는 않는다.

여러 답변을 함께 표시하는 항목은 `providedAnswers`의 질문·접두어와 `separator`를 사용한다. 이사비처럼 선택한 비용에 따라 추가 안내가 달라지면 `remainingVariant`의 질문·선택지별 문구로 `remainingChecks`의 지정 위치를 바꾼다. 위치는 0부터 시작하며 존재하는 항목만 바꿀 수 있다.

## 입력 재사용

`/conditions`에서 확인한 생년월일을 화면 메모리에만 두고, 상세의 ‘질문에 답하기’를 누르면 `POST /api/v1/policies/{number}/question-prefill`에 현재 개정·규칙 버전과 함께 보낸다. 9개 정책의 출생일·연령 답변을 채우고 적용 사실을 표시한다. 국가근로장학금·보증료 지원의 답변은 생년월일에서 만들지 않는다. 학적·소득 등 다른 답변은 추정하지 않는다.

생년월일은 URL·브라우저 저장소·DB에 남기지 않는다. 조건 수정·입력 삭제·질문 답변 삭제·계정 전환·새로고침 시 재사용 값을 지운다. 답변 수정 중 늦게 도착한 응답은 무시한다. 원문·규칙이 바뀌면 409로 이전 답변을 지우고 새 질문을 불러온다.

## 검증

2026-09-12 로컬 검증. JDK·재실행 기준은 [검증 절차](verification-workflow.md)를 따른다.

- 기존 11개 정책 테스트와 이전한 9개 정책의 조건별 선택지 조합·혼합 답변에서 판정·근거·표시 값·추가 안내 일치. 이전 구현은 고정된 테스트 자료로만 유지한다. 공고 값을 바꿀 때 운영 Java 클래스를 추가하지 않는다.
- 기존 만 나이 모듈에서 윤년·서울 자정·병역 예외 경계와 기본 비교·답변 변환 일치 확인. K-패스는 월이 바뀌면 이전 답변을 거부한다.
- 실제 PostgreSQL에서 11개 정책의 질문 제공과 9개 연령 답변 변환, 월별 정책의 연령 기준 변경 즉시 반영, 이전 버전 거부 확인. 원문 변경·기간 만료·동시 적용 충돌·적용 버전 변경 방지 테스트도 통과했다.
- `npm run verify -- check:backend` 통과: `.local/verification/1789167190294-2c966168.log`. 관련 규칙 검사는 `/tmp/youth-rule-expansion-unit.log`에 있다. DB 검사에서 기존 만료 안내 문구 단언을 수정한 뒤 전체 검사에서 재확인했다.

- 로컬 DB V24 적용. K-패스의 생년월일 재사용·기준 월·첫 가입 월 예외, 청년주택드림청약통장의 병역 예외 확인 대기를 실제 화면에서 확인했다. 390px 모바일 가로 넘침이 없다. 운영 명령의 초안 등록·적용·내보내기 흐름은 이전 검증을 재사용했다.

AI 공급자 호출·추출 결과 저장·자동 초안 생성은 아직 연결하지 않았다. 다음 작업은 수집·AI 후보를 원문 개정에 연결해 저장하고 검토 가능한 규칙 초안으로 만드는 것이다. 연도만 바꿔 이전 공고를 자동 이월하지 않는다.
