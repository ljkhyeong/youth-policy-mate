# 공고별 조건 데이터

응시료 지원과 국가근로장학금은 공고 데이터를 읽어 질문과 조건 비교를 제공한다. 연도·출생일 범위·성적 구간·예외·질문 문구를 바꿀 때 Java 코드 수정이나 서버 재시작이 필요 없다. 나머지 9개 정책은 기존 구현이며, 새로운 비교 방식은 공통 코드 보완이 필요하다.

## 적용 범위

- `PolicyRuleDefinition`: 질문·선택지·판정표·근거·적용 기간과 출생일 연결.
- `PolicyRuleStore`: 변경 불가 버전과 현재 적용 버전. Flyway V22는 테이블·변경 방지, V23은 기존 검토 데이터 2건을 추가한다.
- `PolicyQuestionService`: 현재 원문 해시와 기간을 확인하고 같은 데이터로 질문·판정·출생일 답변을 만든다.
- `PolicyCatalogStore`: 목록의 질문 표시·필터와 기본 연령 정렬에도 같은 규칙을 적용한다. 질문·답변 제출은 SELECT 한 번, 목록·기본 비교는 규칙 조회 한 번과 건수·페이지 조회 두 번이다. 정책 수만큼 조회하지 않는다.

질문 답변은 저장하지 않는다. 적용한 규칙은 수정할 수 없고 새 버전으로 교체한다. 원문 변경이나 적용 기간 만료 시 질문·기본 연령 비교를 중단하며 `status`에 재검토 사유를 표시한다. 모집 마감과 규칙 적용 기간은 별개다. 기존 국가근로장학금에도 2026년 적용 종료를 명시했다.

## 운영 명령

저장소 루트에서 로컬 DB와 `.env` 설정을 사용한다. DB 접근 권한이 있는 운영자가 실행하며 운영 기록의 작업자는 실행 계정 이름이다. 공개 웹 API로 규칙을 수정하지 않는다. 명령은 정기 수집·알림·이메일 실행을 비활성화한다.

```sh
npm run rules:policy -- --args='status'
npm run rules:policy -- --args='export ba390000-0000-4000-8000-000000000001 /tmp/exam-next.json'
```

`export`는 기존 파일을 덮어쓰지 않는다. 파일에서 새 `ruleVersion`과 검토한 `contentHash`, 적용 기간, 질문·선택지·판정표·근거를 함께 수정한다. 이전 연도 문구나 선택지 이름도 확인한다. 적용 기간은 시간대가 있는 시각이며 시작 포함·종료 제외다. 서울 자정은 `+09:00`으로 적는다.

```sh
npm run rules:policy -- --args="draft /tmp/exam-next.json '공고 기준 변경'"
npm run rules:policy -- --args='publish <등록한 초안 UUID> exam-fee-2026-v1'
```

첫 적용이면 직전 버전에 `none`을 사용한다. `publish`는 현재 적용 기간, 원문 해시, 직전 버전을 확인한다. 원문이 없거나 바뀌었으면 적용할 수 없다. 같은 직전 버전으로 동시에 적용하면 하나만 성공한다. 정책 수집과 같은 정책 행을 잠그므로 수집 중 원문 변경과 적용이 엇갈리지 않는다. 미래에 적용할 버전은 초안으로 보관했다가 적용일에 공개한다. 예약 적용은 제공하지 않는다.

적용 후 `status`와 해당 정책의 질문·결과를 확인한다. 되돌릴 때도 새 버전으로 초안을 만든다. DB 직접 수정이나 이전 적용 버전 재공개를 운영 절차로 사용하지 않는다.

## 판정표 형식

각 판정 항목의 `cases`를 위에서부터 비교해 첫 일치 행을 적용한다. `when` 안의 질문은 모두 일치해야 하며 선택지 배열은 그중 하나와 일치하면 된다. 일치하지 않으면 `UNKNOWN`과 `unknownExplanation`을 반환한다. 임의 수식·JavaScript·SQL은 실행하지 않는다.

```json
{
  "when": {"grade": ["BELOW_70"], "gradeException": ["NONE"]},
  "outcome": "NOT_MET",
  "explanation": "입력한 성적은 기준에 맞지 않고 적용 제외 대상에도 해당하지 않아요."
}
```

성적·소득 기준은 충족 행과 확인된 예외 행을 먼저 두고, 명확한 불충족 행을 뒤에 둔다. 예외를 확인하지 못했으면 불충족으로 단정하지 않는다. `remainingChecks`에 기관별 심사·참여 제한 등 남은 확인을 기록한다. 현재 형식은 공통요건 비교에 한정하며 최종 자격은 추가 확인으로 유지한다.

`birthBinding`은 포함 경계인 `minimumInclusive`·`maximumInclusive` 중 하나 이상과 구간별 선택지를 연결한다. 해당 질문만으로 판단할 수 있어야 하며, 다른 질문의 군복무·예외 답변이 필요한 조건을 단순 출생일 범위로 등록하지 않는다. 만 나이·월별 이용 실적 등 다른 비교 방식은 이번 형식에 억지로 넣지 않는다.

## 입력 재사용

`/conditions`에서 확인한 생년월일을 화면 메모리에만 두고, 상세의 ‘질문에 답하기’를 누르면 `POST /api/v1/policies/{number}/question-prefill`에 현재 개정·규칙 버전과 함께 보낸다. 응시료 지원의 출생일 답변을 채우고 적용 사실을 표시한다. 학적·소득 등 다른 답변은 추정하지 않는다.

생년월일은 URL·브라우저 저장소·DB에 남기지 않는다. 조건 수정·입력 삭제·질문 답변 삭제·계정 전환·새로고침 시 재사용 값을 지운다. 답변 수정 중 늦게 도착한 응답은 무시한다. 원문·규칙이 바뀌면 409로 이전 답변을 지우고 새 질문을 불러온다.
