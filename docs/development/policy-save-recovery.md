# 정책 저장 상태와 오류 복구

정책 상세에서 저장 목록을 조회하지 못하면 ‘미저장’으로 표시하지 않는다. 저장 상태를 확인할 때까지 변경 버튼을 비활성화하고 **저장 상태 다시 불러오기**를 제공한다.

## 동작

- 로그인 정보와 필요한 저장 목록을 모두 확인한 뒤 저장·해제를 허용한다. 비회원은 기존 로그인 경로로 이동하고 로그인 후 해당 정책을 다시 확인한다. 자동 저장하지 않는다.
- 저장 중에는 `저장 중…`, 해제 중에는 `저장 해제 중…`으로 표시하고 중복 클릭을 차단한다.
- 변경 요청의 응답을 받지 못하면 성공·실패를 단정하지 않는다. 추가 변경을 막고 로그인 정보와 저장 목록을 다시 조회한다. 재조회가 저장·해제 요청을 재전송하지는 않는다.
- 401 응답에는 로그인 버튼을 제공하고 돌아올 정책번호를 유지한다. 다른 오류에는 저장 상태 재조회 경로를 제공한다.
- 정책 상세를 떠나면 진행 중 요청을 취소하고 늦은 응답을 무시한다. 취소 전에 서버에 반영된 저장·해제까지 되돌리는 기능은 아니다.
- 재조회와 변경 작업이 끝나면 사용 가능한 저장 버튼 또는 재조회 버튼으로 키보드 초점을 돌린다. 상태를 모를 때는 `aria-pressed=false`로 안내하지 않는다.

`SavePolicyButton`은 로딩·확인 완료·변경 중·확인 실패를 구분한다. 기존 `memberApi`와 저장 API를 사용하며 인증·CSRF·저장/알림 취소 규칙·API 계약은 변경하지 않았다. 정책을 바꿀 때는 기존 `PolicyArticle`의 정책번호 `key`로 버튼 상태를 새로 만든다.
