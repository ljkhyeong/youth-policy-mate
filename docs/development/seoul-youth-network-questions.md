## 질문과 결과

| 질문 | 비교 기준 |
|---|---|
| 공고의 출생일 범위 | 1986.1.2.~2007.1.1. 출생자(양 끝 포함)가 기본 대상이다. 의무복무 제대군인은 복무기간에 따른 상한 연장 후 연령 기준을 충족한다고 담당 기관에서 확인한 경우만 충족한다. 단순 군필 여부나 연장 인정만으로 처리하지 않는다. |
| 서울 거주 또는 생활권 | 서울 거주, 서울 소재 대학 재학·휴학, 직장 재직·휴직 중 하나면 해당 항목을 충족한다. 서울 사업장은 담당 기관의 생활권 증빙 인정을 확인한 경우만 반영한다. 서울에 살지 않는다는 이유만으로 불충족 처리하지 않는다. |
| 연임 제한 | 2023~2025년 2차례 연임 여부를 묻는다. 중간 공백 등으로 불분명한 경우는 추가 확인으로 남긴다. |
| 과거 위원 활동에 따른 제한 | 과거 징계·해촉 등 위촉 제한 사유의 유무를 확인한다. 담당 기관에서 제한 사유를 확인한 경우 해당 항목만 불충족으로 표시한다. |

군복무 연장 여부가 미확인이면 연령 불충족을 확정하지 않는다. 연령 예외가 확인돼도 연임·위촉 제한을 면제하지 않는다. 미응답은 ‘미응답’으로 표시하며 모두 충족하는 답변을 기본값으로 넣지 않는다.

비교한 네 조건의 결과와 별개로 전체 `status`는 `NEEDS_REVIEW`다. 활동신청서 3개 문항 총 500자 이상 작성, 거주·생활 증빙, 사전교육 인증, 퀴즈 70점 이상, 우선선발 서류와 종합 평가는 별도 확인 사항이다. 우선선발 증빙 미제출을 일반선발 탈락으로 처리하지 않는다. 생년월일·주소·증빙파일·징계 사유를 받지 않으며 선택한 답변은 비교 시에만 전송하고 저장하지 않는다.

## 모집 기간과 기준 변경

공고의 접수 기간은 서울 시각 2026-05-20 09:00~2026-05-29 17:00이다. 시작 전에는 접수 전, 마감 시각부터는 접수 마감을 질문·결과 안내에 표시한다. 접수 마감은 개인의 연령·지역·이력 결과를 바꾸지 않는다. 현재 제공하는 질문은 이미 끝난 하반기 모집의 조건 확인이며 신규 신청 안내가 아니다.

`SeoulYouthNetworkRules`를 `ReviewedPolicyQuestions`와 `PolicyQuestionService`에 등록했다. 기존 질문·결과 API, 목록의 질문 표시와 필터, 상세 화면을 사용한다. API 구조·생성 타입·프런트엔드 소스·DB 스키마는 바꾸지 않았다.

검토한 내용 해시·현재 개정·규칙이 다르면 이전 답변을 409 `POLICY_CHANGED`로 거절한다. 한 요청은 같은 시각으로 검사한다. 서울 기준 2027년부터 질문과 필터 제공을 중단하며 다음 모집으로 기준을 옮기지 않는다. 이 제한은 검토 범위의 종료이며 공고의 위원 활동기간 종료일을 변경한 것이 아니다.

공식 공고를 별도로 자동 감시하지는 않는다. 온통청년 반영 전 공고가 바뀌면 다시 검토해야 한다.

## 검증

- 규칙 검사 6건과 PostgreSQL API 검사 2건을 추가했다. 서울 거주·대학·직장의 대체 경로, 군복무 연장, 이력 제한·미확인, 접수 시작·마감과 서울 연말, 원문·개정·규칙 변경을 확인한다.
- 정책 관련 52건, 서버 전체 **448건**과 빌드가 통과했다. 실패·오류·건너뜀 0이며 실제 OpenAPI와 저장 계약의 일치 검사도 통과했다.
- API 구조와 웹 소스를 변경하지 않아 웹 테스트·빌드는 재실행하지 않았다. 실제 화면은 새 서버와 기존 웹 빌드를 사용한다.
- 실제 목록의 질문 제공 5건과 상세 링크를 확인했다. 실제 서버 응답으로 미응답, 서울 소재 대학·직장, 군복무 연장과 이력 제한, 연장 확인 중, 서울 거주·생활권 없음, 인정된 사업장 증빙을 확인했다. 모든 결과에 해당 모집의 마감 안내가 남는다.
- 모바일 390px·데스크톱 1280px에서 선택지·결과와 가로 넘침을 확인했다. 답변 수정 시 결과 삭제, 답변 지우기, 새로고침 초기화, Enter로 질문 시작·제출과 결과 제목 초점을 확인했다. 기본 선택상자의 키보드 답변 선택 전체 흐름은 이번 검증에 포함하지 않았다.
- 새 로컬 서버의 정상 상태와 정책 40건 중 질문 제공 5건을 확인했다. 실제 소셜·SMTP·수집 일정·`.env`는 변경하지 않았다.
- 전체 검사 종료 시 기존 Spring Session 정리 작업의 DB 연결 중단 경고가 재현됐다. JUnit 실패는 없으며 종료 순서는 이번 변경에 포함하지 않았다.
