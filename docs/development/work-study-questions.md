# 국가근로장학금 공통요건 질문과 비교

2026-09-12부터 질문·판정은 [공고별 조건 데이터](policy-rule-data.md)로 관리한다. 아래 원문 검토 기준은 유지하며 운영 코드의 정책별 클래스는 제거했다.

2026-09-05에 실제 정책 한 건의 추가 질문을 연결했다. 제품의 전체 자격 상태와 부분 비교 기준은 [PRD 5절](../PRD/0001_product-baseline/spec.md#5-자격-안내와-추천-근거)을 따른다. 다른 정책과 대학별 선발요건까지 검토한 기능은 아니다.

## 확인한 근거와 적용 범위

- 온통청년 정책번호: `20260821005400113348`, 로컬 확인 개정: `2`, 대상: 2026년 2학기 국가근로장학금.
- 공식 확인 페이지: [한국장학재단 국가근로장학금 지원자격](https://www.kosaf.go.kr/ko/scholar.do?pg=scholarship05_04_01), 확인일 2026-09-05.
- 적용 규칙: `work-study-2026-2-v1`.
- 검토한 온통청년 원문의 정규화 내용 해시: `a1523aaa7fc8ac8097c70cf4830048c9c6f8430464864823206778f7c82c5e5d`.

재단 안내에서 국적·지원 대상 대학의 학적·직전학기 성적·학자금 지원구간을 확인했다. 재단과 대학의 선발요건을 함께 충족해야 하므로, 이 구현은 재단의 공통요건 비교만 제공한다. 대학별 참여 제한, 중복 참여, 차수 운영과 서류·동의 일정은 남은 확인 사항이다. 원문에 표시된 신청 마감과 서류·가구원 동의 마감은 서로 다른 절차이며 이 판정 결과로 접수 상태를 계산하지 않는다.

성적은 대학이 제공한 100점 기준의 70점 이상을 비교한다. 다른 평점을 임의 환산하지 않는다. 소득은 2026년 2학기 재단 산정 9구간 이하를 비교하며 급여액으로 지원구간을 추정하지 않는다. 적용 제외가 가능한 대상인지에 관한 사유나 민감한 증빙은 받지 않고, 재단 또는 대학에서 적용 제외를 확인받았는지만 질문한다.

| 답변 | 항목 결과 |
|---|---|
| 기준 구간 충족 | 충족 |
| 재단·대학에서 기준 적용 제외를 확인받음 | 해당 답변 기준 충족. 서비스가 증빙을 검증한 것으로 표시하지 않음 |
| 기준 미달이며 적용 제외 대상 아님 | 불충족 |
| 기준 미달이지만 적용 제외 여부 미확인 | 추가 확인 |
| 직전학기 성적 없음·지원구간 미산정·미응답·모름 | 추가 확인 |

## 서버와 화면

`WorkStudyRules`는 네 항목을 비교한다. `commonCriteriaStatus`는 검토한 공통요건의 결과다. 전체 `status`는 대학별 검토가 남아 있으므로 `NEEDS_REVIEW`를 유지한다. 화면도 ‘확인한 공통요건 충족’과 ‘최종 신청 자격 · 추가 확인 필요’를 함께 표시한다. 기존 `/conditions` 전체 목록을 개인별 추천 순위로 바꾸지 않는다.

| API | 동작 |
|---|---|
| `GET /api/v1/policies/{number}/questions` | 현재 개정에서 검토한 질문과 선택지 조회 |
| `POST /api/v1/policies/{number}/evaluation` | 개정·규칙 버전·추가 답변으로 비교. 답변 저장 없음 |

정책 상세의 ‘내 조건으로 확인하기 → 공통요건 확인하기’에서 답변을 입력한다. 답변은 화면 상태로만 유지하다 비교 버튼을 누를 때 서버에 보내며, DB나 브라우저 저장소에 보관하지 않는다. 답변 수정·삭제 시 이전 결과를 지우고 진행 중 요청을 취소한다. 통신 실패 시 답변을 유지하고 재시도할 수 있다. 정책 변경 응답은 답변을 지우고 최신 질문을 다시 조회한다.

존재하지 않는 정책은 404, 잘못된 질문·선택지·중복 답변은 400, 개정·규칙·검토한 내용이 다르면 409 `POLICY_CHANGED`, 저장소 장애는 503이다. 질문과 결과는 `no-store`다. Next.js는 숫자 정책번호로 정해진 두 경로만 중계하고 회원 쿠키·CSRF·응답 세션 쿠키를 이 공개 흐름에서 제외한다. 비교 요청은 저장 작업이 아니므로 서버 CSRF 예외이며, 웹 중계는 같은 출처의 요청인지 검사한다.

정책 조회와 내용 해시 확인은 같은 PostgreSQL 읽기 스냅샷을 사용한다. 수집한 내용이 달라지면 기존 질문을 중단한다. 아직 검토하지 않은 다른 정책에도 질문을 만들어내지 않는다. 새 원문 검토가 끝나면 적용 규칙·해시와 근거를 함께 변경해야 한다. 재단 사이트의 변경을 독립적으로 감시하는 기능은 없으므로 온통청년 반영 전 변경은 별도 재검토가 필요하다.

## 검증

```bash
./backend/gradlew -p backend test --tests 'kr.youthpolicymate.policy.catalog.*' --no-daemon
npm run generate:api
npm run test:web
npm run check:web
npm run check:api-types
npm run build --workspace frontend -- --webpack
```

규칙 단위 검사는 공통요건과 전체 상태 분리, 미확인 예외, 명시적 불충족, 성적·지원구간 없음, 확인된 적용 제외와 잘못된 답변을 확인한다. PostgreSQL API 검사는 원문 해시·개정·규칙 변경, 빈 답변과 입력 오류, 공개 접근·캐시 제외를 확인한다. API의 규칙 활성화 자료는 인공 내용이므로 정책 원문 검토를 대신하는 자료로 사용하지 않는다. 실제 로컬 원문과 연결한 브라우저 검증은 별도로 기록한다.

Tab 초점 이동은 확인했지만 자동화의 방향키·Enter가 기본 선택상자 값을 바꾸지 못해 키보드만으로 선택 완료하는 흐름은 미확인이다.
