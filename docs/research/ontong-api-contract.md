# 온통청년 API 조사와 확인할 계약

- 조사일: 2026-08-30
- 상태: 공식 명세·코드 정의서·공개 정책 화면 확인. 인증키를 사용한 성공 응답은 미확인
- 제품 기준: [PRD-0001](../PRD/0001_product-baseline/spec.md)
- 설계 초안: [정책 수집·판정 데이터 구조](../design/policy-data-model.md)

## 1. 이번에 확인한 범위

현재 청년정책 API는 `https://www.youthcenter.go.kr/go/ythip/getPlcy`다. 공식 제공목록에서 **청년정책API** 탭을 선택하면 요청·응답 표가 로딩된다. 페이지 초기 HTML과 검색 도구에 남아 있는 `/opi/youthPlcyList.do`, `openApiVlak`, `pageIndex`, `display` 예시를 현재 계약으로 사용하지 않는다. [공식 제공목록](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiDoc/48)

확인 수준을 다음과 같이 구분한다.

| 구분 | 이번에 확인한 내용 | 아직 확인하지 못한 내용 |
|---|---|---|
| 공식 명세 | 현재 URL, 인증 파라미터, 목록·상세 구분, 요청 필터와 응답 필드명 | 실제 JSON 객체 구조, 필드 누락·널·빈 문자열, 값의 형식 |
| 코드 정의서 | 신청기간·소득·취업·학력 등의 코드 의미 | 실제 응답의 코드 사용 현황, 복수 값 구분 방식 |
| 공개 정책 화면 | 기간·추가 조건·신청 주체에 대한 대표 사례 2건 | 해당 화면과 Open API 응답이 동일한지 여부 |
| 키 없는 실제 요청 | GET, `pageNum=1`, `pageSize=1`, `rtnType=json` 요청에 HTTP 400과 HTML 오류 문서 반환 | 유효 키의 성공 응답, 인증 오류 코드, 할당량 초과 응답 |

HTTP 400 한 사례만으로 모든 인증 실패가 같은 응답이라고 일반화하지 않는다. `rtnType=json`을 보냈다는 이유로 오류 본문까지 JSON이라고 가정하지 않는다. 공개 웹 화면도 Open API 성공 응답 샘플을 대신하지 않는다.

## 2. 인증·이용 조건

- 온통청년 로그인 후 마이페이지의 OPEN API 메뉴에서 인증키를 신청한다. 공식 이용 안내는 심사 후 발급하는 절차를 안내한다. 회원가입·신청서 제출은 이번 작업에서 하지 않았다. [이용 안내](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiGuide)
- 공공데이터포털에는 LINK형 API, JSON+XML, 무료, 이용허락범위 제한 없음으로 표시되어 있다. 개발단계 자동승인·운영단계 심의승인이라는 포털 표기만으로 온통청년 인증키가 즉시 발급된다고 단정하지 않는다. [공공데이터포털](https://www.data.go.kr/data/15143273/openapi.do)
- 숫자로 된 호출 한도와 최대 페이지 크기는 확인하지 못했다. 무료라는 표기는 무제한 호출·가용성 보장을 뜻하지 않는다.
- 인증키는 서버 측 비밀 설정으로 관리한다. 브라우저 코드, `NEXT_PUBLIC_*`, 저장소, 원본 수집 기록과 요청 URL 로그에 포함하지 않는다. 값은 채팅으로 공유하지 않는다.

## 3. 요청 계약

다음은 공식 표의 필드명이다. 실제 기본값·최댓값·조건 조합은 아직 검증하지 않았다.

| 파라미터 | 명세의 의미 | 구현 시 확인할 점 |
|---|---|---|
| `apiKeyNm` | 발급받은 인증키, 필수 String | 서버가 주입하며 요청 URL 전체를 로그에 남기지 않음 |
| `pageNum`, `pageSize` | 페이지 번호·크기, Number | 시작 번호, 최대 크기, 마지막 페이지, 정렬 안정성 |
| `pageType` | String, `1` 목록 / `2` 상세 | 상세 조회 시 필수 조합과 목록 대비 필드 차이 |
| `plcyNo` | 정책번호, String | 상세 조회 대상 식별자. 제목으로 대체하지 않음 |
| `rtnType` | `xml` / `json` | 명세상 JSON 사용 가능. 실제 성공·실패 본문 확인 필요 |
| `plcyNm`, `plcyExplnCn` | 정책명·정책설명 검색 | 정확 일치·부분 일치, 여러 조건의 결합 의미 |
| `plcyKywdNm` | 쉼표로 구분한 키워드명 | 복수 키워드의 AND/OR 의미 |
| `zipCd` | 5자리 법정시군구코드, 쉼표로 복수 전달 | `11000`은 서울, `11680`은 강남구라는 명세 예시만 확인. 전국 정책 포함·상하위 지역 확장은 미검증 |
| `lclsfNm`, `mclsfNm` | 쉼표로 구분한 대분류·중분류명 | 현재 API가 받는 이름과 분류 변경 시 처리 |

공식 요청 표에서 수정시각 이후 조회, 삭제 목록, 정렬 키를 확인하지 못했다. 응답에 최종수정일이 있다는 것만으로 증분 수집 기능이 있다고 가정하지 않는다.

## 4. 사용할 응답 필드

명세는 아래 개별 값들을 String으로 표시한다. 나이·금액·날짜처럼 보여도 수집 경계에서 원문 값을 보존한 뒤 파싱한다. XML의 `youthPolicyList` 표기만으로 JSON의 최상위 경로를 확정하지 않는다.

| 용도 | 명세 필드 | 정규화·판정 기준 |
|---|---|---|
| 식별·변경 확인 | `plcyNo`, `frstRegDt`, `lastMdfcnDt` | 정책번호는 문자열. 일시의 형식·시간대·정렬 보장은 미확인 |
| 표시·검색 | `plcyNm`, `plcyExplnCn`, `plcySprtCn`, `plcyKywdNm`, `lclsfNm`, `mclsfNm` | HTML·줄바꿈·빈 값 확인. 설명문도 자격 조건 검토 대상 |
| 기관·승인 | `pvsnInstGroupCd`, `plcyAprvSttsCd`, `sprvsnInstCd`, `sprvsnInstCdNm`, `operInstCd`, `operInstCdNm` | 기관 분류를 거주 조건과 혼동하지 않음. Open API가 승인된 정책만 주는지는 미확인 |
| 지역 | `zipCd` | 코드 집합 후보. 빈 값이나 중앙부처 분류를 전국 허용으로 바꾸지 않음 |
| 연령 | `sprtTrgtAgeLmtYn`, `sprtTrgtMinAge`, `sprtTrgtMaxAge` | Y/N 실제 의미와 연령 기준일 확인. 기준일 전용 필드는 명세에서 찾지 못함 |
| 취업·학력·전공 | `jobCd`, `schoolCd`, `plcyMajorCd` | 실제 복수 값 형식·관계와 서술형 예외 확인 |
| 소득 | `earnCndSeCd`, `earnMinAmt`, `earnMaxAmt`, `earnEtcCn` | 개인/가구, 금액 단위, 적용 연도, 포함 경계가 확정되지 않으면 비교 보류 |
| 그 밖의 조건 | `mrgSttsCd`, `sBizCd`, `addAplyQlfcCndCn`, `ptcpPrpTrgtCn`, `etcMttrCn` | 필요한 사용자 정보가 없으면 추가 확인. 새 민감정보 수집 항목을 자동 추가하지 않음 |
| 신청기간 | `aplyPrdSeCd`, `aplyYmd` | 신청 일정의 근거. 복수 기간·상시·마감·시각 유무를 따로 확인 |
| 사업기간 | `bizPrdSeCd`, `bizPrdBgngYmd`, `bizPrdEndYmd`, `bizPrdEtcCn` | 사업 운영 기간. 신청 마감일로 대체하지 않음 |
| 신청 안내 | `plcyAplyMthdCn`, `srngMthdCn`, `sbmsnDcmntCn`, `aplyUrlAddr`, `refUrlAddr1`, `refUrlAddr2` | 공식 안내와 링크에 사용. 신청절차 본문에도 자격 제한이 있을 수 있음 |
| 지원 규모 | `sprtSclLmtYn`, `sprtSclCnt`, `sprtArvlSeqYn` | 선착순·소진 가능성과 날짜 마감을 구분 |
| 조회 지표 | `inqCnt` | 조회수만 바뀌었다고 사용자에게 정책 변경 알림을 보내지 않음 |

기본계획 번호, 등록기관 계층, 담당자명 등 나머지 필드는 원본에 남길 수 있지만 MVP의 개인 자격 판정 입력으로 사용하지 않는다. 현재 이 표는 서버 DTO나 DB 스키마가 아니다.

### 문서끼리 일치하지 않는 부분

- API 표는 `bizPrdSeCd`, 정의서는 `bizPrdSecd`로 표기한다.
- API 표는 `sBizCd`, 정의서는 `sbizCd`로 표기한다.
- 코드 정의서의 대분류에는 `교육`, `복지문화`, `참여권리`가 있지만 현재 웹 검색 화면에는 `교육·직업훈련`, `금융·복지·문화`, `참여·기반` 계열의 표시명이 보인다. 웹 표시명을 API 요청 값으로 바로 복사하지 않는다.

실제 응답을 받기 전에는 어느 이름이 런타임 계약인지 확정하지 않는다. 모든 필드명을 소문자로 바꾸거나 여러 별칭을 무조건 허용하여 차이를 숨기지 않는다.

## 6. 공개 정책에서 확인한 위험 사례

아래는 웹 화면 관찰이며 Open API 원시 응답이나 공식 신청 자격의 최종 검증 결과가 아니다. 개인정보 없이 정책번호와 조사한 항목만 기록한다.

### 사례 A: 학력 코드만 비교하면 놓치는 추가 조건

[서울영커리언스 점프업(미래 청년 일자리 사업)](https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch/ythPlcyDetail/20260722005400213264?isNew=N), 정책번호 `20260722005400213264`.

- 학력 항목에는 제한없음이 표시되지만 추가사항에는 대학생 참여 불가가 적혀 있다.
- 신청기간은 2026-05-04~2026-05-31, 사업 운영 기간은 2026-07-01~2026-12-31로 다르다.
- 결론: 학력 코드의 제한없음만으로 신청 가능을 확정하지 않는다. 사업 종료일로 마감 알림을 만들지 않는다.

### 사례 B: 전국 분류와 개인 신청 가능 여부는 다름

[2026 서울 동아리ON(대학생 동아리 지원)](https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch/ythPlcyDetail/20260410005400212663?isNew=N), 정책번호 `20260410005400212663`.

- 전국으로 표시되고 거주지역에 여러 지역이 포함되어 있다.
- 실제 지원 대상은 서울 소재 대학 소속 동아리이며, 신청절차에 재학생 10명 이상 등의 조건이 있다.
- 결론: 거주지역만 맞는 개인에게 신청 가능이라고 표시하지 않는다. 동아리 등 신청 주체와 서술형 요건을 확인할 수 없으면 추가 확인 필요로 남긴다. 이를 이유로 MVP에 단체 프로필 기능을 추가하지 않는다.

## 7. 서울 수집과 자동 판정의 범위

### 서울 후보를 빠뜨리지 않는 수집

- `zipCd=11000` 한 번으로 서울 자치구·전국 공통 정책이 모두 내려온다고 가정하지 않는다.
- 유효 키를 확보하면 지역 필터 없는 목록과 서울·자치구 필터 결과를 정책번호로 비교한다. 비교는 같은 시점의 작은 표본부터 시작하며 일치한 몇 건만으로 전체 누락이 없다고 선언하지 않는다.
- 전체 수집이 호출 한도와 예산 안에서 가능하면, 지역을 확정하지 못한 항목까지 받아 내부에서 서울 후보를 가르는 방법을 우선 검토한다. 한도 확인 전 전체 수집을 실행하지 않는다.
- 전국 전용 코드, 지역 코드의 계층 확장, 목록의 기본 정렬·페이징 보장은 아직 미확인이다. 빈 지역 코드를 전국으로 만들거나 제목에 서울이 없다는 이유로 제거하지 않는다.

### 자동 판정 후보

| 조건 | 자동 비교를 허용할 전제 | 전제가 없을 때 |
|---|---|---|
| 지역 | 실제 코드 의미·복수 값·거주 기준과 본문 예외가 확인됨 | 추가 확인 필요 |
| 취업·학력 | 입력 상태와 정책 코드의 의미가 같고 서술형 제한까지 처리됨 | 추가 확인 필요 |
| 연령 | 나이 정의, 기준일, 범위 경계, 예외가 확인됨 | 추가 확인 필요 |
| 소득 | 개인/가구·연도·단위·상하한 의미와 필요한 사용자 값이 확인됨 | 추가 확인 필요 |
| 신청 주체·중복수혜·특화 조건 | 개인 입력만으로 확인 가능한 명시적 조건이며 근거가 있음 | 추가 확인 필요 |

이 표는 자동화 가능 비율 측정 결과가 아니다. 현재 공개 사례 2건으로 전체 정책의 비율을 계산하지 않는다. 규칙으로 확정할 수 없는 조건을 AI 신뢰도 점수로 대체하지 않는다.

## 8. 유효 인증키 확보 후 필요한 최소 확인

응답 확보에는 [개발용 점검 명령](../development/ontong-api-probe.md)을 사용할 수 있다. 키 노출 없이 단건 응답을 로컬에 보관하는 도구이며, 도구 테스트 통과는 아래 실제 계약 확인을 대신하지 않는다.

1. 지역 필터 없이 작은 목록을 조회하여 성공 본문의 객체 구조·목록 경로·페이지 정보·실제 값 타입을 기록한다.
2. 같은 정책번호의 목록·상세를 비교한다. 명세와 다른 필드명, 생략된 조건, 널·빈 문자열·복수 코드·날짜 형식을 확인한다.
3. 서울시, 한 자치구, 전국 공통, 상시 또는 기간 미확인 사례를 확보한다. 해당 유형을 찾지 못하면 샘플 미확보로 남긴다.
4. 공개 사례 A·B와 API의 정책 내용을 비교하여 정규화·미확인 판정용 자료를 만든다. 가짜 성공 응답을 실제 API 자료로 저장하지 않는다.
5. 호출 한도·최대 페이지 크기·수정 및 삭제 의미를 공식 답변 또는 승인 화면에서 확인한다. 서비스에 부하를 주는 방식으로 한도를 실험하지 않는다.

인증키를 제외한 요청 조건, 확인 시각, HTTP 상태, Content-Type, 필요한 원시 정책 필드만 증거로 남긴다. 오류 본문은 HTML일 수도 있으므로 로그에 그대로 넣지 않는다. 성공 계약을 확인하기 전에는 운영 수집기·확정 DTO·Flyway DDL을 만들지 않는다.
