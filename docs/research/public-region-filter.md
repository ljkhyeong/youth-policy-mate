# 공개 목록 지역 필터 조사

2026-10-05 조사. 구현하지 않았다. [PRD 3.2](../PRD/0001_product-baseline/spec.md#32-최소-화면-범위)의 "검색어와 지역 등 명확한 정책 조건으로 탐색"과 AC-01의 지역 기준을 공개 목록에 적용할 수 있는지 확인했다. 원천 필드 계약은 [온통청년 API 조사](ontong-api-contract.md)를 따른다.

## 결론: 조건부 가능

- 정책의 `zipCd`(저장 시 `content.regionCodes`)는 5자리 법정 시군구 코드 목록이다. 로컬 40건 모두 값이 있고 원본과 저장값이 같다. "선택한 자치구의 코드가 공고 지역에 포함된 정책"을 거르는 **검색 보조 필터**는 지금 데이터로 정확히 만들 수 있다.
- 코드는 거주 자격이 아니라 **공고 지역**이다. 본문이 코드보다 좁거나(소속·참여 지자체 한정) 넓은(서울 소재 대학·직장 포함) 사례가 있다. 자격 판정이나 `ResidenceCondition` 생성에는 쓰지 않는다. [거주 조건](../development/residence-condition.md)의 "빈 코드·전국 분류를 전국 허용으로 바꾸지 않는다"는 원칙도 유지한다.
- 현재 수집은 `zipCd=11000`(서울) 요청 결과라 40건 모두 서울 코드를 포함한다. 자치구를 골라도 빠지는 정책은 1~3건뿐이라, 지금은 효용이 작고 **전체 수집 이후에 쓸모가 커진다**.

## 데이터 관찰

로컬 DB 40건과 `.local/ontong-api` 캡처·테스트 캡처를 읽기 전용으로 확인했다.

| 코드 유형 | 건수 | 기관 | 본문과의 관계 |
|---|---|---|---|
| 전국(254·256개) | 31 | 중앙부처 29, 광역 2 | 대부분 본문에 지역 제한 없음. 일부는 본문이 더 좁음(해당 지자체 거주, 특정 대학 소속, 다른 광역 외 거주) |
| 서울 23개 + 다른 지역 | 1 | 농식품부 | 미추진 지자체(강서·송파 등)가 코드에서 빠져 본문과 일치. 코드가 실제 제한을 반영한 사례 |
| 서울 25개만 | 6 | 서울시 | 본문이 협약대학 재학생(서울 밖 대학 포함)이나 서울 소재 대학·직장까지 넓히는 사례 있음 |
| 자치구 1개 | 2 | 자치구 | 신청 자격에 거주 제한 문구가 없음. 필터가 다른 구 거주자를 잘못 뺄 수 있음 |

- 저장값에 `11000`이나 빈 목록은 없다. `11`로 시작하는 코드는 아래 25개뿐이다.
- 전국 코드 집합은 고정돼 있지 않다(254개와 256개가 공존하고, 행정구역 개편 코드가 섞여 있음). "전국"을 고정 코드 집합과 비교해 판정하지 않는다.
- 서울 자치구 코드(법정동코드 앞 5자리): 11110 종로, 11140 중구, 11170 용산, 11200 성동, 11215 광진, 11230 동대문, 11260 중랑, 11290 성북, 11305 강북, 11320 도봉, 11350 노원, 11380 은평, 11410 서대문, 11440 마포, 11470 양천, 11500 강서, 11530 구로, 11545 금천, 11560 영등포, 11590 동작, 11620 관악, 11650 서초, 11680 강남, 11710 송파, 11740 강동. 집합은 캡처의 전국 코드와 일치함을 확인했다. 이름 대응은 5개(강남·은평·중랑·강서·송파)만 저장소 자료로 교차 확인했고 나머지는 외부 코드표 기준이다.
- 코드와 자치구 이름의 매핑은 저장소에 없다. `SeoulDistrict`와 조건 화면의 자치구 목록은 이름만 가진다. 공개 화면에는 코드를 표시하지 않지만 공개 상세 API의 `content.regionCodes`에는 원시 코드가 있다.

## 제안 설계

- **API**: `GET /api/v1/policies?district=GANGNAM`. 값은 `SeoulDistrict` 이름이고, 잘못된 값은 `category`처럼 400 `INVALID_SEARCH`다. 기존 검색어·분야·접수 상태·질문 필터와 AND로 묶는다.
- **매핑**: `policy/catalog`에 원천 코드 매핑을 따로 둔다. 자격 판정의 `SeoulDistrict`는 원천 코드와 분리된 상태를 유지하고, 코드표 출처와 확인일을 기록한다.
- **포함 규칙**:
  1. 선택한 구의 코드가 있으면 포함한다(전국 코드·서울 25개·해당 구 포함 정책).
  2. 코드가 비었거나 `11000`이 있으면 지역 미확인으로 보고 포함한다(현재 0건).
  3. 서울 코드는 있는데 선택한 구가 없으면 제외한다(다른 구 전용, 일부 구 미추진).
  4. 서울 코드가 하나도 없으면 제외한다(전체 수집 후 생김).
- **SQL**: `content->'regionCodes' @> jsonb_build_array(:code)`처럼 `@>`를 쓴다(JDBC 자리표시자와 충돌하는 `?` 연산자는 쓰지 않는다). 전체 수집 후에는 GIN `jsonb_path_ops` 인덱스를 검토한다. 분야별 수와 내 조건 결과에는 적용하지 않는다(조건 결과는 비교할 수 없는 조건을 제외하지 않는다는 PRD 기준).
- **화면**: 목록 검색 폼의 접수 상태 옆에 "지역" 선택(전체 + 25개 구). 페이지 이동·필터 초기화·결과 제목·빈 상태에 반영한다. 저장한 거주 자치구를 주소에 자동으로 넣지 않는다(개인 조건이 주소창·로그에 남음).
- **문구**: 도움말 "선택한 자치구가 공고 지역에 포함된 정책을 보여줘요. 신청 자격은 공고에서 확인해주세요." 빈 상태 "선택한 지역이 포함된 정책이 없어요." "거주자 대상"·"신청 가능"·코드 설명은 쓰지 않는다.

## 남은 위험과 필요한 실제 데이터

| 위험 | 확인 방법 |
|---|---|
| 자치구 하나만 코딩된 정책이 다른 구 거주자에게서 빠짐 | `zipCd=11000` 전체 페이지(당시 totCount 481)의 서울 코드 1~24개 분포를 세고, 자치구 전용 10~20건의 원문에서 거주 제한 여부 확인 |
| 원천 자치구 필터의 의미 미확인 | `zipCd=11380` 결과 수와 위 전체 목록 중 11380 포함 건수 비교 |
| 전국 코드인데 본문이 지역을 한정 | 보조 문구로 완화하고 정책별 보정 대상으로 관리 |
| 서울 코드가 없는 정책의 범위 | 지역 필터 없는 목록(당시 totCount 2747)의 수집 범위를 호출 한도 확인 후 결정 |

조사에서는 외부 API 호출·수집 명령을 실행하지 않았다. 로컬 DB는 조사용으로 시작해 읽기 전용으로 조회한 뒤 종료했고 볼륨은 유지했다.
