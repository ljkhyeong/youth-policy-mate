# API 계약 변경

계약의 관리 기준은 서버 컨트롤러·DTO다. 생성 방식은 [ADR-0002](../../docs/ADR/0002_서버_DTO_기반_API_계약_생성.md)를 따른다.

## 계약 기준

- 공개·회원·관리자 API의 접근 권한을 구분한다. 이름 있는 DTO와 중복되지 않는 안정적인 `operationId`를 사용한다.
- 필드명·형식·enum·페이지 구조 변경이 기존 호출에 미치는 영향을 확인한다. 필수·누락·null의 의미를 실제 JSON과 명세에 일치시킨다.
- 생성 타입이 틀리면 서버 스키마를 고친다. OpenAPI·생성 TypeScript는 직접 수정하지 않으며, 웹에 같은 DTO를 별도로 만들지 않는다. 입력 폼·표시 모델은 구분한다.
- 자격 상태와 모집 상태, 미확인 사유와 원문 근거·정책 개정을 보존한다. 소셜 프로필을 본인 인증 완료로 표현하지 않는다.
- 날짜는 `date`, 정확한 시각은 `date-time`으로 구분한다. 필요한 원래 시간대를 보존하고 상시·미확인 기간에 임의의 시각을 넣지 않는다.
- 오류 상태 코드와 메시지를 맞추고 입력한 개인정보·DB 오류·비밀값을 응답에 노출하지 않는다.

## 변경·검증 순서

1. 서버 계약과 영향을 받는 호출 코드를 수정한다. 형식·null·오류가 바뀌면 대표 응답을 계약 테스트로 확인한다.
2. 저장소 루트에서 `npm run generate:api`로 OpenAPI와 TypeScript를 재생성한다. 공개 계약 생성에는 PostgreSQL 테스트용 Docker가 필요하다.
3. 생성 결과를 확인하고 `npm run check:api-types`와 `npm run check:web`으로 소비 코드까지 점검한다. 변경한 동작의 테스트·빌드는 필요한 범위로 실행한다.
