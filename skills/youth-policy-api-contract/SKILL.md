# 청년정책메이트 API 계약

대상 저장소는 `/Users/lim/devProject/personal/youth-policy-mate`다. 문서 경로는 저장소 루트 기준이다.

## 시작

- `AGENTS.md`, `HANDOFF.md`, `docs/PRD/0001_product-baseline/spec.md`와 관련 ADR을 읽는다.
- 컨트롤러·DTO와 실제 OpenAPI·클라이언트 생성 설정을 찾는다. 생성기가 아직 없으면 최초 구현에서 관리 주체와 재생성 명령을 정하고 기록한다.
- 공개 목록·상세, 개인 조건·저장·일정, 관리자 보정의 인증·소유권 경계를 구분한다.

## 계약 원칙

- 이름 있는 DTO를 사용한다. raw Map이나 컨트롤러 내부 임시 타입으로 공개 계약을 숨기지 않는다.
- 업무 정책은 PRD, 실제 요청·응답은 서버 계약을 기준으로 한다. OpenAPI와 생성 클라이언트를 손으로 고치지 않는다.
- `operationId`는 유일하고 안정적으로 유지한다. 필드 제거·이름 변경·형식·널 허용·enum·페이지 의미 변경을 호환성 변경으로 다룬다.
- 항상 제공하는 응답 필드와 누락 가능한 필드, 값이 null일 수 있는 필드를 구분한다. 생성 타입이 잘못되면 서버 스키마를 수정한다.
- 서버 DTO를 프론트엔드에 손으로 복제하지 않는다. 폼 상태와 표시 모델은 서버 DTO와 별도로 둘 수 있다.
- 자격 판정 상태와 모집 상태를 분리하고, 추가 확인 필요의 사유·근거·적용 정책 버전이 전송 중 사라지지 않게 한다.
- 날짜만 있는 값, 시간대가 있는 시각, 상시·미확인 마감의 의미를 명시한다. 프론트엔드 편의를 위해 가짜 시각을 넣지 않는다.
- 일반 소셜 정보와 본인확인 결과를 같은 인증 완료 필드로 표현하지 않는다.
- 오류 응답은 형식·상태 코드·사용자 안내를 일관되게 정의하고 비밀 값이나 DB 내부 오류를 포함하지 않는다.

## 변경과 검증

1. 영향을 받는 요청·응답과 사용처를 검색한다.
2. DTO·동작·관련 제품 기준을 함께 수정한다.
3. 실제 저장소의 생성 명령으로 OpenAPI와 TypeScript 계약을 갱신한다.
4. 실제 응답의 대표 직렬화와 생성 타입의 소비 코드를 확인한다. 예시 JSON만 맞는 것으로 완료하지 않는다.
5. 변경한 인증·소유권·날짜·널 의미 중 위험한 경계만 검증하고 프론트엔드 타입 검사·빌드를 확인한다.

happyGallery의 경로, 오류 enum, 관리자 API 키 방식과 생성 명령은 이 프로젝트 계약으로 복사하지 않는다.
