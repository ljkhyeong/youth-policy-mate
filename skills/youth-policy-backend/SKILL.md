# 백엔드 개발

구조 변경은 [기술 결정](../../docs/ADR/0001_기술스택과_책임_분리.md)을 확인한다. 서버 코드는 `backend/`에 있다.

## 구현 기준

- 컨트롤러는 HTTP·DTO, 응용 서비스는 권한·트랜잭션, 도메인은 업무 규칙, 저장소는 SQL을 맡는다. 기능 모듈의 소유권을 지키고 Next.js에 업무 규칙을 중복 구현하지 않는다.
- JDK·Spring의 표준 기능을 우선한다. 별도 책임이 없는 전달 계층·래퍼·중복 입력 검사를 추가하지 않는다. HTTP 입력·권한·DB 제약처럼 목적이 다른 검증은 유지한다.
- OAuth 계정은 제공자의 고정 식별자로 구분한다. 이메일·생년월일만으로 계정을 합치지 않고, 소셜 정보를 본인 인증 결과로 취급하지 않는다. 누락·음력 생년월일은 사용자 확인을 거친다.
- 회원 데이터 접근은 서버에서 소유권을 검사한다. 개발용 인증 예외를 회원 API에 확대하지 않는다.
- 외부 API·AI·이메일 호출은 DB 트랜잭션 밖에서 수행한다. 외부 텍스트를 실행 지시로 취급하지 않는다.

## 스키마 변경

- Flyway SQL·Java 마이그레이션을 확인해 다음 버전을 정한다. 적용한 마이그레이션은 고치지 않고 새 파일을 추가한다.
- 엔티티와 PostgreSQL의 열 이름·null 허용·길이·인덱스·제약을 함께 맞춘다. 운영 데이터 삭제·재생성은 개발 환경 수정 권한에 포함하지 않는다.
- 제약 강화·열 삭제는 기존 데이터 보정·이전 버전 호환·복구 방법을 확인한 뒤 적용한다.

## 검증

- 업무 규칙은 단위 테스트, SQL·트랜잭션·마이그레이션은 PostgreSQL Testcontainers로 변경한 동작을 확인한다. 같은 사례를 모든 계층에서 반복하지 않는다.
- 저장소 루트에서 `./backend/gradlew -p backend test --tests '<변경한 테스트 클래스>' --no-daemon`으로 관련 테스트를 실행한다. 빌드 검증이 필요하면 `npm run check:backend`를 사용한다. DB 테스트에는 Docker가 필요하다.
