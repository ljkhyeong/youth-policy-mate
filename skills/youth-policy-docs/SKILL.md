# 청년정책메이트 문서 작업

대상 저장소는 `/Users/lim/devProject/personal/youth-policy-mate`다. 아래 경로는 모두 저장소 루트 기준이다.

## 읽을 문서

- `AGENTS.md`, `HANDOFF.md`, `README.md`를 읽어 현재 작업과 문서 위치를 확인한다.
- 제품 동작은 `docs/PRD/0001_product-baseline/spec.md`, 기술 결정은 관련 `docs/ADR/` 문서에서 확인한다.
- 스킬을 변경하면 `docs/development/skill-reuse.md`에서 출처와 의도적으로 제외한 규칙을 확인한다.

## 문서의 역할

- PRD: 승인한 사용자 동작, 범위, 예외 처리와 완료 기준.
- ADR: 장기간 유지할 구조·소유권·실패 경계·기술 선택과 그 이유.
- README: 프로젝트 현재 상태와 문서 진입점. 정책 전문을 복사하지 않는다.
- HANDOFF: 진행 중인 일, 다음 진입점, 실제 확인한 제약. 장기 정책의 기준으로 쓰지 않는다.
- 최초 합의 HTML: 그 시점의 승인 기록이다. 구현 완료에 맞춰 다시 쓰거나 직접 편집하지 않는다.
- OpenAPI와 서버 DTO 기반 클라이언트: 생성 파이프라인을 만든 뒤에는 기계 생성 계약으로 관리한다.

## 변경 절차

1. 요청이 제품 변경인지, 기술 결정인지, 현재 상태 기록인지 구분한다.
2. 해당 기준 문서를 먼저 수정하고 영향받은 요약·링크만 갱신한다.
3. 기존 합의와 다른 제품 동작은 제안으로 표시하고 승인 없이 확정하지 않는다.
4. 실제 코드·빌드 파일에 없는 경로와 실행 명령을 현재 기능처럼 적지 않는다.
5. 도입 예정·조사 중·채택·구현 완료를 구분한다. 특히 배포 환경과 운영 공급자를 미리 확정하지 않는다.

## 검증

- 문서만 바뀌면 내부 링크, 존재하는 경로, 요구사항 간 모순과 오래된 표현을 확인한다.
- 코드 동작을 설명한 부분은 실제 구현과 비교한다. 문서만 수정해 구현 불일치를 덮지 않는다.
- 문서 작업 때문에 앱 테스트나 별도 검증 프레임워크를 만들지 않는다.
- 한글 문서는 사용자 행동·실패 결과를 알 수 있는 표현으로 작성한다.
