# 청년정책메이트 자격 판정

대상 저장소는 `/Users/lim/devProject/personal/youth-policy-mate`다. 문서 경로는 저장소 루트 기준이다.

## 시작

- `AGENTS.md`, `HANDOFF.md`, `docs/PRD/0001_product-baseline/spec.md`의 조건 입력·자격 안내를 읽는다.
- 변경할 정책의 원문·예외·적용 개정·사용자 입력 의미와 현재 규칙을 먼저 확인한다.
- 기존에 없는 기준일·소득 단위·지역 예외를 임의로 정하지 않는다. 원문으로 확정할 수 없으면 추가 확인 필요를 유지한다.

## 판정 불변식

- 신청 가능은 입력 조건 기준의 안내이며 공식 자격 인증이나 선정 보장이 아니다.
- 명확하게 적용할 수 있는 모든 필수 조건과 예외가 처리되어야 신청 가능으로 표시한다.
- 누락된 사용자 값, 알 수 없는 코드, AI 추출 실패, 해석할 수 없는 조건을 제한 없음·참·거짓으로 대체하지 않는다.
- 불충족은 명확히 적용되는 조건에만 사용한다. 미해석 예외가 해당 불충족을 뒤집을 수 있으면 추가 확인 필요다.
- 정책의 연령 기준일과 나이 정의를 보존한다. 서비스 대상 19~34세를 모든 정책의 연령 규칙으로 쓰지 않는다.
- 서울 거주자가 신청할 수 있는 전국 공통 정책을 포함하고, 자치구 조건을 서울 전체 조건으로 넓히지 않는다.
- 개인/가구 소득, 월/연 단위, 적용 연도, 가구원 수와 기준을 맞출 수 없는 소득 비교는 보류한다.
- 모집 상태와 개인 자격을 분리한다. 마감 상태를 자격 불충족으로 바꾸거나 자격 충족을 현재 접수 가능으로 바꾸지 않는다.

## 구현과 근거

- 같은 입력·정책 개정·규칙·기준 시점은 같은 결과와 근거를 만들게 한다.
- 판정 결과에는 적용 조건, 비교한 값, 근거와 미확인 이유를 담고 API/UI에서도 의미를 보존한다.
- AI는 설명과 후보 추출에만 사용한다. 모델의 신뢰도 점수를 규칙 검증이나 원문 근거 대신 사용하지 않는다.
- 사용자 조건 또는 정책이 바뀌면 재판정하되, 과거 판정과 최신 판정을 구분할 수 있게 한다.
- 시간 의존 규칙에는 Clock을 주입하고 현재 시각이나 기기 시간대에 숨은 의존을 만들지 않는다.
- 실제 정책 하나의 규칙을 표현하는 데 범용 규칙 엔진·동적 코드 실행·사용하지 않는 조건 타입을 먼저 만들지 않는다.

## 검증

- 변경한 규칙의 충족·불충족·미확인과 필요한 예외를 대표 원문 사례로 검증한다.
- 연령·기간 규칙은 기준일 경계와 윤일 등 실제 적용에 영향을 주는 사례만 고정 시계로 확인한다.
- 순위 변경은 자격 상태와 근거를 바꾸지 않는지 확인한다.
- 동일 입력 행렬을 여러 계층에 복사하지 않는다. 규칙은 단위 테스트, 직렬화 의미는 대표 API 테스트로 나눈다.
