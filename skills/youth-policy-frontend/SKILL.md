# 청년정책메이트 프론트엔드 작업

대상 저장소는 `/Users/lim/devProject/personal/youth-policy-mate`다. 문서 경로는 저장소 루트 기준이다.

## 시작

- `AGENTS.md`, `HANDOFF.md`, `docs/PRD/0001_product-baseline/spec.md`와 `docs/ADR/0001_기술스택과_책임_분리.md`를 읽는다.
- 실제 Next.js 구조·패키지 설정·공통 API 경계를 확인한다. Vite 라우터나 happyGallery의 Bootstrap·관리자 토큰 저장 방식을 옮기지 않는다.

## 렌더링과 데이터 경계

- 공개 정책 페이지는 검색 가능한 본문·출처·메타데이터를 제공한다. 회원 조건과 결과를 공용 캐시·사이트맵·공유 미리보기에 넣지 않는다.
- Next.js Server Component·Server Action·Route Handler는 화면과 필요한 중계를 담당한다. 자격·수집·알림 업무 규칙은 Spring API의 결과를 사용한다.
- 클라이언트 상호작용이 필요한 곳에만 클라이언트 컴포넌트를 둔다. 모든 서버 데이터를 별도 전역 상태에 복사하지 않는다.
- 생성된 서버 타입을 사용하고, 사용자 입력 폼 상태와 표시용 모델만 별도로 작성한다.
- 로그인·로그아웃·계정 변경 시 회원별 캐시와 로컬 상태를 비우고 이전 계정의 늦은 응답이 새 화면을 갱신하지 못하게 한다.

## 사용자에게 보일 의미

- 입력 조건 기준 신청 가능, 추가 확인 필요, 조건 불충족을 구분한다. 로딩·오류·AI 실패를 판정 결과로 바꾸지 않는다.
- 자격과 모집 상태를 각각 보여주고 원문 근거·수집 시각·공식 신청 링크를 확인할 수 있게 한다.
- 정보 미제공이나 동의 거부에도 생년월일 직접 입력 경로를 제공한다. 음력 생일을 그대로 만 나이 계산에 쓰지 않는다.
- 비회원의 검색·조건 입력과 회원의 조건·정책 저장을 구분한다.
- 정책 저장과 이메일 수신 동의를 합치지 않는다. 저장 해제·마감일 변경이 일정과 예약 알림에 반영된 서버 결과를 보여준다.
- 날짜형 마감을 브라우저 로컬 시간대로 바꾸거나 임의의 자정 시각으로 표시하지 않는다.
- 로딩·빈 결과·추가 정보 필요·외부 오류를 다른 상태로 안내하고 공통 UI를 재사용한다.

## 검증

- 실제 패키지 스크립트에서 타입 검사·빌드·해당 테스트를 선택한다.
- 로그인 전환, 저장과 취소, 이메일 동의 변경은 대표 브라우저 흐름을 검증한다.
- 화면을 바꾸면 모바일·데스크톱에서 근거와 상태가 읽히는지, 키보드로 주요 동작을 할 수 있는지 확인한다.
- 서버 동작이나 API 계약도 바뀌면 해당 소유 스킬을 읽고 양쪽 계약을 함께 확인한다.
