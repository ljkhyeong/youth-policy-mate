# 프런트엔드 개발

화면 코드는 `frontend/`에 있다. 화면 구조를 바꿀 때 [웹앱 기준](../../docs/design/webapp-interface.md)을 확인한다.

## 구현 기준

- Next.js는 화면·메타데이터·API 중계를 맡고 업무 판단은 Spring에 둔다. 서버 응답은 생성 타입을 사용하고 입력 폼·표시 모델만 별도로 둔다.
- 공개 페이지의 공용 캐시·메타데이터·사이트맵·공유 미리보기에 회원 정보를 섞지 않는다. 계정 전환·로그아웃 때 개인 상태를 지우고 이전 계정의 늦은 응답을 무시한다.
- 자격과 모집 상태를 각각 표시하고 정책 원문 링크·수집 시각·추가 확인 사유를 제공한다. 로딩·조회 실패를 불충족이나 결과 없음으로 바꾸지 않는다.
- 소셜 정보의 누락·음력 생년월일은 직접 확인하게 한다. 비회원의 탐색·조건 입력과 로그인 후 저장을 구분한다.
- 관심 정책 저장과 이메일 수신 동의를 구분한다. 저장 취소·마감 변경·발송 상태는 서버 결과를 표시한다.
- 날짜만 있는 마감을 브라우저 시간대로 옮기거나 자정으로 바꾸지 않는다. 상시·미확인 사유를 그대로 표시한다.
- 입력·로딩·빈 결과·오류 화면은 기존 공통 컴포넌트를 사용하고, 사용자가 취할 다음 행동을 짧게 안내한다.

## 검증

- 동작·타입 변경은 저장소 루트의 `npm run check:web`과 관련 테스트로 확인한다. 렌더링·라우팅·서버/클라이언트 경계가 바뀌면 `npm run build:web`도 실행한다.
- 상호작용 변경은 해당 대표 흐름을 브라우저로 확인한다. 배치·입력 컨트롤이 바뀌면 모바일·데스크톱과 키보드 접근도 확인한다. 단순 문구 변경은 표시 확인으로 범위를 제한한다.
