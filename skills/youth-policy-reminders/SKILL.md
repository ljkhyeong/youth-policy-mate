# 일정과 알림

제품 기준은 [PRD의 관심 정책·일정·알림](../../docs/PRD/0001_product-baseline/spec.md#7-관심-정책일정알림)이다. 이메일의 현재 구현·설정은 [개발 문서](../../docs/development/member-email-reminders.md)를 확인한다.

## 예약과 취소

- 관심 정책 저장은 서비스 내 D-7·D-3·D-1 알림을 설정한다. 이메일은 별도 수신 동의를 확인한다. 저장 해제는 해당 정책의 모든 미발송 알림을, 이메일 동의 철회는 미발송 이메일만 취소한다.
- 마감은 정책의 날짜·시각 정보를 사용하며 발송 코드에서 원문을 다시 해석하지 않는다. 서울 달력 날짜로 계산하며 날짜만 있는 마감에 자정·23:59를 붙이지 않는다.
- 상시·예산 소진·미확인 기간에 마감일을 만들지 않고, 날짜 충돌은 알림 보류로 처리한다. 새로 저장할 때 이미 지난 알림을 몰아서 발송하지 않는다.
- 정책 개정과 마감 변경에 맞춰 미발송 일정을 다시 계산한다. 발송 시간·재시도 횟수·TTL은 현재 설정을 확인하고 임의로 정하지 않는다.

## 발송과 복구

- 업무 변경과 Outbox 요청을 같은 트랜잭션에 저장한다. 발송 배정·결과 저장은 짧게 처리하고 외부 호출은 커밋 후 실행한다. 대기 중인 여러 요청의 잠금을 잡아두지 않는다.
- 배정과 발송 직전에 회원 소유권·저장 상태와 변경 이력·정책 개정·수신 동의를 재확인한다.
- 발송 전 실패와 전달 결과 미확인을 구분한다. 결과 미확인은 공급자 조회나 멱등 기능으로 확인하며, 확인 수단이 없으면 재발송을 보류한다.
- 수신 거부·잘못된 주소에 계속 재시도하거나 다른 채널로 임의 전환하지 않는다. 성공·실패·미확인·취소를 구분해 기록하고 정확히 한 번 전달을 보장한다고 표시하지 않는다.
- 예약에는 회원 식별자 등 필요한 정보만 두고 연락처 복제를 줄인다.

## 검증

- 변경한 동작에 해당하는 서울 날짜 경계·저장 해제·마감 변경·동의 철회·중복 발송·결과 미확인을 확인한다.
- 트랜잭션·재시도 변경은 롤백 시 Outbox 생성 취소와 재시작 후 복구를 DB 테스트로 확인한다. 공급자 호출·동시성 테스트는 변경한 부분에만 둔다.
