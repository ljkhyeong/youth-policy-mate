# 청년정책메이트 일정과 알림

대상 저장소는 `/Users/lim/devProject/personal/youth-policy-mate`다. 문서 경로는 저장소 루트 기준이다.

## 시작

- `AGENTS.md`, `HANDOFF.md`, `docs/PRD/0001_product-baseline/spec.md`의 일정·알림 및 자동화 실패 기준을 읽는다.
- 원문 마감의 날짜/시각/상시/미확인 의미와 실제 예약·발송 설정을 확인한다.
- 알림톡·SMS·외부 캘린더 구독·BATON 연동을 이번 작업에 자동으로 추가하지 않는다.

## 저장·날짜·변경

- 정책 저장으로 내 일정과 서비스 내 마감 7일·3일·1일 전 알림을 연결한다. 이메일은 별도 활성화가 있어야 한다.
- 일 단위 계산은 Asia/Seoul을 명시한다. 날짜만 있는 마감을 임의의 자정·23:59 시각으로 바꾸지 않는다.
- 상시·예산 소진·미확인 마감에 가짜 날짜를 만들지 않는다. 충돌한 날짜는 해당 마감 알림을 보류한다.
- 이미 지난 알림 시점을 저장 직후 몰아서 보내지 않는다.
- 저장 해제는 미발송 알림을 취소한다. 마감 변경은 최신 개정의 일정과 미발송 알림에 반영한다.
- 정책 원문·마감 계산은 해당 소유자가 제공한 값을 사용하고 알림 발송기가 별도 파싱·계산하지 않는다.
- 구체적인 발송 시각·재시도 만료·변경일 알림 정책은 실제 합의·설정에서 확인한다. 이 스킬에서 임의의 운영 수치를 만들지 않는다.

## 전달 책임

- 업무 변경과 발송 의도는 같은 DB 트랜잭션에 보존하고, 외부 발송은 커밋 후 수행한다.
- 작업 선점·결과 저장은 짧은 트랜잭션으로 처리한다. 외부 전달을 기다리는 동안 여러 행을 선점한 채 유지하지 않는다.
- 회원, 저장 상태, 정책·예약 개정과 채널 수신 동의를 발송 직전에 다시 확인한다. 취소된 예약이나 이전 개정의 작업이 뒤늦게 발송되지 않게 한다.
- 예약 중복 방지와 외부 발송 결과의 불확실성을 구분한다. 재시도마다 새 전달 건을 만드는 방식으로 중복을 숨기지 않는다.
- 전송 전 실패와 응답 대기 시간 초과처럼 전달 여부를 알 수 없는 실패를 구분한다. 결과 미확인 시 공급자 조회나 멱등 기능 없이 곧바로 재발송하지 않는다.
- 수신자 없음·동의 해제·유효하지 않은 주소를 무한 재시도하거나 다른 채널로 임의 전환하지 않는다.
- 성공·실패·결과 미확인·취소를 구분해 운영자가 확인하게 한다. 외부 이메일의 정확히 한 번 전달을 보장한다고 주장하지 않는다.
- 예약에는 필요한 회원 식별자만 두고 연락처 복제를 줄인다. 로그·메트릭에 이메일·토큰을 넣지 않는다.

## 검증

- Clock을 고정해 달력 날짜 경계를 확인하고 저장 해제·마감 변경·수신 해제 후 미발송 취소를 검증한다.
- 정책 저장 트랜잭션 실패 시 발송 의도가 남지 않고, 커밋 뒤 프로세스 재시작에도 미처리 작업을 회수할 수 있는지 확인한다.
- 실제 변경한 동시성·재시도·공급자 결과 미확인 경계만 통합 검증한다. 모든 규칙을 모든 계층에서 반복하지 않는다.
